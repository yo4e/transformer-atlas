# カリキュラム検証メモ

設計書の順序は、`入力の表現 → 位置間の情報混合 → ブロック → 自己回帰生成 → 学習 → 近年の運用 → 実装` という依存関係になっている。原著の構成をそのまま解説順にせず、読者が先に「何が流れているか」を見てから必要な数式に戻るようにした。

| 判断 | 根拠 | 反映 |
| --- | --- | --- |
| Q/K/V の前に attention の問題を置く | 記号を先に導入すると、学習済み線形射影の目的が見えにくい | 第5章を独立させ、第6章で式へ進む |
| original の位置符号化と RoPE を分ける | sinusoidal encoding は原著の設計であり、RoPE は後年の異なる仕組み | 第10章で歴史と機構を分離する |
| GPT-style decoder-only を original encoder–decoder の後に置く | 「Transformer=decoder-only」という誤解を避ける | 第14–15章で対比する |
| sampling を logits の直後に置く | temperature、top-k、top-p は出力分布への操作であり、モデル内部の性格付けではない | 第16–17章で操作対象を可視化する |
| tiny model は実装後でなく概念完了後に置く | コードの1行を、すでに学んだ概念へ戻れるようにする | 第26–27章に cross-link を置く |

現行の第一版では、FlashAttention・分散学習・長文最適化の詳細な比較は、核心の理解に必要な最小範囲を超えるため扱わない。
