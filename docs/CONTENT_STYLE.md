# コンテンツと用語の規約

本文の基本単位は一章一ファイルである。各章は `title`、`part`、`order`、`summary`、`concepts`、`references`、`status` を必須にし、概念がどこで導入されたかを索引と関連付ける。

説明は、**問題 → 直感 → 実際の機構 → 最小の数式 → 小さな例 → コード → 比喩の限界 → 実際の LLM との接続 → 確認問題 → 一文の要約 → 参照** の順を標準とする。すべての章で同じ長さにする必要はないが、新しい数学記号を出すときは普通の言葉と小さな数値例を先に置く。

| 用語 | 採用する表現 | 避ける表現 |
| --- | --- | --- |
| token | tokenizer が文字列から作る ID の単位 | 「token は単語」 |
| embedding | token ID を引く学習済み vector 表 | 「次元ごとに意味ラベルがある」 |
| attention weight | value の混合比を作る中間量 | 「モデルの考えを完全に説明する量」 |
| softmax | score を相対重みに変換する関数 | 「自動的に確信度を返す関数」 |
| logit | softmax 前の未正規化 score | 「すでに確率」 |
| 教材用図 | 小さな計算または明示的な模式図 | 実モデルの内部状態を示すかのような表現 |

原著の事実、近年の一例、実装依存の選択、教材用の簡略化は一文の中で混ぜない。実際のモデル名や採用実態を語る必要がある場合は、一次資料または公式資料を追加する。
