# Dot product: 向きと関連度を比べる

問題提起 — なぜ「二つの同じ長さの数の列を一つのスコアにする仕組み」が必要か

自然言語処理や推薦、検索のような場面を想像してください。ある単語や文（ここでは「問い合わせ」）と、複数の候補（ここでは「文脈の断片」や「他の単語」）の間で「どれが似ているか」「どれを重視すべきか」を決めたいとします。問い合わせと候補は、それぞれ同じサイズの数の列（ベクトル）で表されます。実務上は、問い合わせと各候補を比較して「一つの数」（スコア）を出し、そのスコアをもとにどれを選ぶか、あるいは重みづけして合成する、という操作が頻繁に出てきます。

ここで求められる性質は次のようなものです。
- 各成分が寄与する方法が分かりやすく、合成が線形的であること（成分ごとの掛け算の和で表せると解釈しやすい）。
- ベクトルの向き（成分の符号や配置）が似ていれば高いスコア、反対向きなら低い（負の）スコアを与えられること。
- ベクトルの「長さ」もスコアに影響を与え、長いベクトルは強い確信（あるいは大きな影響）を示すことができる。

こうした要請を満たす、実装が簡潔で計算効率も良い仕組みが古くから使われています。本章ではその計算の仕組みと直感、注意点を具体的な数値例と簡潔なコードで示します（最初の説明では仕組みの固有名詞は出しません）。

直感とその限界（有用なイメージ）

直観的には、二つのベクトルを要素ごとに掛け合わせて合計する操作は次のように理解できます。各次元は「ある特徴の強さ」を表すと考え、二つのベクトルが同じ符号を持つ次元では掛け算の結果が正になり、スコアを押し上げます。逆に符号が反対なら負の寄与をしてスコアを下げます。こうして「全体としての方向の一致度」が数値になります。さらに、どちらかのベクトルが大きな数（長さが大きい）であれば、その次元の寄与が強くなり、スコアの絶対値も大きくなります。

しかし、直感どおりに使うと誤解する点があります。
- 「向きだけを比較している」わけではありません。長さ（ベクトルノルム）もスコアに影響します。向きだけを比較したければ正規化（長さで割る）して角度（コサイン類似度）を使う必要があります。
- スコアが大きくなると、後段で softmax のような非線形変換を使う場合、挙動は極端に変わります（小さな差が大きな確率差になることもある）。
- 成分ごとの寄与は単純に足し合わされますが、上流や下流の処理（線形変換や残差結合、複数ヘッドなど）によって最終的な意味は変わります。

「数値オブジェクト」「学習パラメータ」「活性化」を区別する

実際のニューラルモデルでは次の三つを区別して考えることが重要です。
- 入力や中間の出力としての数値オブジェクト（例: 単語を埋め込みしたベクトルやレイヤーからの出力）。一般に「アクティベーション」と呼びます。
- 学習されるパラメータ（例: 線形変換の重み行列 W_Q, W_K, W_V）。これらは訓練によって値が決まります。
- モデルが計算で得る一時的な量（例: クエリとキーの内積によるスコア、softmax 後の注意重み）。訓練の過程で参照されますが、直接更新されるのはパラメータです。

Query（問い合わせ）と Key（候補）は多くの場合、同じ次元数のアクティベーションであり、しかしそれらを得るための重み W_Q / W_K は学習パラメータであり別物だ、ということを頭に置いてください。

具体例 — 実際に数を計算する

ここで必ず触れる具体例を計算します。三つのベクトルを考えます。
a = [2, −1, 1]
b = [3, 2, −2]
c = [2, −1, 0]

まず a と b の「一つのスコア」を成分ごとの積の和として計算します（これが章の中心になる計算です）。

a · b = (2)*(3) + (−1)*(2) + (1)*(−2)
      = 6 + (−2) + (−2)
      = 2

次に a と c の同じ計算。

a · c = (2)*(2) + (−1)*(−1) + (1)*(0)
      = 4 + 1 + 0
      = 5

差を成分別に見ると分かりやすいです。各成分の a と b, c の積は次のようになります。
- 第1成分: 2*3 = 6 と 2*2 = 4 → c 側は −2 の差
- 第2成分: (−1)*2 = −2 と (−1)*(−1) = +1 → c 側は +3 の差
- 第3成分: 1*(−2) = −2 と 1*0 = 0 → c 側は +2 の差

これらの差を合計すると −2 + 3 + 2 = 3 で、実際 a·c − a·b = 5 − 2 = 3 になります。つまり、a と c のスコアが a と b のスコアより 3 大きい理由は、二つめと三つめの成分における符号の違いとゼロ要素の寄与の合算です。

ここで注意すべき点は、第一成分は b の方が大きい（6 vs 4）ので b に有利な寄与がありますが、それを第二・第三成分の不一致が打ち消して c の方が全体で高得点になっている、ということです。スコアは単純な合算なので「一部が良くても他が悪ければ全体は低くなる」性質を持ちます。

数式での定義と行列視点（普通の言葉で）

1次元の列で表したベクトルを x, y（次元は d）とすると、内積（dot product）は
x · y = Σ_{i=1}^d x_i y_i
と書けます。ここで x_i は x の i 番目の成分を表します。言葉に戻すと「各成分を掛け合わせて全部足す操作」です。

複数の問い合わせベクトル Q（行数 n_q、列数 d）と複数の鍵ベクトル K（行数 n_k、列数 d）を同時に扱うときは、行列積を使って効率的に計算します。Q を n_q×d 行列、K を n_k×d 行列としたとき、Q と K の転置 K^T（d×n_k）を掛けると、結果は n_q×n_k の行列 S（スコア行列）になります。S_{ij} は Q の i 行目と K の j 行目の内積、すなわち「i 番目の問い合わせと j 番目の候補のスコア」です。

言い換えると、
S = Q K^T
という計算は、各問い合わせに対してすべての候補とのスコアを一度に得る方法です。軸の意味を普通の言葉で言えば「Q の各行が問い、K の各行が候補。行列積の出力の行は問い、列は候補で、要素はそれらの内積」です。

現代の Transformer ではこの S を sqrt(d) などで割る「スケーリング」を行う（S ← S / sqrt(d)）ことが提案されており、これは数値が大きくなりすぎて softmax が極端になるのを防ぐためです。続けて softmax を行うと、各問い合わせについて候補群に対する正の重み（和は 1）を得られます。これらの重みを値行列 V に掛け合わせると各問い合わせに対する加重和が得られ、これが attention の出力になります。

短い Python コード（透明で数式と対応）

以下は先ほどの具体例を再現し、さらに a をクエリ、b と c をキーとして softmax 後の注意重みまで示す簡潔なコードです（説明目的の小さな数値であり、実際の大規模モデルの内部状態ではないことに注意してください）。

```python
import math
import numpy as np

a = np.array([2.0, -1.0, 1.0])
b = np.array([3.0, 2.0, -2.0])
c = np.array([2.0, -1.0, 0.0])

# 内積（dot product）
dot_ab = np.dot(a, b)  # 2.0
dot_ac = np.dot(a, c)  # 5.0

# スコア行列（ここでは a を 1x3 の Q、b と c を 2x3 の K と見なす）
Q = a.reshape(1, 3)       # shape (1, 3)
K = np.vstack([b, c])     # shape (2, 3)  (行: b, c)
scores = np.dot(Q, K.T)   # shape (1, 2)  -> [[2.0, 5.0]]

# スケーリング（d = 3）
d = 3.0
scaled = scores / math.sqrt(d)

# softmax（問い合わせごとに）
def softmax(x):
    e = np.exp(x - np.max(x))
    return e / e.sum(axis=-1, keepdims=True)

weights = softmax(scaled)  # shape (1,2)

print("a·b =", dot_ab)
print("a·c =", dot_ac)
print("scores =", scores)
print("scaled =", scaled)
print("softmax weights =", weights)
```

この出力から分かるとおり、(a·b, a·c) = (2, 5) というスコアの差は softmax を通すと重みに変換され、5 の方がより高い重みを受けます。スケーリングはこの重みの分布を柔らかくする役割を果たします。

Transformer 全体での前後の処理と大規模モデルとの接続

実際の Transformer ブロックでの流れを端的に述べると、入力トークン（通常はトークンを表現する埋め込みベクトル）が層ごとに次のように処理されます。

1. 入力埋め込み（および位置情報の付加） → アクティベーション x。
2. 線形変換でクエリ Q = x W_Q、キー K = x W_K、値 V = x W_V を得る。ここで W_Q, W_K, W_V は学習されるパラメータ行列（別物）。
3. Q と K の内積でスコア S = Q K^T を計算し、スケーリングして softmax を取る → attention weights。
4. 重みと V を掛けて加重和を計算 → attention 出力。
5. その後、残差結合、正規化、フィードフォワード層などを通して次の層へ渡す。

注意点:
- Q, K, V は同じ元の x から計算されることが多い（Self-Attention）か、別のソースから来る（Cross-Attention）。Q, K, V を作るための W_* はパラメータで、訓練で更新されます。
- GPT 系のような decoder-only モデルでは「将来のトークンを見ない」ようにマスクをかけ、因果的に情報フローを制限します。オリジナルの "Attention Is All You Need" 論文の構成（encoder-decoder）とは用途や細部が異なります。これらを混同しないでください。
- 実際の大規模モデルでは、上の Q,K,V の次元 d は数百〜数千、ヘッド数も複数（multi-head attention）で並列化されます。内部の値のスケールや分布、正規化の有無は実装によって変わり、訓練データや最適化手法に依存します。示した小さな数値や分布は教材目的の簡易例であり、実モデルの中身そのものではありません。

よくある誤解を訂正する
- 「attention weight が高ければモデルが人間のようにその部分を注視した証拠だ」：attention weight はモデル内部の一つの中間量に過ぎません。出力に至る他の経路（残差接続、次層の重み）や学習の傾向を総合的に考えないと、単純に「ここを見た」と結論づけるのは危険です。
- 「token = 単語」：現実の実装ではトークンはサブワードやバイトペア、文字の断片などを含むため、一般の「単語」と同一視できません。したがって「このトークンに attention が多い = モデルはその単語に注目した」と単純化して語るのは誤解を招きます。
- 「内積は角度だけを測る」：内積は角度の情報（コサイン類似度）と、ベクトルの長さの積の情報を両方含みます。向きだけに着目したければ正規化が必要です（cosine similarity）。
- 「すべての Transformer 実装で同じスケールや正規化が使われる」：論文や実装によって layer normalization の位置や RMSNorm、scaling の方式、位置埋め込みの手法などが異なるため、手元のモデルがどの変種に近いかを確認してください。modern variations を扱うときは採用状況を一般化しないこと。

章のまとめ — 読者が説明できるようになること

この章を学んだあと、あなたは次の事柄を自分の言葉で説明できます。
- 同じ長さの二つの数列を一つのスコアにする計算がどのように成分ごとの積の和として構成されるか。
- 符号（符号一致が正の寄与、逆が負の寄与）と長さ（ノルム）がスコアに与える影響。
- 行列積 Q K^T が複数の問い合わせと複数の候補に対するスコア行列を同時に出す仕組みと軸の意味（行: 問い、列: 候補）。
- Transformer 内でそのスコアがどのように得られ、スケーリング・softmax・V による加重和へつながるか。
- attention weight を文字通りの「人間的注目」として鵜呑みにしてはいけない理由。

確認問題（演習）
1. ベクトル x = [1, 2, −1], y = [0, −1, 3] の内積を計算しなさい。また、x の長さを 2 倍すると内積はどう変わるか説明しなさい。
2. あなたが a = [2, −1, 1] をクエリ、b と c をキーとする状況で softmax を使って重みを求めたとき、もし b のすべての成分を 3 倍したら（b' = 3*b）、a·b' はどうなるか。softmax の出力にどのように影響するか定性的に説明しなさい（スケーリング係数 sqrt(d) を考慮してもよい）。
