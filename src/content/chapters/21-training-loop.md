# Training loop

## 問題提示 — なぜこの反復が必要か（名前を出さずに）

あなたが「文章を生成する方法」をコンピュータに学ばせたいとする。具体的には、ある短い前置（prefix）を与えたときに次に来る適切な要素を出力できるように、内部の数値（重み）を調整したい。これを行うには、次の操作を繰り返す必要がある。

1. 現在の重みで与えられた前置を数値的に処理して、出力候補に対応する一連の数（生のスコア）を作る。
2. その生のスコアを、正解の候補と比較して「どれだけ間違っているか」を測る値にまとめる。
3. 間違いを小さくする方向を決め、その指示に従って重みを少し変更する。

これらを一度で終わらせることはできない。データ全体に対して多数回繰り返すことで、重みはだんだん正しい出力を出すように変化する。ここで重要なのは、出力を作るための「計算の流れ」と、重みを変えるための「学習の流れ」を明確に分けて理解することだ。推論（学習後に新しい前置を評価する）では重みは固定で、単に数を計算するだけでよい。訓練（学習中）はさらに損失を計算し、その損失を基に逆向きに計算して重みを更新する操作が加わる。

以降では、この一連の反復（以下で詳述する）を数式・数値例・短いPythonで具体的に追い、各段階で扱う実際の数値オブジェクト（入力・活性化・パラメータ）を明確に区別する。

注意：この章で使う小さな数値例は教育目的の擬似値であり、実際の大規模モデルで内部に現れる値や大きさとは無関係です。また「token」は必ずしも単語ではなく、分割・符号化された単位であることに注意してください。

## 有用な直感とその限界

直感（良い働き）：
- 前置が与えられると、モデルはそれを数値に変換し（埋め込み）、内部状態を計算して各可能な次のtokenに「どれくらいふさわしいか」を数で表す（これを「ロジット」と呼ぶ）。ロジットが大きいほどその候補がより好ましい。
- 損失は「正解の確率の負の対数」と考えれば分かりやすい。正解の確率が高ければ損失は小さくなる。
- 損失の勾配（どの方向へパラメータを動かせば損失が減るか）は、ロジットや中間活性化を通じて計算できる。勾配に従って重みを少し動かすのが更新ステップ。

直感の限界（注意点）：
- 「確率が高い＝意味的に正しく見える」は必ずしも真ではない。モデルは文法的にもっともらしい選択をするが、それが事実や文脈に合うとは限らない。
- attention weight（注意重み）やロジットの大きさをもって「モデルが人間と同じように注目している」と断定するのは危険。これらは計算上の数量であり、解釈には注意が必要。
- 勾配計算の式（例：softmax とクロスエントロピーの組合せで得られる簡潔な勾配）を導出するには微分の概念があるが、実務上はその結果だけを使えばよい。ここでは、その結果を直感的に説明して使う。

## 数値オブジェクトの区別

この章で登場する主要な数値オブジェクトは次の三つの役割に分けて考える。

- 入力（tokens, token indices）: モデルに与える離散的なラベル。例：前置 [2, 5]。
- 活性化（activations）: 埋め込みや中間層・出力のように、入力とパラメータの組み合わせから計算される一時的な実数配列。例：隠れベクトル h、ロジット logits。
- 学習パラメータ（parameters）: 訓練によって更新される固定配列。例：埋め込み行列 E、出力重み行列 W。

訓練時の流れは「入力 → 活性化（順伝播）→ 損失 → 勾配（逆伝播）→ パラメータ更新」であり、推論時は「入力 → 活性化（順伝播）→ 出力決定（argmax や確率）」のみでパラメータ更新がない点を常に区別する。

## 簡潔なモデルと数式（動機の後に）

ここでは理解しやすさのために非常に簡単化した「埋め込み→平均化→線形出力」のモデルを例にとる。これは Transformer 全体の最終段（語彙への線形写像）で起きている計算に対応するものだが、残りの Transformer ブロックは「入力から最終的な隠れベクトル h を作る処理」と見なせる。

記号と意味（平易な言葉で）：
- V: 語彙（token の種類）数。ここでは簡単のため 12 とする。
- d: 隠れ次元（埋め込みベクトルの長さ）。ここでは 2 とする。
- E ∈ R^{V × d}: 埋め込み行列。行 i が token i の埋め込みベクトル e_i を与える。
- W ∈ R^{d × V}: 出力重み行列。隠れベクトル h を語彙ごとのロジットに写す（線形写像）。
- prefix = [t1, t2, ..., tK]: 入力の token インデックスの列。ここでは K=2 で prefix [2,5]。
- h ∈ R^{d}: prefix から得られる最終的な隠れベクトル。ここでは単純に埋め込みの平均をとる。
- logits ∈ R^{V}: ロジットは logits = h^T W（行ベクトルに対する説明では logits_j = h ⋅ w_j で、w_j は W の j 列）。
- softmax: logits を正規化して確率 p_j を作る関数 p_j = exp(logits_j) / Σ_k exp(logits_k)。
- target: 正解の token インデックス（この例は 9）。
- loss: クロスエントロピー損失 loss = -ln p_target。確率が高いほど損失は小さくなる。

行列積と軸を普通の言葉に戻す：
- W の各列 w_j は「隠れベクトル h と内積を取って、その候補 j の生スコア（ロジット）を出すための小さな重みの集まり」。 h と w_j をかけ合わせる（内積を取る）と、その候補のスコアになる。
- 全ての候補について内積を取ると、長さ V の列ロジットができる。これは隠れ状態 h を「語彙空間」に写したものと考えればよい。

## 具体例（prefix [2,5] → target 9）を数値で通す

前提（教育用の小さな数値）：
- V = 12, d = 2
- 埋め込み E のうち必要な行だけ：
  - e_2 = [0.5, -0.1]
  - e_5 = [0.2, 0.3]
- 出力重み W の行（2 行 × 12 列）を簡単に指定：
  - Row 0 (W[0, :]) = [0.1, 0.0, 0.2, -0.1, 0.05, 0.0, 0.0, 0.0, 0.1, 0.3, 0.0, 0.0]
  - Row 1 (W[1, :]) = [0.0, 0.2, -0.1, 0.05, 0.0, 0.1, 0.0, 0.0, 0.2, 0.0, 0.0, 0.0]
- 学習率 lr = 0.1
- target = 9

順伝播（forward）：
1. 隠れベクトル h を埋め込みの平均で作る。
   h = (e_2 + e_5) / 2 = ([0.5+0.2]/2, [-0.1+0.3]/2) = (0.35, 0.10)

2. ロジット logits = h^T W。列ごとに内積を取るので、各 j について
   logits_j = h0*W[0,j] + h1*W[1,j]
   代表的な j の値を計算すると（小数第3位で四捨五入）:
   - logits_0 = 0.35*0.1 + 0.1*0.0 = 0.035
   - logits_2 = 0.35*0.2 + 0.1*(-0.1) = 0.06
   - logits_3 = 0.35*(-0.1) + 0.1*0.05 = -0.03
   - logits_8 = 0.35*0.1 + 0.1*0.2 = 0.055
   - logits_9 = 0.35*0.3 + 0.1*0.0 = 0.105
   その他の位置は 0〜0.035 程度になる。

3. softmax を取って確率に変換する。
   - まず exp を取ると、exp(logits_9) ≈ 1.1107 などとなる。
   - 全ての exp の和 S ≈ 12.28305。
   - したがって target=9 の確率 p_9 ≈ 1.1107 / 12.28305 ≈ 0.09045（約 9.0%）。

4. 損失 loss = -ln p_9 ≈ 2.4014。

逆伝播（loss を重み更新につなげる）：
- softmax とクロスエントロピーの組合せでは、ロジットに関する損失の勾配は簡潔に表せる：
  grad_logits = p - y
  ここで y は one-hot ベクトル（target の位置が 1、他は 0）。
  したがって target の位置では grad_logits_9 = p_9 - 1 = -0.90955。
  他の位置 j では grad_logits_j = p_j（正の小さな値）。

- W に関する勾配は、ロジットが線形であることを利用して外積で表される：
  grad_W = h[:, None] × grad_logits[None, :]
  つまり grad_W[i, j] = h_i * grad_logits_j。

- 具体的に W[0,9] の勾配は
  grad_W[0,9] = h0 * grad_logits_9 = 0.35 * (-0.90955) ≈ -0.31834。

パラメータ更新（単純な確率的勾配降下法）：
- W_new = W_old - lr * grad_W
- 特に W[0,9] の更新は
  W_new[0,9] = 0.3 - 0.1 * (-0.31834) = 0.3 + 0.031834 ≈ 0.331834。

この一回で起きたことのまとめ：
- 順伝播で前置 [2,5] は隠れベクトル h に圧縮され、その h から各語彙のロジットが計算され、softmax で確率に変換された。
- 実際の確率は target=9 に対して約 9% で、損失は約 2.40。
- 逆伝播により W の要素（ここでは W[0,9]）に対する勾配が得られ、その勾配に基づいて W[0,9] が 0.3 → 0.331834 に更新された。
- 更新の符号は「target のロジットを上げる方向」であり、これが次回に target の確率を高くするように働く。

補足：上記の小さな数値は教育用の擬似値であり、実際の Transformer や GPT 系モデルの内部で観察される値・スケールとは異なります。

## 透明な短い Python（NumPy）コード

以下は上の数値例をそのまま計算する最小限のコード。変数名は数式と対応するようにしました。実際のライブラリの自動微分は使わず、手計算した勾配の式を使っています。

```python
import numpy as np

V = 12
d = 2
lr = 0.1
target = 9
prefix = [2, 5]

# 埋め込み（E）と出力重み（W）
E = np.zeros((V, d))
E[2] = np.array([0.5, -0.1])
E[5] = np.array([0.2, 0.3])

W = np.zeros((d, V))
W[0] = np.array([0.1, 0.0, 0.2, -0.1, 0.05, 0.0, 0.0, 0.0, 0.1, 0.3, 0.0, 0.0])
W[1] = np.array([0.0, 0.2, -0.1, 0.05, 0.0, 0.1, 0.0, 0.0, 0.2, 0.0, 0.0, 0.0])

# 順伝播: 埋め込みの平均 -> h -> logits -> softmax -> loss
h = (E[prefix[0]] + E[prefix[1]]) / 2.0           # shape (d,)
logits = h @ W                                    # shape (V,)
exp_logits = np.exp(logits)
probs = exp_logits / np.sum(exp_logits)
loss = -np.log(probs[target])

# 逆伝播（softmax + cross-entropy の簡便式）
grad_logits = probs.copy()
grad_logits[target] -= 1.0                        # p - y

# W に関する勾配（外積）
grad_W = np.outer(h, grad_logits)                 # shape (d, V)

# パラメータ更新（単純なSGD）
W -= lr * grad_W

# 結果表示（主要な数値）
print("h =", h)
print("logits[target] =", logits[target])
print("prob[target] =", probs[target])
print("loss =", loss)
print("grad_W[0,9] =", grad_W[0,9])
print("W[0,9] after update =", W[0,9])
```

このコードは教育目的の手順を実装するもので、実運用の学習スクリプトはバッチ処理、自動微分、複雑な最適化器（Adamなど）、勾配クリッピング、学習率スケジューラ、混合精度などを加える。

## バッチ処理、反復とバリアントについての直感

- バッチ: 多数の前置を同時に処理して得られる損失の平均に対して勾配を計算すると、ノイズが減り安定して更新できる。実装上は各前置を行列としてまとめ、同時に h を計算してまとめて W の勾配を算出する。
- ミニバッチと確率的勾配降下法（SGD）: 1つの前置で更新するよりミニバッチで平均を取る方が典型的に効率が良い。学習率やバッチサイズで挙動は変わる。
- オプティマイザ: 実際の学習では単純な SGD ではなく、Adam のような慣性・スケール補正を持つ手法がよく使われる。これらは勾配の履歴を保持し、更新の大きさや方向を調節する。

## full Transformer 内での前後の処理と訓練ループの位置

実際の Transformer（ここでは GPT 型の decoder-only 系を想定）では、今回扱った「埋め込み → 隠れベクトル h → 線形出力 W によるロジット」は次のような流れの一部である。

1. トークナイザで文字列を token に分割しインデックス化する（token は単語ではないことに注意）。
2. token インデックスを埋め込みベクトルに変換（E）。ここに位置情報を加える（位置埋め込みや相対位置表現）。
3. 一連の Transformer ブロック（自己注意とフィードフォワード）を通じて、各位置に対応する隠れベクトルを生成する。decoder-only では過去の位置のみを参照するよう因果的マスクが入る。
4. 最終層の隠れベクトルを語彙に写すため lin = h W でロジットを得る（今回の簡易例の W に相当）。
5. softmax と損失計算、逆伝播、最適化器によるパラメータ更新。ここで「パラメータ」とは埋め込み E、各 Transformer ブロックの重み、出力重み W などすべてを含む。

今回示した訓練ループは（4）と（5）を簡略化して示したものであり、実際には（2）と（3）の計算が何十層にもわたって行われ、その途中の勾配伝播が自動微分ライブラリで管理される。計算効率のために Attention の高速化（FlashAttention など）、分散学習やメモリ最適化が導入される。

## よくある誤解の訂正（少なくとも一つ）

誤解: 「訓練後に得られる attention weight を見ると、モデルが『人間と同じ意味で注目している』ことが証明される。」

訂正: attention weight はある入力に対して計算されたスカラーの集合で、モデルの内部計算に寄与する一要素に過ぎない。重みが高いからといって人間的な『注目』や解釈可能性を直接示すわけではない。attention が言語的構造と一致する場合もあれば、表面上一致しても内部の他の計算と相まって人間的な理解に結びついているとは限らない。注意深い実験と因果的解析が必要である。

## 実際の大規模モデルとのつながり（実装上の差分）

- スケール: 実モデルは d が数千、語彙 V が数十万、レイヤー数が数十〜百、学習データが数テラバイトと圧倒的に大きい。数値の絶対スケールや数値の振る舞いはここで示した簡易例と大きく異なる。
- 最適化: 実務では AdamW、RMSNorm、学習率ウォームアップ、重み減衰（weight decay）、勾配ノルムのクリッピング、mixed precision（半精度）などが不可欠。
- 実行効率: Attention の計算やメモリ転送を高速化するための専用実装（FlashAttention、分散処理、モデル並列化）が用いられる。
- 勾配とチェックポイント: 勾配の数値安定性を保つために勾配正規化やチェックポイント（中間活性化の保存方法）に工夫がある。

注意：ここで挙げた手法は現代の実装でしばしば採用されるが、全研究・全実装で共通というわけではない。例えば RMSNorm はある系で採用が広いが、常に標準というわけではない。

## 章の終わりに：読者が説明できること（チェックリスト）

この章を読み終えた後、あなたは次を説明できるはずです。

- 前置（prefix）から最終的な「ロジット」を得る順伝播の流れと、推論時に重みを更新しないことの意味。
- softmax とクロスエントロピー損失の関係、およびその結果として得られるロジットに対する簡潔な勾配式（grad_logits = p - y）。
- パラメータ（例：出力重み W）の勾配が隠れベクトルとロジット勾配の外積で表される理由と、その更新が target のロジットを上げる方向に働くこと。
- 訓練ループ（前進→損失→逆伝播→更新）がなぜ繰り返されるのか、そしてバッチやオプティマイザが果たす実用上の役割。
- 推論と訓練の違い（勾配計算・パラメータ更新の有無）を具体的な数値の流れで説明できること。

## 確認問題（短い問題を2問）

1. あなたはある語彙サイズ V=5、隠れ次元 d=3 のモデルを持つ。ある入力で隠れベクトル h = [0.2, -0.1, 0.5] が得られ、ある候補 j のロジットが 0.4 であった。softmax によるその候補の確率が 0.2 だったとき、損失（クロスエントロピー）とそのロジットに対する勾配（loss を logits_j で微分した値）を計算せよ。

2. 上の本章の具体例で、もし学習率を 0.01 にしたら、W[0,9] の更新後の値はいくらになるか計算せよ。（ヒント：grad_W[0,9] を再利用）
