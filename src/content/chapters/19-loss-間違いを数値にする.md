# Loss: 間違いを数値にする

問題提起 — なぜ「次に来る正解」を1つの数にするのか
まず問いをはっきりさせます。言語モデルを学習させるとき、ある時点の文脈に対して「次に続く正しいトークン」が訓練データに書かれています。学習の目的は、モデルがその正しいトークンをなるべく高い確率で予測するようにパラメータを変えることです。では、「なるべく高い確率」を数学的にどのように表現して、パラメータをどのように変えればよいでしょうか。

単に「正解が上位に来るようにする」と漠然と言うだけでは機械的に扱えません。学習アルゴリズムには「このままではどれだけ間違っているか」を1つの数（損失）で返してもらい、その数を小さくする向きにパラメータを更新します。ここで問題は、予測確率の差をどう数に変えるか、すなわち「確率が0.8と0.2だったらどちらをどれだけ強く直すべきか」を合理的に表現することです。章の残りは、この「確率を損失に変えるルール」を直感的かつ数値的に説明します（仕組みの名前は動機の説明段階では伏せます）。

有用な直感（かつ注意点）
直感的には、確率が低いほど「もっと直してほしい」と感じます。0.2と0.8の差は見た目では 0.6 の差ですが、学習で必要な力の大きさ（「どれだけ重みを変えるべきか」）は単純な差だけで決まらないことが多いです。現実には、0.2を0.4に上げるのと、0.8を0.95に上げるのでは「重みの調節の難しさ」や「与えるべきシグナルの強さ」が違います。損失関数は、こうした違いを自動的に反映するために対数という変換を使います。

注意点：ここでの「確率」はモデルが出す予測確率であり、データの真の確率とは別物です。また「大きな損失＝正しくない」を意味しますが、損失が小さいことが必ずしも“意味的に正しい”生成を保証するわけではありません（下で誤解の訂正をします）。

数値オブジェクトの区別
以降で登場するものをはっきり区別します。

- 入力データ（離散）: たとえばトークンID 17。これは数そのものですが学習可能ではありません。
- 埋め込み・アクティベーション（実数ベクトル）: 埋め込みベクトル e ∈ R^d、モデル内部の出力 a ∈ R^d。これらはデータ由来ですが、学習中はパラメータによって変わります。
- 学習パラメータ（固定の実数集合）: 出力層の重み W_out ∈ R^{V×d}、バイアス b ∈ R^V など。これらを更新してモデルを学習します。
- ロジット（スコア）: z = W_out a + b ∈ R^V。語彙ごとの未正規化スコア。
- 確率分布（正規化）: p ∈ R^V、p_i ≥ 0、∑_i p_i = 1。ロジットに対して softmax を取って得る。
- ラベル（正解）: 正解トークンのインデックス y（あるいはワンホット表現）。
- 損失（スカラー）: 正解トークンに対する数値 L。学習アルゴリズムはこのスカラーを小さくする方向にパラメータを更新します。

具体例（必須） — 確率0.8と0.2の -log の比較
ここで必ず示す数値例です。自然対数を用いると、確率 p に対する「損失候補」は -ln(p) になります。実際の数を計算します。

- p = 0.8 のとき: L = -ln(0.8) ≈ 0.2231435513
- p = 0.2 のとき: L = -ln(0.2) ≈ 1.6094379124

同じ“正解”に対して、確率が0.2のときの損失は確率が0.8のときより約7.22倍大きくなっています（1.609 / 0.223 ≈ 7.22）。直感的な「差0.6」よりも、学習上必要とされる“重みを動かす力”の差は遥かに大きいことを示します。これは対数関数が小さいpをより強く罰するためで、確率がほとんどゼロに近い場合は損失が急増します。

動機の後の数式（記号と軸の説明を含める）
まず一例として1つの時刻での計算を書きます。語彙サイズを V、内部表現の次元を d とします。

- モデルの出力（アクティベーション）: a ∈ R^d（前段の Transformer 層からの出力ベクトル）
- 出力層の重みとバイアス: W_out ∈ R^{V×d}, b ∈ R^V
- ロジット（スコア）: z = W_out a + b, ここで z ∈ R^V
  - 「行列積 W_out a」は、各語彙項目 i に対してスコア z_i を計算することを意味します。W_out の i 行は語彙 i に対応する重みベクトル（長さ d）です。
- ソフトマックスによる確率化:
  p_i = exp(z_i) / sum_{j=1..V} exp(z_j)  for i = 1..V
  - 全ての語彙スコアを正の数に変換して合計で割り、確率分布にします。
- 損失（単一トークン）:
  L = - ln p_{y}
  - 正解トークン y の確率を対数で負にしたもの。これが学習信号になります。

なぜ対数をとるのか（平易な説明）
対数をとる理由は複数ありますが、直感的には次の点が重要です。

1. 積の和に変換されるため、系列長全体の損失が扱いやすくなる（対数は積を和にする機能）。言語では複数の時刻の確率を掛け合わせる場面があるので、合計で損失を扱えるのは便利です。
2. 小さい確率をより強く罰することで、モデルが「ゼロに近いけれど本来あるべき確率」を持つ語彙に対して大きな修正を受ける。逆に、すでに高確率（例えば0.99）を持っている語彙をさらに少し上げるインセンティブは相対的に小さい。
3. 数学的に勾配（パラメータをどう動かすか）を取るとき、対数を取ると扱いやすい形になる（対数の導関係が理由）。ここでは計算は示しますが、高等数学の前提は不要です。

ロジットと確率の関係を具体的なロジット差で示す
2語彙（V=2）の単純な例で、ある語彙を正解とし、もう一つを非正解とします。softmax において正解が i、対の語彙が j の場合、正解の確率は

p_i = 1 / (1 + exp(z_j - z_i)) = sigmoid(z_i - z_j)

となります。ここから、p_i = 0.8 を得るためには z_i - z_j = ln(0.8/0.2) = ln(4) ≈ 1.38629 の差が必要です。逆に p_i = 0.2 であれば差は ln(0.25) ≈ -1.38629 です。つまり確率の上下はロジット差に線形に対応しますが、確率自体はロジット差の非線形写像です。

短いPythonコード（数式の変数名と対応）
以下は上の式の直接実装です。実験的にロジットを作ってソフトマックスと損失を計算します。ここでは numpy を使います。変数名は数式に合わせています。

```python
import numpy as np

def softmax(z):
    z = z - np.max(z)        # 数値安定化
    expz = np.exp(z)
    return expz / expz.sum()

# case A: p_true = 0.8  -> z_true - z_other = ln(4) ≈ 1.38629
z_caseA = np.array([1.38629436112, 0.0])   # z_true, z_other
p_caseA = softmax(z_caseA)
loss_caseA = -np.log(p_caseA[0])

# case B: p_true = 0.2  -> z_true - z_other = ln(0.25) ≈ -1.38629
z_caseB = np.array([-1.38629436112, 0.0])  # z_true, z_other
p_caseB = softmax(z_caseB)
loss_caseB = -np.log(p_caseB[0])

print("p_caseA[0] =", p_caseA[0], " loss =", loss_caseA)
print("p_caseB[0] =", p_caseB[0], " loss =", loss_caseB)
```

このコードを実行すると、先に示した数値（約0.223 and 1.609）が得られるはずです。ここで大事な点は、損失は確率 p（softmax の出力）だけで決まり、ロジットや重みそのものはその背後で損失を減らすために調整される、という点です。

ミニバッチ・系列・平均化について
実際の訓練では、1つのトークンの損失をそのまま使うことは少なく、ミニバッチ内の複数トークン・複数系列にわたる損失を平均（あるいは合計）して最終的なバッチ損失を得ます。文の長さが異なる場合はパディング位置をマスクして損失計算から除外します。損失関数としては上で示した単一トークンの -ln p_y を平均したものが「クロスエントロピー損失」にあたります（後で用語を明示します）。

現実のTransformerとの結びつけ
Transformer（原著の encoder-decoder 構造）では翻訳の教師あり学習で、decoder 部分における各位置の「次トークン」を教師として上の損失を使います。一方で、GPT 型の decoder-only モデルでは自己回帰的に「次トークン予測」を行い、同じ -ln p_y を全位置で合計（あるいは平均）して学習します。違いはモデルの前段（encoder の有無や、トレーニング時のマスクの違い）にあり、損失そのものは同じ数学的枠組みで扱えます。ただし、用語や処理フローを混同しないよう注意してください：原論文（Vaswani et al., 2017）は encoder-decoder の設定を扱い、GPT 系は自己回帰学習に焦点を当てています。

よくある誤解の訂正
- 「損失が小さい＝モデルが正しい」ではない：損失は訓練データに対する確率的適合度を表します。モデルが訓練データと違うがらみの偏見を学んでしまっている場合でも損失は小さくなります（過学習やデータの偏り）。
- 「確率が高い＝モデルは自信を持っている」：確率はモデル内部のスコアを正規化したものです。キャリブレーションが悪いと（特に深層モデルでは）過剰に確信してしまうことがあります。確率 ≠ 「人間の意味での確かさ」。
- 「注意（attention）重みは人間的な注目の完全な証拠」：attention の重みは内部計算の一部であり、人間が行うような説明（なぜその単語を参照したか）を常に与えるわけではありません。損失や予測確率とは別の話題です。
- 「小さな数値例は実モデルの内部状態を表す」ではない：本章の数値は概念説明のための単純化された例で、実際の大規模モデルのロジットや確率は次元やスケール、正規化方法が異なります。教科書の小数値は直感を与えるためのもので、実機の内部値ではないことを明示します。

実装上の注意（実務的ポイント）
- 語彙サイズ V が非常に大きいと softmax の計算が重くなります。実務では効率化（ケープト化、サンプリング手法、FlashAttention など）を行いますが、損失の定義自体は同じです。
- 出力層の重み W_out は埋め込み行列の転置を共有（weight tying）することが多いです。これによってパラメータ数を節約し、学習が安定することがありますが、これは実装の工夫の1つであって損失定義の本質を変えません。
- ラベルスムージングという手法は、正解ラベルのワンホットをわずかに平滑化して「過剰な確信」を抑えるため、損失計算に小さな変更を加えます。これは学習の安定化手段の1つです。

確認問題（短い）
1) あるモデルのある位置で、正解トークン y の確率が 0.95 のときと 0.6 のときの損失を計算し、その比を求めよ（自然対数を用いること）。またその比が意味することを簡潔に説明せよ。
2) 語彙サイズ V=3 の場合、ロジット z = [2.0, 1.0, 0.0] の softmax 確率と、正解が第1要素（インデックス0）だったときの損失を計算せよ（自然対数を用いること）。また、もし z を [3.0, 1.0, 0.0] に増やしたときに損失がどのように変わるかを説明せよ。
