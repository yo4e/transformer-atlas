# Embeddings: ID がベクトルになる

問題提起 — なぜ「ID をベクトルにする」仕組みが必要か

コンピュータは数を扱えますが、言葉や項目（単語・サブワード・ユーザーID・商品IDなど）はそのままでは計算できません。例えば「りんご」「みかん」「ばなな」という3つの語を受け取るニューラルネットワークに、これらをそのまま入力しても意味がありません。そこで各語を数値に対応させる「ID」（0,1,2 のような整数）はまず必要になります。しかし整数だけでは問題は解決しません。単なる整数IDは順序や差の意味を不当に含んでしまい（2 − 1 の差が語彙の意味差にならない）、またネットワークが学習して内部で使える連続的な表現ではありません。そこで、離散的なIDを「計算可能な小さな実数ベクトル」に変換する仕組みが必要になります。本章で扱うのはその仕組みと、その仕組みが「学習によりどう変化するか」「実際にどのように計算されるか」です。

最初に注意したい点（直感と誤解の種）

直感的には、ID → ベクトル（embedding）は「単語を意味の座標に置く」行為として説明されることが多いです。確かに学習が進めば類似した語は近いベクトルに収まる傾向がありますが、重要なのは以下の2点です。

- IDそのもの（例えば整数の 17）が意味を持つわけではない。IDは単なるラベルで、意味は対応するベクトル（数値列）にあります。
- embeddingベクトルは「表現としての値」であって、学習によって変化するパラメータ（モデルの重み）です。推論時の「入力に対して計算される一時的な値」（activation）と区別して扱う必要があります。

またよくある誤解を先に潰すと、embeddingの座標軸（第1成分、第2成分など）にそれぞれ「色」や「大きさ」といった直観的な意味が対応しているわけではありません。学習された座標軸はモデルが内部で扱いやすい抽象量になっているだけです。

用語をはっきりさせる

ここで以降使う語の意味をはっきりさせます（難しい数学用語は避け、感覚的に説明します）。

- ID：語彙やカテゴリに割り振られた整数ラベル（例：0,1,2,...）。これは入力であり、固定される。
- embedding table（埋め込み表）：IDごとに対応するベクトル（数値列）を並べた表。モデルの学習パラメータの一部。
- 埋め込みベクトル（embedding vector）：あるIDに対応する表の1行。これが実際にニューラルネットワークに渡される数値のまとまり（activationの元になる）。
- activation（活性化、出力値）：あるレイヤに入力して得られる一時的な数値。学習中は誤差に基づいてパラメータが更新されるが、activation自体は毎回計算される値。
- 学習パラメータ（parameter）：訓練によって更新される持続的な数値（埋め込み表の値もここに含まれる）。

具体例を先に示す（語彙4・次元3、ID列 [2,0,3]）

まずは実際の数を見て直感を固めます。語彙（vocabulary）のサイズを V = 4、埋め込み次元を d = 3 とします。埋め込み表 E を行ごとに示すと次のような数値になります（これは教科書用の例であり、実際の大規模モデルの内部値ではありません）。

E (4×3) =
Row 0: [ 0.1, -0.2,  0.3 ]
Row 1: [ 0.0,  0.5, -0.1 ]
Row 2: [ 1.2, -0.4,  0.7 ]
Row 3: [-0.3,  0.8,  0.2 ]

ここで入力として ID の並び i = [2, 0, 3]（長さ N = 3）を与えます。埋め込みの「ルックアップ」は単純で、このID列の順に表の該当行を取り出します。結果は行列 X（N×d）になります：

X = [ E[row 2],
      E[row 0],
      E[row 3] ]

数値をそのまま並べると

X (3×3) =
[ 1.2, -0.4,  0.7 ]   ← ID 2
[ 0.1, -0.2,  0.3 ]   ← ID 0
[-0.3,  0.8,  0.2 ]   ← ID 3

これが embedding lookup の全過程です。形（shape）だけでなく、各要素がどの行から来たかを明示しています。

別の見方：one-hot を使った選択

ID選択は数学的には one-hot ベクトルを使った乗算でも表現できます。ID j を表す one-hot ベクトル h ∈ R^V は j 番目だけが 1、他は 0 です。行列 H（N×V）を作り、各行が対応するIDの one-hot になっているとします。すると

X = H · E

になります。ここで H の i 行は ID i の one-hot で、行列積がちょうど対応する行を選ぶ操作になっています（one-hot の行と E の対応行が掛け合わさるため）。実装上は index で直接行を取り出す方が効率的ですが、数学的理解としてはこちらも有益です。

学習と更新の流れ（embedding がパラメータであること）

埋め込み表 E はニューラルネットワークの他の重みと同様に学習パラメータです。順伝播で ID → 埋め込みベクトルのルックアップをして得た X は、その後の層（例えば多層パーセプトロン、Attention 、出力層など）に入力され、最終的に損失（loss）が計算されます。誤差逆伝播法（backpropagation）により、その損失の勾配が E の該当行（ルックアップされた行）にだけ伝わり、それらの行の値が更新されます。言い換えると：

- 順伝播：E の該当行が取り出され、後続の計算の入力となる。
- 逆伝播：後続の計算から来た勾配が、対応する E の行に加算される（複数回出現する同一IDは勾配が累積される）。
- 更新：オプティマイザ（SGD, Adam など）によって、その行の値が変化する。更新されない行（学習で一度も出現しないID）もありうる。

具体例に戻ると、ID 列 [2,0,3] を用いてバッチ一回の順伝播を行えば、E の行 2,0,3 にのみ勾配が流れ、行 1 は更新されません（トレーニングデータに現れない語の埋め込みはしばらく更新されない）。

数式で整理する（記号の意味を普通の言葉で）

用いる記号とその意味を繰り返します。

- V：語彙サイズ（表の行数）
- d：埋め込み次元（表の列数）
- N：入力列の長さ（トークン数）
- E ∈ R^{V×d}：埋め込み表、行 j は E_{j,:}（あるIDに対応するベクトル）
- i ∈ {0,...,V-1}^N：ID の列（入力）
- H ∈ {0,1}^{N×V}：ID列に対応する one-hot 行列（行ごとに1つだけ 1）
- X ∈ R^{N×d}：埋め込みルックアップの結果（各行が該当IDのベクトル）

関係は簡潔に書くと

X = H · E,

もしくは索引表記で

X[n,:] = E[i[n],:]   for n = 0,...,N-1.

ここで「·」は行列積を意味し、H の各行が one-hot なので H·E の n 行目は E の i[n] 行目と一致します。後続の層に渡った X は、そのまま足し算や行列積の入力になります（例えば、位置情報を加える、あるいは線形変換を掛けるなど）。

小さな数値例で更新の流れ（直観的示唆）

先ほどの具体例でさらに一歩進めて、X を次の単純な出力 y_hat = X · w で縮約する線形層（ここでは d→1 の線形写像）を考えます。w ∈ R^{d} を重みとし、最終出力がスカラーであるとします。損失 L = 1/2 (y_hat − y)^2（目標 y が与えられる）だった場合、勾配は chain rule によりまず w へ、次に X の各成分へ流れます。X は E の該当行なので、E の該当行の値が更新されます。重要な点は「更新は E 全体ではなく、実際にルックアップされた行に限られる」ということです。

短い Python 実装例（Numpy ベース、数式と変数名を対応）

以下は上の数式と対応する簡潔なコードです。変数名は数式と一致させています。

```python
import numpy as np

V = 4   # 語彙サイズ
d = 3   # 埋め込み次元

# 埋め込み表 E (V x d)
E = np.array([
    [ 0.1, -0.2,  0.3],   # row 0
    [ 0.0,  0.5, -0.1],   # row 1
    [ 1.2, -0.4,  0.7],   # row 2
    [-0.3,  0.8,  0.2]    # row 3
])

# 入力 ID 列 i (長さ N=3)
i = np.array([2, 0, 3])

# ルックアップ（numpy のインデクシングで行を取り出す）
X = E[i]   # shape (N, d)
# X は [[1.2, -0.4,  0.7],
#       [0.1, -0.2,  0.3],
#       [-0.3, 0.8,  0.2]]

# one-hot を使うなら
H = np.zeros((len(i), V))
H[np.arange(len(i)), i] = 1
X_alt = H.dot(E)  # X_alt は X と同じ
```

このコードは単純なルックアップ操作を示すもので、実際のフレームワークではメモリ効率や GPU での実行を重視した専用実装（例えば PyTorch の nn.Embedding）が使われます。

Transformer の中での位置と実装上の注意

オリジナルの Transformer（Vaswani et al., 2017）では、入力トークンはまず埋め込み表でベクトルに変換され、その後「位置情報」を持たせるために位置エンコーディングを加え（加算）、その合成ベクトルがエンコーダ／デコーダブロックの最初に渡されます。ここで重要なのは：

- 埋め込みはトークンごとの初期表現であり、Attention レイヤや FFN レイヤによりさらに変換される「出発点」であること。
- 位置エンコーディングは埋め込みと同じ次元である必要があり、通常は足し算で合成される（既存の実装では学習可能な位置埋め込みを使うことも固定のサイン波を使うこともある）。
- 出力側（生成する語の確率分布を作るための線形層）は、埋め込み表と重みを共有（weight tying）することがよくある。ただしこれは設計上の選択であり、すべてのモデルが採用するわけではない（原著 Transformer はエンコーダとデコーダの埋め込みを共有しているが、出力投影との共有は明示していない）。

現実の大規模モデルとの接続（実装上・運用上の視点）

実運用では語彙は数十万〜数百万、次元 d は512〜数千に及び、各エントリは32ビット浮動小数点が使われることが多いです。すべての埋め込みをメモリに置いたまま更新するコストは高く、それを軽減する工夫（分散学習、部分更新、パラメータサーバ、混合精度など）が用いられます。また、実際のトークンは単語ではなくサブワード（BPE や SentencePiece）であることが多い点に注意してください（Sennrich et al., 2016）。トークン ≠ 単語、これは重要な実装上の事実です。

よくある誤解の訂正

1) 「ID の差が意味の差を表す」：たとえば ID 5 − ID 3 = 2 が「意味的差分」を表すわけではありません。ID は単なるラベルであり、意味は対応するベクトルにあります。

2) 「埋め込みの各次元に人間が解釈可能な意味がある」：一部の次元が特定の属性に対応して見えることはありますが、これが常に成り立つわけではなく、次元ごとの意味付けは保証されません。

3) 「Attention weight は人間が注目した証拠」：Attention の重みが高い（大きい）ことはモデルがある入力の組合せを計算に強く使っていることを示しますが、それが「人間的な注目（解釈）」をそのまま意味するとは限りません。注視の有無を示す一つの信号にすぎず、モデルの内部計算全体を説明する十分条件ではありません。

最後に：学習可能な値と推論時のactivationの区別（繰り返し）

重要な整理として、以下は明確に区別してください。

- E（埋め込み表）は学習パラメータ（訓練で変化する）。
- X（id から得られる行列）はその都度計算される activation（入力に依存する一時的な値）。
- 学習時、勾配は X を経由して E の該当行へ伝わり、E が更新される。

まとめ：読者が説明できること（短く箇条で）

- なぜ離散IDを埋め込みベクトルに変換する必要があるか。
- 埋め込み表 E とルックアップ X (= E[i]) の違いと計算方法（one-hot を使った行列積の観点も含む）。
- 埋め込みが学習パラメータであり、どのようにして更新されるか（ルックアップされた行にのみ勾配が流れる）。
- Transformer における埋め込みの置かれ方（位置情報の加算、出力投影との重み共有は設計選択であること）。
- トークン ≠ 単語、実際にはサブワードが使われることが多い点。

確認問題（自身で答えを書いてみてください）

1. 語彙サイズ V=4、次元 d=3、埋め込み表 E を本章の具体例と同じ値とします。入力ID列が [0,2,2] のとき、ルックアップで得られる行列 X を明示的に求めよ。また、この入力に対して X の各行に同じベクトル v = [0.5, 0.0, -0.5] を足した場合、埋め込み表 E のどの行が学習時に更新されると期待されるか説明せよ。

2. one-hot 行列 H（N×V）を使う方法と、インデクシングで直接行を取り出す方法の長所短所を一つずつ挙げよ。特にメモリや計算効率の観点を中心に説明せよ。

補足（最後の注意）

本章の数値例は教科書的な説明を目的とした単純化された値です。実際の大規模モデルでは次元や値の振る舞いは異なり、学習や最適化に高度な手法が用いられます。また、本章では埋め込みの基本的性質と実用的な取り扱いに焦点を当て、派生的な変種（例：相対位置エンコーディング、ロータリーポジショナル埋め込みなど）は別章で扱います。
