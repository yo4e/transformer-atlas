# Tokens: 文字列が部品になる

問題提起――なぜ文字列を別のものに変える必要があるのか
現実の言葉は長さが自由な文字列（たとえば "青い猫" や "unhappiness"）です。一方で計算機や学習済みの数値モデルは有限個の離散的なシンボルや固定長の数値ベクトルで処理します。任意長の文字列を、決まった数だけ使える「記号」へと写像する仕組みが必要になります。これがなければ、未知の単語や新しい表記、複数言語混在の入力をモデルに与えられません。さらに、計算コストや並列化の観点でも、扱う単位の総数（語彙の大きさ）と一文あたりのトークン数を制御する必要があります。

ここで注意する点を最初に述べます。下で説明するトークン化の仕組みは「言語学上の単語」と同じではありません。トークンはモデルが扱いやすい断片であり、語彙表に登録された「テンプレート」への対応関係です。トークン化方式は設計・学習に依存し、同じ文字列が仕組みによって別のトークン列になります。

直観とその限界
直観的には「トークンは単語の代わり」と言いたくなりますが、これは正確ではありません。長い単語は分割されることが多く（subword）、短い語が結合されることもあります。言語や利用目的に応じて「どの断片を単位にするか」は設計上のトレードオフです。

有用な直感：
- トークンは「断片テンプレートの辞書」を参照するためのインデックス列だと考えるとよい。
- トークン化によって得られる列の長さは、計算量（時間・メモリ）に直接影響する。短い列は速いが語彙を増やす必要がある。
ただし直観が文字どおりではない点：
- ある単語が常に同じトークン列になるとは限らない（大文字小文字、前処理、Unicode正規化、スペースの扱いなどで変わる）。
- トークン境界は言語学上の境界と一致しないことが普通で、同じ語彙を共有する複数言語で別の分割が有用になる。

数学的な記述（記号の意味を自然言葉に戻す）
以下で使う記号の意味を簡単に列挙します。
- V: 語彙（ボキャブラリ）の大きさ（有限の整数）。
- d: 埋め込み（embedding）ベクトルの次元（正の整数）。
- s: 入力文字列（例："青い猫"）。
- T(s): 文字列 s を語彙のインデックス列に変換する手続き（トークン化）。結果は整数列 [i1, i2, ..., iN]、各 ij は 0..V-1 のいずれか。
- E ∈ R^{V×d}: 埋め込み行列。j 行目が語彙 j に対応する d 次元の実数ベクトル（学習可能パラメータの場合が多い）。
- P_j ∈ R^d: 位置埋め込み（位置 j に対応する d 次元ベクトル）。位置埋め込みは固定関数でも学習可能でもよい。
- X ∈ R^{N×d}: トークン列から作られる入力行列。行 t は E[i_t] + P_t（埋め込みベクトルと位置ベクトルの和）。

これを式で書くと、
1) T(s) = [i1, i2, ..., iN] （整数列）
2) X_t = E[i_t] + P_t  （t = 1..N）
ここで E[i_t] は E の i_t 行（d 次元の行ベクトル）を意味し、X の各行 X_t はモデルに入力される「活性化（activation）」です。E や P の各成分は「学習可能パラメータ」または固定のハイパーパラメータであり、X_t は入力文字列から計算される「活性化」です。この区別を常に意識してください。

教育用の具体例（数を実際に計算する）
ここで完全に具体的な小さな語彙と埋め込みを使い、"青い猫" と "unhappiness" を二つの異なるトークナイザで処理して違いを示します。注：以下の小数値は教育目的の例であり、実際の大規模モデルの内部状態を表すものではありません。

トークナイザA（単純なサブワード辞書）:
- 語彙（抜粋）: '青'->10, 'い'->11, '猫'->12, 'un'->20, 'happi'->21, 'ness'->22
- V_A = 30（便宜上）

トークナイザB（別の分割方針）:
- 語彙（抜粋）: '青い'->40, '猫'->12, 'un'->20, 'happy'->23, 'ness'->22
- V_B = 50（便宜上）

埋め込み次元 d = 4 とし、埋め込み行列 E から関係する行だけ示します（行はベクトル，カンマ区切り）:
- E_A[10] = [0.10, 0.20, 0.05, 0.00]  ('青')
- E_A[11] = [0.00, 0.10, 0.00, 0.10]  ('い')
- E_A[12] = [0.50, 0.40, 0.30, 0.20]  ('猫')
- E_A[20] = [0.20, 0.10, 0.00, 0.00]  ('un')
- E_A[21] = [0.30, 0.25, 0.10, 0.00]  ('happi')
- E_A[22] = [0.10, 0.05, 0.05, 0.05]  ('ness')

E_B shares some indices (例: '猫' は 12), ただし '青い' と 'happy' は別の行:
- E_B[40] = [0.08, 0.28, 0.03, 0.01]  ('青い')
- E_B[23] = [0.35, 0.30, 0.15, 0.02]  ('happy')
（同じインデックス番号は異なる語彙表で再割り当てされるが、ここでは示す行値を別々に扱う）

位置埋め込み P_t（t=1,2,3）を簡単に:
- P_1 = [0.01, 0.01, 0.01, 0.01]
- P_2 = [0.02, 0.02, 0.02, 0.02]
- P_3 = [0.03, 0.03, 0.03, 0.03]

では2つのトークナイザで実際に計算してみます。

A: "青い猫"
- T_A("青い猫") = [10, 11, 12]
- 埋め込みと位置埋め込みの和:
  - X_1 = E_A[10] + P_1 = [0.10+0.01, 0.20+0.01, 0.05+0.01, 0.00+0.01] = [0.11, 0.21, 0.06, 0.01]
  - X_2 = E_A[11] + P_2 = [0.00+0.02, 0.10+0.02, 0.00+0.02, 0.10+0.02] = [0.02, 0.12, 0.02, 0.12]
  - X_3 = E_A[12] + P_3 = [0.50+0.03, 0.40+0.03, 0.30+0.03, 0.20+0.03] = [0.53, 0.43, 0.33, 0.23]

B: "青い猫"（別トークナイザ）
- T_B("青い猫") = [40, 12]
- X_1 = E_B[40] + P_1 = [0.08+0.01, 0.28+0.01, 0.03+0.01, 0.01+0.01] = [0.09, 0.29, 0.04, 0.02]
- X_2 = E_B[12] + P_2 = [0.50+0.02, 0.40+0.02, 0.30+0.02, 0.20+0.02] = [0.52, 0.42, 0.32, 0.22]

A: "unhappiness"
- T_A("unhappiness") = [20, 21, 22]  （'un', 'happi', 'ness'）
- X_1 = E_A[20]+P_1 = [0.21,0.11,0.01,0.01]
- X_2 = E_A[21]+P_2 = [0.32,0.27,0.12,0.02]
- X_3 = E_A[22]+P_3 = [0.13,0.07,0.08,0.08]

B: "unhappiness"
- T_B("unhappiness") = [20, 23, 22]  （'un', 'happy', 'ness'）
- X_1 = E_B[20]+P_1 = [0.21,0.11,0.01,0.01]  （shared 'un'）
- X_2 = E_B[23]+P_2 = [0.37,0.32,0.17,0.04]
- X_3 = E_B[22]+P_3 = [0.13,0.07,0.08,0.08]  （shared 'ness'）

これで明確に分かること：同じ文字列でもトークン列の長さやIDが変わり、それに続く行列 X（活性化）も変化する。学習パラメータ（E の各行や P_t）は語彙ごとに異なる実数列であり、文字列から計算される X_t は「活性化」である。

対応する簡単な透明な Python（NumPy）コード例
（教育用で要点を示す最小限のコード）
```python
import numpy as np

E_A = np.zeros((30, 4))
E_A[10] = np.array([0.10, 0.20, 0.05, 0.00])  # '青'
E_A[11] = np.array([0.00, 0.10, 0.00, 0.10])  # 'い'
E_A[12] = np.array([0.50, 0.40, 0.30, 0.20])  # '猫'
E_A[20] = np.array([0.20, 0.10, 0.00, 0.00])  # 'un'
E_A[21] = np.array([0.30, 0.25, 0.10, 0.00])  # 'happi'
E_A[22] = np.array([0.10, 0.05, 0.05, 0.05])  # 'ness'

P = np.array([[0.01]*4, [0.02]*4, [0.03]*4])  # P_1, P_2, P_3

# トークンID列
ids_A_aoineko = np.array([10, 11, 12])
embs = E_A[ids_A_aoineko]      # shape (3,4)
X = embs + P[:len(ids_A_aoineko)]
print("A: '青い猫' の入力活性化:\n", X)
```
このコードは E の行参照と位置和の実際の計算を示しており、モデルに渡される入力行列を具体的に得られます。

トークン化の設計や学習について（概要）
代表的な手法に BPE（Byte Pair Encoding）や Unigram Language Model に基づくサブワード分割があります。これらは大量のテキストを走査し、頻出する断片を語彙として選ぶ方法です。設計上のパラメータ（語彙サイズ V や最大トークン長など）を変えると分割方針が変わり、結果的にトークン列が変わります。言語によっては文字ベースのトークナイザやバイト列をそのまま扱う方式（byte-level BPE など）も使われます。

全体のモデルとの前後関係
入力の前処理段階はおおむね次の順です：
1. 正規化（Unicode正規化、全角半角変換、トリミングなど）
2. トークン化（T(s) による ID 列生成）
3. ID → 埋め込み（E[i] の参照）＋位置埋め込み → 入力活性化 X
4. Transformer（またはその他ニューラル機構）による処理
5. 出力側では最終層のロジットを語彙サイズ V による softmax で確率化し、最も高い ID を選ぶ。出力時に ID を再びトークン→文字列へ戻す処理（デトークナイズ）が必要

現実の大規模モデルとの接続例
実使用では V は数万（例: 30k〜200k）で、d は数百〜数千（例: 768, 1024, 2048）になります。語彙が大きいほど「短いトークン列で表現できる可能性」は上がりますが、学習パラメータも増えます。ここで示した小数値や d=4 は教材上の単純化であり、実モデルの内的表現（値の分布や次元）は大幅に異なります。必ずしも小さな例の数値を実際のモデル挙動に直接適用しないでください。

誤解の訂正（少なくとも一つ）
「トークン数が多い＝モデルがより多くの語彙知識を持っている」は一面の真です。しかし重要なのは「トークンがどのように学習されたか」です。語彙数を増やしても、訓練データにおける分布やパラメータの割当て方によっては性能向上につながらないことがあります。また「attention weight が高ければモデルはその単語に“注目”している」という直感も便利ですが、attention の重みは計算上の割合であり、必ずしも人間の意味的注目と一致する証拠にはなりません。最後に、「トークナイザは交換可能でどれでも同じ結果になる」という誤解も避けてください。トークナイザの違いはモデルの学習プロセスと最終性能に影響します。

まとめ（読者が説明できること）
本章を読めば、読者は以下を説明できます：
- なぜ文字列を有限語彙のID列に変換する必要があるのか（計算と学習の要請）。
- トークナイザが語彙表とID列をどう生成するかの直観と限界。
- 埋め込み行列 E と位置埋め込み P がどのように「活性化」X を作るか、パラメータと活性化を区別して説明できる。
- 同じ文字列がトークナイザによって別のトークン列・長さ・IDになる具体例を示せる。

確認問題（自己確認用）
1. "青い猫" をトークナイザAとBでトークン化したときの ID 列の違いが、Transformer の計算コスト（例：注意機構での N^2）とモデルの入力埋め込みにどう影響するかを説明してください。
2. ある語彙 V と埋め込み E が与えられ、文字列 s のトークン列 T(s) = [i1,i2] が得られたとする。X_1 = E[i1]+P_1, X_2 = E[i2]+P_2 を計算したあと、Transformer の出力が softmax を通して ID j を高確率で返した場合、どうして「モデルが j に関係する意味を知っている」と言えるのか――その主張の根拠と限界を述べよ。
