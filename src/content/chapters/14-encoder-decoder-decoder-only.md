# Encoder, decoder, decoder-only

問題提起 — なぜ二つの「注意の仕組み」が必要か
入力文を別の言語に訳すとき、訳す側（出力を作る側）は原文の全体を参照してよい。一方、文章を自動で続きを生成するとき（「今ある語の列から次の語を当てる」）は、未来の語を見てはいけない。つまり「出力は全入力を自由に参照してよい」場合と「出力は既に出た語だけ参照できる」場合とで、情報の通り道が根本的に違う。翻訳や要約のように「別に与えられた入力列（ソース）」を全体的に利用したいときは、出力側がその全入力を参照できる仕組みが必要だ。対して、文章生成のように「これから出す語はまだ存在しない」場合は、出力を逐次決めるために過去の出力だけを情報源にする仕組みが必要だ。

ここで扱うのはその二つの情報経路の違いを明瞭にし、数値の流れを追える具体例で示すことだ。仕組みの名前（例えば「encoder–decoder」や「decoder-only」）は後で整理するが、まずは「どの情報がどこから来られるか」を明確にしたい。

直感とその注意点
便利な直感は次の二つだ。第一に、「ある出力位置（例：訳文の第二語）は、いつでも原文のどの位置にも『注意（attention）』を向けられる」。第二に、「次の語を予測する場面では未来の語へは注意を向けられない（因果的な制約）」。この直感はほとんどの場合に有用だが、文字どおり「注意が人間の注意と同じ意味で注目の証拠になる」と解釈してはいけない。数式上の attention weight はモデル内部の線形代数結果であり、必ずしも「理由付けの可視化」ではない。さらに、ここで言う「token」は一般にサブワードであり、自然言語の「単語」と一対一対応するとは限らない。

数値オブジェクト（学習するパラメータ）と計算で生じる活性化の区別
以降の説明で出るオブジェクトは二種類に分けて考える。学習されるパラメータ（例：単語埋め込み行列、重み行列 W_Q, W_K, W_V, 出力投影行列）は固定されていない「モデルの可変部分」で、訓練によって更新される。計算過程で得られる中間値（入力埋め込みの組み合わせ、クエリ Q、キー K、値 V、attention のスコアや重み、最終的なレイヤー出力）は「活性化」で、推論ごとに異なる。どれがパラメータでどれが活性化かを常に意識することが重要だ。

まずは数式（記号とその意味）
- 埋め込みテーブル: E — 語彙番号を実数ベクトルに変換する表（パラメータ）。1行が1トークンの埋め込み。
- 入力トークン列（数列）を埋め込みに変換したもの: X ∈ R^{L×d}（活性化）。L はトークン長、d はモデルの次元。
- 学習される線形変換: W_Q, W_K, W_V ∈ R^{d×d_k}（パラメータ）。典型的には d_k = d / h（hはヘッド数）。
- クエリ・キー・値: Q = X W_Q, K = X W_K, V = X W_V（活性化）。Q ∈ R^{L_q×d_k}, K ∈ R^{L_k×d_k}, V ∈ R^{L_k×d_k}。ここで L_q は「クエリの数」、L_k は「キー／値の数」。
- スコア（未正規化）: S = Q K^T / sqrt(d_k)。S_{ij} はクエリ i とキー j の線形内積をスケールした値（活性化）。
- 重み（確率的な正規化）: A = softmax(S)（行単位にsoftmaxを取る）。A_{ij} はクエリ i がキー j に割く重み（活性化）。
- 出力（attention 出力）: O = A V。O ∈ R^{L_q×d_k}（活性化）。

ここで「軸の意味」を普通の言葉で戻すと、Q の各行は「ここ（ある出力位置）が欲しい情報の問い掛け」、K の各行は「ソースの各位置が持つ特徴の要約」、S の行は「その問いと各特徴の親和性」、A がその親和性を正規化した重みで、最終的に O は「重み付けした情報の合成」である。

具体例：『猫が寝る』を翻訳する場合と、prefix『猫が』から次トークンを予測する場合の比較
まず、簡潔にモデルトイセットを決める（これは教育目的の簡略化であり、実際の大規模モデルの内部数値とは異なる）。

設定（例示のための小さな数値）
- モデル次元 d = 4、d_k = 4、単一ヘッド（h = 1）。sqrt(d_k) = 2.0（とする）。
- 語彙の埋め込み（E）から取り出した三つのトークン埋め込み（行列 X_enc、実際は E の該当行）を次のように決める（各行が 4 次元ベクトル）:
  - '猫' → k1 = [1.0, 0.0, 0.0, 0.0]
  - 'が' → k2 = [0.0, 1.0, 0.0, 0.0]
  - '寝る' → k3 = [0.0, 0.0, 1.0, 0.0]
（これらは説明用の単純化で、実際はもっと複雑で連続的な値を取ります。ここでの数値は教材用の小数値であり、実モデルの内部状態ではないことを明記する。）

線形変換はわかりやすくするため単位行列（W_Q = W_K = W_V = I）にすると、Q = K = V = X と考えられる。次に二つの状況を比較する。

A) encoder–decoder 方式（翻訳）
- ソース（エンコーダ）に "猫 が 寝る" が与えられ、デコーダが翻訳文の最初の単語を生成する局面を考える。デコーダ側のその位置のクエリを q_dec = [2.0, 1.0, 0.0, 0.0] とする（活性化）。
- キーはエンコーダの k1,k2,k3。スコアは q_dec · k_j / sqrt(d_k) で計算される。
  - q·k1 = 2.0 → scaled = 1.0
  - q·k2 = 1.0 → scaled = 0.5
  - q·k3 = 0.0 → scaled = 0.0
- softmax を取ると（行ごと）重みは
  - A_encdec ≈ [0.5068, 0.3073, 0.1860]
これはこのデコーダ位置がソースの 3 トークン全てにアクセスでき、その寄与が上の数値で分布することを示す。

B) decoder-only（因果マスク）で prefix = '猫が' から次を予測
- 入力列としてモデルに ['猫', 'が'] が入っている。予測に用いるクエリ（通常は最後の位置の出力に由来）を q_last = [0.5, 2.0, 0.0, 0.0] とする。
- キーとしては存在しているトークンだけ（k1,k2）。未来の '寝る' に対応する k3 はこの時点でモデルの入力にないためアクセスできない（スコアは存在しない、または -∞ にされて softmax 後 0 になる）。
  - q·k1 = 0.5 → scaled = 0.25
  - q·k2 = 2.0 → scaled = 1.0
- softmax を取ると重みは（存在するキーに対して）
  - A_decoder_only_partial ≈ [0.3210, 0.6790]
- 比較のため列の数を揃えて幅 3 にすると、未来の位置はゼロ寄与で表せる：
  - A_decoder_only ≈ [0.3210, 0.6790, 0.0000]

二つの重み行列を並べると分かりやすい（行はクエリ位置、列はソースのトークン '猫','が','寝る'）:
- encoder–decoder のクロスアテンション（1×3）:
  - [0.5068, 0.3073, 0.1860]
- decoder-only（次トークン予測時、prefix='猫が'）を同じ列幅で表すと:
  - [0.3210, 0.6790, 0.0000]

ここから読み取れるのは明快で、encoder–decoder の出力はソース全体（この例では '寝る' を含む）を直接参照できるのに対し、decoder-only は prefix 内にない位置（'寝る'）を直接参照できない、という点である。

数式と軸を普通語に戻す（再掲）
- Q（クエリ）: 「今作っている出力位置が欲しがる情報」の表現が各行。
- K（キー）: 「ソースの各位置が持つ特徴」の表現が各行。
- S = Q K^T / sqrt(d_k)（行 i 列 j は「問い i と特徴 j のスコア」）。
- A = softmax(S)（行 i のスコアを正規化して重みに変換）。
- O = A V（重みで価値（V）を合成して出力を作る）。

短い Python 実装（数式と変数名を対応させる）
以下は上の数値例を再現する最小コード（NumPy を仮定）。変数名は数式と一致させている。

```python
import numpy as np

def softmax_rows(M):
    # 行ごとの softmax
    e = np.exp(M - np.max(M, axis=1, keepdims=True))
    return e / e.sum(axis=1, keepdims=True)

sqrt_dk = 2.0

K_enc = np.array([[1.0, 0.0, 0.0, 0.0],   # '猫'
                  [0.0, 1.0, 0.0, 0.0],   # 'が'
                  [0.0, 0.0, 1.0, 0.0]])  # '寝る'
V_enc = K_enc.copy()

# decoder のクエリ（翻訳時の最初の出力位置）
Q_dec = np.array([[2.0, 1.0, 0.0, 0.0]])  # 1x4

S = (Q_dec @ K_enc.T) / sqrt_dk   # 1x3
A_encdec = softmax_rows(S)        # 1x3 ≈ [0.5068, 0.3073, 0.1860]

# decoder-only の場合（prefix '猫が' だけ存在）
K_prefix = K_enc[:2, :]           # 2x4 ('猫','が')
V_prefix = K_prefix.copy()
Q_last = np.array([[0.5, 2.0, 0.0, 0.0]])  # 1x4

S_pref = (Q_last @ K_prefix.T) / sqrt_dk  # 1x2
A_pref = softmax_rows(S_pref)             # 1x2 ≈ [0.3210, 0.6790]

# 比較のため幅 3 に揃える（未来トークンの寄与は 0）
A_decoder_only_full = np.array([[A_pref[0,0], A_pref[0,1], 0.0]])
```

全体の処理と学習・推論時の違い
- エンコーダ・デコーダ方式の全体像（典型的な順序）: トークン化 → 埋め込み + 位置符号化 → エンコーダスタック（自己注意＋FFN）→ デコーダスタック（マスク付き自己注意 → エンコーダ出力へのクロス注意 → FFN）→ 出力線形変換 → softmax → 損失（教師あり訓練では正解トークンで教師強制: teacher forcing）。
  - 重要: デコーダのクロスアテンション部分が「ソース全体を参照」する箇所。
- decoder-only（自回帰言語モデル）の全体像: トークン化 → 埋め込み + 位置符号化 → デコーダスタック（ただし各レイヤの自己注意は因果マスクで未来を遮断）→ 出力線形 → softmax → 損失（次トークン予測）。
  - 重要: 因果マスクが常に「未来のトークンを見せない」ことを保証する。

現実の大規模モデルとの接続と一般化に関する注意
実運用のモデルはここで示した単純例より遥かに複雑だ。層数（深さ）、ヘッド数、埋め込み次元、学習される位置符号化（絶対位置、相対位置、RoPE 等）、正規化（LayerNorm, RMSNorm 等）、効率化（FlashAttention など）や巨大語彙の扱い（サブワード分割）などの違いがある。ただし基本的な情報経路（クロスアテンションでソース全体を参照できるか、因果マスクで未来を遮断するか）は原理的に同じである。現代の変種（位置表現の方式や注意の近似アルゴリズム）は多様だが、それらを全て「いつもそうだ」と一般化するのは誤りである（採用状況は論文や実装に依る）。

よくある誤解の訂正
- 「attention weight が高い = モデルがそのトークンを人間的に注目している証拠」ではない。重みは最終出力に対する線形結合の係数であり、内部のスケーリングや後続の非線形や残差接続と組み合わさるため、単独で「説明」にはならない。
- 「token = 単語」ではない。多くのモデルはサブワード単位（Byte-Pair Encoding, SentencePiece 等）でトークン化するため、一つの日本語の語や助詞が複数トークンに分割される場合がある。
- 「GPT 型＝古典 Transformer の改良版」ではない。GPT 系はアーキテクチャ上は decoder-only（因果自己注意を基本とする）という明確な設計決定を取っている。原著の encoder–decoder 構成とは目的（与えられた入力を全体参照して出力を作るか、逐次的に自己生成するか）が異なる。

章末まとめ（読者が説明できること）
- encoder–decoder と decoder-only が情報をどのように取り込むか（どこまで参照できるか）を、数式と具体的な数値例で説明できる。
- Q, K, V, S, A, O の各記号が何を表し、どの軸が「クエリ数」「キー数」「次元」を意味するかを普通の言葉で説明できる。
- 因果マスクがどの段階で作用し、どのようにスコアを変えるかを説明できる。
