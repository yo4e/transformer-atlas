# Scaling と softmax

**問題（冒頭） — 任意の実数を「正の比率」に変えたい**

実装や設計の場面で、いくつかの実数（たとえば 2, 1, -1）の集合を扱っているとします。これらは「スコア」と呼びます。スコアは負になったり、幅（尺度）が大きく変わったり、順序はあるが大きさがそのまま比率に変わるわけではありません。私たちが欲しいのは「各スコアに基づいて正の数の比率に直して合計が1になるような重み（＝比率）」です。こうして得た正の比率を使えば、別のベクトル（値：value）をこれらの比率で混ぜ合わせることができます。なぜこの仕組みが必要かを具体的に考えると、たとえばある位置（質問）に対して複数の候補（文脈中の他の位置）をどれだけ「混ぜる」かを決める場面で、負やゼロを持たない、合計が1の重みが便利だからです。

問題点を列挙すると次のとおりです。
- スコアは負になることがある（例：-1）。
- スコアの尺度が大きくなると計算が不安定になることがある。
- スコアから直接比率に変換するには、順序を保ちながら全てを正にする必要がある。
- 温度パラメータ（temperature）の導入によって分布の「平坦さ」や「鋭さ」を調整したい場合がある。

以降では、上記問題を解くための具体的な道具（式、直感、実装例）を丁寧に示します。まずは「直感」と「注意点」を説明し、次に数式、具体例（scores = [2,1,-1]）の詳細な計算、Pythonコード、Transformer内部での位置づけとよくある誤解の訂正へ進みます。

**直感（有用だが文字どおりではない点）**

- 有用な直感
  - 大きいスコアは「より多く混ぜるべき」ことを示す。小さいスコアは「あまり混ぜない」。
  - 負のスコアも扱える。指数関数（exp）を使えば全て正にできる。
  - 最終的に合計が1になるため、確率のように重み付けして値を線形に混ぜられる。

- 文字どおり受け取ってはいけない点
  - 「最も高いスコアが正しく注目している」という直感は必ずしも正しくない。attention weight（後述）はモデルの内部値であり、人間の注目の完全な証拠ではない。
  - スコア同士の差が小さいと、比率はかなり均等になる。逆に差が大きいと一つが突出するが、それが意味的に正しいとは限らない。
  - 数値例は教材用の小さなスケールで示す。実際の大規模モデル内部の値とは異なることを明示します。

**数値オブジェクトと役割を区別する**

まず用語をはっきりさせます。
- スコア（scores）：モデルの内部で計算される実数。たとえばクエリとキーの内積（点積）の結果。通常は学習によって間接的に変わるが、スコア自体は「入力や中間活性」。
- 学習パラメータ（parameters）：重み行列やバイアスなど、学習によって更新される固定値。スコアはこれらと入力の組合せから計算される。
- 値（values）：重みを掛け合わせて最終的に混ぜ合わせるベクトル。スコア→重み→値の混合で出力が作られる。
- 活性（activations）：ネットワーク内部で一時的に得られる数値。スコアや値は活性の一種。

この区別は、後で「何が学習され、何がその場で計算されるか」を理解するために重要です。

**基本的な式（言葉に戻す）**

私たちが使う操作は次の二段階です。

1. スコアを指数関数で正に変換する：
   - 各スコア s_i に対して exp(s_i) を計算する。exp は指数関数で、どんな実数でも正に変える。

2. それらを合計で割って正規化する：
   - p_i = exp(s_i) / sum_j exp(s_j) とする。これにより p_i は正で、全て足すと1になる。p は比率（確率風の重み）で、値ベクトルを線形結合するために使える。

言葉で戻すと、「まず各スコアの『勢い』を指数で測り、その勢いを全体の勢いで割って相対的な比率にする」操作です。ここで使う exp の性質は、単調増加（より大きな s に対してより大きな exp(s)）であるため、順序は保たれますが差の扱われ方は非線形です。

注意：スコアに定数 c を足しても結果は変わりません。理由は exp(s_i + c) / sum_j exp(s_j + c) = exp(s_i) exp(c) / (exp(c) sum_j exp(s_j)) = exp(s_i) / sum_j exp(s_j)。この性質は数値計算で最大値を引いてオーバーフローを防ぐときに使います（後述）。

この操作には「softmax」という名前が付いていますが、ここでは名前を先に出さず仕組みを説明しました。以降では便宜上「正規化指数」と呼びます。

**具体例：scores = [2, 1, -1] を実際に計算する**

まず生のスコアを取り、指数にします。教材用の小数値を用いますが、これらは実際の大規模モデル内部の精確な値ではないことを明記します。

- スコア s = [2, 1, -1]

指数を取ると（exp(2) ≈ 7.389056、exp(1) ≈ 2.718282、exp(-1) ≈ 0.367879）：
- exp(s) ≈ [7.389056, 2.718282, 0.367879]

合計は sum ≈ 7.389056 + 2.718282 + 0.367879 = 10.475217 ≈ 10.48

正規化して比率にすると：
- p_1 = 7.389056 / 10.475217 ≈ 0.705
- p_2 = 2.718282 / 10.475217 ≈ 0.2595
- p_3 = 0.367879 / 10.475217 ≈ 0.0351

したがって、最初の要素が約70.5%、次が約25.95%、最後が約3.51%の比率になります。これらの重みを使えば、値ベクトル v_1, v_2, v_3 の線形結合 p_1 v_1 + p_2 v_2 + p_3 v_3 を取ることで「値の混合」が得られます。

（繰り返し）この数値は教材向けの小さな例です。実モデルの内部状態のスケールや精度は異なります。

**temperature（温度）の導入と比較：tau = 0.5 と tau = 2**

温度はスコアに対するスケーリング係数です。通常はスコアを温度で割る（あるいは逆に掛ける実装もあるので表記を確認する）ことで導入します。ここでは一般的な定義として、logits = scores / τ とし、exp(logits) を取ります。τ が小さいほど分布は尖り（シャープ）大きいほど平坦になります。

同じ元スコアで τ = 0.5 と τ = 2 を比較します。

1) τ = 0.5 の場合：
- logits = scores / 0.5 = [4, 2, -2]
- exp(logits) ≈ [exp(4)=54.59815, exp(2)=7.389056, exp(-2)=0.135335]
- 合計 ≈ 54.59815 + 7.389056 + 0.135335 = 62.12254
- 正規化：
  - p1 ≈ 54.59815 / 62.12254 ≈ 0.879
  - p2 ≈ 7.389056 / 62.12254 ≈ 0.119
  - p3 ≈ 0.135335 / 62.12254 ≈ 0.00218

2) τ = 2 の場合：
- logits = scores / 2 = [1, 0.5, -0.5]
- exp(logits) ≈ [2.718282, 1.648721, 0.606531]
- 合計 ≈ 2.718282 + 1.648721 + 0.606531 = 4.973534
- 正規化：
  - p1 ≈ 2.718282 / 4.973534 ≈ 0.5465
  - p2 ≈ 1.648721 / 4.973534 ≈ 0.3316
  - p3 ≈ 0.606531 / 4.973534 ≈ 0.1220

比較すると、τ=0.5 で最初のスコアがほとんどすべてを占める（非常に尖った分布）一方、τ=2 では分布はかなり平坦になり第三要素の重みも無視できない大きさになります。温度は「どれだけ差を拡大するか（τ<1）」あるいは「差を和らげるか（τ>1）」の役割を果たします。

**数学的に重要な性質（順序保存・差のみが重要・シフト不変）**

- 順序保存：exp は単調増加関数なので、s_i > s_j ならば exp(s_i) > exp(s_j)。したがって正規化後の p_i > p_j も成り立つ。つまり元のスコアの相対順位は保たれる。
- 差のみが重要：スコア全体に同じ定数を足しても比率は変わらない（上で示した性質）。
- 温度は差に対する感度を変える：scores ↦ scores/τ は差を 1/τ 倍する。τ<1 で差が拡大、τ>1 で差が縮小する。

ただし、順序が保たれても「どれだけ」選ばれるかは指数の非線形で大きく変わるため、順序保存＝意味的に同価値ではない点に注意が必要です。

**数式（行列を普通の言葉に戻す）**

Transformer の注意機構における基本式を言葉で書くと次の通りです。

- 各入力位置には「クエリ（Q）」「キー（K）」「値（V）」があり、これらは入力に線形変換（学習される重み行列）を適用して得られる活性です。
- あるクエリ q と全てのキー k_j の間のスコアは q·k_j（内積）として計算される。
- そのクエリに対する重みは各スコアを正規化指数（softmax）で変換したものです。
- 最後にそのクエリの出力は、これら重み付きの値ベクトル v_j の和になります。

行列記法で簡潔に書くと（ここは読者のために言葉を添えます）：
- Q は複数のクエリを縦に並べた集合（行列）、K は複数のキーを縦に並べた集合、V は複数の値を縦に並べた集合。
- スコア行列 S = Q K^T（ここで各行はあるクエリが全てのキーと取った内積の集合）
- スケーリング（原著では d_k の平方根で割る）：S' = S / sqrt(d_k)。ここで d_k はキー・クエリの次元。これは次元が増えると内積が大きくなりすぎることを防ぐ経験的トリックです。
- 重み行列 A = softmax(S') （softmax は各行ごとに指数→正規化を行う操作）
- 出力は A V（行列積で、各クエリが値ベクトルの重み付き和をとる）

ここで「行列積」を普通の言葉で説明すると、あるクエリに対応する行は、そのクエリが値ベクトルの各要素にどれだけ重みを付けて和を取るかを示しています。

重要：original Transformer（Vaswani et al. 2017）ではスコアのスケーリングに sqrt(d_k) を使っています。これは理論的に内積の分散が次元で増えるために生じる数値的な飽和を防ぐための実用的措置です。

**数値的安定性の実装トリック**

実装では exp を直に計算すると大きな正のスコアでオーバーフローする可能性があるため、各行で最大値を引く手法を使います。すなわち p_i = exp(s_i - max(s)) / sum_j exp(s_j - max(s))。これは上で述べたシフト不変性に基づく正当な操作で、数値的に安全です。

**透明な短い Python コード（変数名は数式と対応）**

以下は numpy を用いた簡潔な実装例です。変数名は上で使ったものに合わせています。

```python
import numpy as np

scores = np.array([2.0, 1.0, -1.0])  # s

def softmax(scores, tau=1.0):
    # 温度 tau を用いてスコアをスケーリング
    logits = scores / tau
    # 数値安定性のため最大値を引く
    logits = logits - np.max(logits)
    exps = np.exp(logits)
    probs = exps / np.sum(exps)
    return probs

# 元の温度
probs_default = softmax(scores, tau=1.0)
# 温度 0.5 と 2.0
probs_tau_half = softmax(scores, tau=0.5)
probs_tau_two = softmax(scores, tau=2.0)

print("tau=1.0:", probs_default)       # ≈ [0.705, 0.2595, 0.0351]
print("tau=0.5:", probs_tau_half)      # ≈ [0.879, 0.119, 0.00218]
print("tau=2.0:", probs_tau_two)       # ≈ [0.5465, 0.3316, 0.1220]
```

このコードはスコアを受け取り、温度 tau により鋭さを調節して確率風の重みを返します。実際の Transformer 実装では「各クエリごとに」この softmax を行い、その重みで値行列を混ぜます。

**full Transformer 内での前後処理と大規模モデルとの接続**

局所的に見れば、softmax（正規化指数）は注意機構のスコア→重みの部分で現れます。より広い文脈では次のような流れになります。

- 入力のトークン（正確にはトークンと呼ばれる整数インデックスにエンコーディングされた単位。token は単語と同義ではありません）を埋め込み（embedding）に変換する。
- さらに位置情報を加え、線形層で Q,K,V に投影する（これらの重みは学習パラメータ）。
- Q と K の内積からスコアを計算し、sqrt(d_k) で割ってスケールし、softmax を使って重みを得る。
- 重みで V を混ぜる（行列積 AV）して次の層に渡す。
- これがマルチヘッド注意（複数の独立した Q,K,V を並列で計算し、最後に結合する）で行われ、残差接続や正規化が加わる。

大規模モデルでは同じ原理が当てはまりますが、スケールが大きくなると最適なハイパーパラメータ（学習率、初期化、正規化方法など）は異なり、実装の高速化（たとえば FlashAttention 系の工夫）や数値安定化が不可欠になります。ここで示した小さい数値例はあくまで動作理解のためのもので、実際のモデルでの値の分布や振る舞いは異なる点に注意してください。

**よくある誤解と訂正**

- 誤解：attention weight が「モデルが人間のように注目している」証拠である。
  - 訂正：attention weight は内部的な重みであって、必ずしも人間の解釈と一致しない。解析に有益なヒントを与えることはあるが、行動の唯一の説明や証拠とはならない。

- 誤解：softmax の出力は厳密な確率であり、確率的な意味を持つ。
  - 訂正：数学的には正規化された正の数であり確率分布の形を取るが、ドメイン固有の「イベント確率」を意味するとは限らない。あくまでモデルの内部重み。

- 誤解：token は単語と同義である。
  - 訂正：token はモデルの語彙単位（サブワードや文字など）で、単語より細かい場合が多い。トークンと単語は一致しないことがある。

- 誤解：softmax の入力スコア自体が直接学習されるパラメータである。
  - 訂正：スコアは宿主となる重み行列や入力の内積から計算される活性であって、通常は間接的に学習される（重みが更新されることでスコアが変わる）。スコアそのものは学習パラメータではない点を区別する。

最後に、original Transformer（Vaswani et al., 2017）と GPT 型 decoder-only の細部を混同しないように注意してください。本節で説明したスコア→softmax→重み→値の流れは両者で同じ核を成しますが、アーキテクチャ全体のデザインやマスクの有無、位置エンコーディングの扱いなどは異なります。

**まとめ：この章で説明できること（チェックリスト）**

- 任意の実数から正の比率を作る基本的操作（指数と正規化）を説明できる。
- 負のスコアやスケールの問題を指数と正規化でどう扱うか説明できる。
- temperature が分布の平坦さ/鋭さに与える効果を定量的に説明できる（τ<1 → 鋭く、τ>1 → 平坦）。
- スコア、学習パラメータ、値・活性の違いを区別して説明できる。
- 実装上の数値安定化（最大値を引く）を説明し、短いコードを書ける。
- Transformer 内でのこの処理の位置と、一般的な誤解（attention の解釈など）を説明できる。

**確認問題（自分で解いてみてください）**

1. スコア s = [0.5, 0.5, 0.5, 0.5] に対して温度 τ を 0.1, 1, 10 に変えたとき、得られる比率 p はどのようになるか説明し、各ケースの直感的な意味を述べよ。

2. あるクエリ q と 3 個のキー k1, k2, k3 があり、それぞれの内積（スコア）が [3, 1, 1] であった。ここでスケーリング因子 sqrt(d_k) を用いずに softmax を計算した場合と、sqrt(d_k)=2 で割ってから softmax を計算した場合で、得られる出力（重み）とその意味上の違いを定性的に説明せよ。数値計算も行って比べよ。
