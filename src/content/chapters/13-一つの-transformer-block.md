# 一つの Transformer block

問題提起（先に答えを言わないで）

私たちは、並んだ記号列を扱う小さな計算単位を設計しようとしています。この単位は「各位置（トークン）が自分の内部表現を持ちつつ、他の位置の情報を取り込み、非線形な変換で表現を豊かにし、同時に学習を安定させる」ことを同時に満たす必要があります。具体的には次の課題があります。

- 各位置ごとの値が大きく変化すると学習が不安定になる。各特徴のスケールを揃える仕組みが要る。
- ある位置が他の位置から情報を取り込むとき、どの情報をどれだけ取り込むかを決める柔軟なルールが要る。
- 情報を取り込んだ後、元の位置情報を完全に上書きしてしまうと学習が遅くなる。元の情報を残す「近道」が必要だが、それは単純にコピーするだけよりもうまく機能させたい。
- 各位置での非線形変換（複雑さを与える層）は必要だが、それも独立に働くべきであり、入力列の長さに依存しない方が扱いやすい。

この章では、上の要請を満たすための標準的な組合せ（正規化、並列／順次の文脈集約、残差接続、位置別の小さな非線形ネットワーク）を順に説明し、それらを合成した「ブロック」が内部でどのように情報を流すかを具体的に追います。用語は後で名前を付けますが、まず「何が必要か」を押さえます。

直感と注意点（直感が文字どおりではない点）

直感的にはこう考えます。まず各位置のベクトルを「尺度を揃える」箱に入れてから、箱の中身で他の位置に目を向け（重み付けて合算し）、合算結果を元の位置に戻して「足し算」で元と混ぜる。最後に位置ごとの非線形回路で情報を入れ替える――これがブロックの流れです。

ただし次の点に注意してください。

- 「目を向ける」というのは、人間の注意と同義ではありません。計算機が内部数値を使って重みを決める操作であり、言語的な注目をそのまま示す証拠ではありません。
- 正規化は「入力を平均0、分散1にする」と簡単に言えますが、実際は学習でスケーリングと平行移動（ゲインとバイアス）を許可して微調整します。これにより単純化し過ぎては説明できない微妙な効果が生じます。
- 本章で使う小さな数値例は実際の大規模モデルの中間値ではありません。教育用の縮尺モデルです。

数値オブジェクトの区別（parameters と activations）

ここで扱う「数」は二種類に分けて扱います。学習される固定の数（パラメータ）と、入力や計算過程で変化する動的な数（活性化、activation）です。例えば重み行列 W やバイアス b はパラメータで、入力ベクトル x に W をかけて得られる xW は活性化です。式やコードではこの区別を守ります。

簡潔な数式（使う記号と軸の意味を普通の言葉で）

以下で順番に示す二つの設計を区別します。元の論文で採られた「後に正規化を入れる」構成（post-normalization、原著の Add & Norm の形）と、近年よく使われる「先に正規化する」構成（pre-normalization）。両者は見た目が似ていますが情報の流れが変わり、学習挙動に差が出ます。混同しないでください。

共通の記号（普通の言葉で説明）：
- x : 入力の列（行がトークン、列が特徴）。形は (T, d) — T はトークン数、d は特徴次元。
- LN(z) : 入力ベクトル z の各行ごとに平均を引き分散で割る正規化に、学習されるスケール（γ）とシフト（β）を掛けたもの。出力の形は入力と同じ。
- MHA(L) : 「クエリ」「キー」「バリュー」行列を作り、注意重みでバリューを加重平均して返す操作。入力 L（形 (T,d)）から同じ形 (T,d) を返す。単一ヘッドの簡略表現として説明する。
  - Q = L W_Q, K = L W_K, V = L W_V （W_* は学習パラメータ、形は (d,d_k) や (d,d_v)）
  - scores = Q K^T / sqrt(d_k) （ここで各行iのscoresがトークンiの「誰を見るか」の元になる）
  - A = softmax(scores, axis=keys) @ V  （softmaxは行ごとにキー軸で確率化）
- FF(z) : 位置ごとに独立に作用する小さな非線形ネット。一般に FF(z) = W_2 (act(W_1 z + b_1)) + b_2。各行に同じパラメータを適用するため、列（特徴）方向の変換であり、トークン間で重み共有される。
- + : 残差（shortcut）足し算。形を保ったまま行う。

原著（post-norm）の一層（簡略式）
1) s = x + MHA(x)
2) y = LN(s)
3) t = y + FF(y)
4) output = LN(t)

ここで LN は MHA と FF の後に入ります。元の論文では Add & Norm がサブレイヤごとの標準でした。

pre-norm の一層（よく使われる変種、教育用に追跡する情報経路）
1) a = x + MHA(LN(x))
2) b = a + FF(LN(a))
3) output = b

この流れは「正規化→サブレイヤ→残差」という順で繰り返します。情報の経路（activation がどこを通るか）を追いやすく、深いスタックで学習が安定することが多いです。

行列積・軸の意味（普通の言葉）
- xW は「各トークンの行ベクトルに同じ線形変換 W を適用する」操作。W の列数が入力特徴数、行数が出力特徴数です。
- Q K^T は「各クエリ行と各キー行の内積を並べた行列」で、行はクエリ（出力を決めたいトークン）、列は候補のキー（参照先トークン）を表します。softmax は「列方向（参照先）」で確率にし、確率で V を混ぜて最終的な加重平均を得ます。

具体例（数を実際に計算する）

教育用の非常に小さな例で具体的に計算を追います。二つのトークンがあり、それぞれのベクトル表現が [2, 2] とします（x を二行、二列の行列で表す）。この例では正規化の学習パラメータは γ=[1,1], β=[0,0] とし、LayerNorm は単純に平均を引いた後に分散で割る形で実行します（分母には小さな eps を加えます）。また、ここではサブレイヤ（注意とFF）の出力を既に小さな数で計算してあるものとして、残差で足し戻す過程を示します。これらの小さな出力は教育用の値で、実モデルの内部状態ではないことを明示します。

初期入力 x:
| トークン | 特徴0 | 特徴1 |
|---:|---:|---:|
| 0 | 2.0 | 2.0 |
| 1 | 2.0 | 2.0 |

Step 1 — LN(x)
各行の平均は 2.0、分散は 0 → 正規化結果は (x - 2)/sqrt(0+eps) ≈ [0,0]（gamma=1, beta=0 のため）。
LN(x) = [[0,0],[0,0]]

Step 2 — Attention の出力（既出の小さな値を使う）
教育用に次のように与える：
attn_out = [[ 0.2, -0.4],
            [ 0.1,  0.3]]
（これは LN(x) を用いた注意計算の結果だとします。実際の計算は Q,K,V と softmax を含みますが、ここでは数値の追跡に集中します。）

残差で足し戻す：
a = x + attn_out =
[[2.0+0.2, 2.0-0.4],
 [2.0+0.1, 2.0+0.3]] =
[[2.2, 1.6],
 [2.1, 2.3]]

Step 3 — LN(a)
各行ごとに平均と標準偏差を計算する。
- 行0: mean = (2.2+1.6)/2 = 1.9, deviations = [0.3, -0.3], var = (0.09+0.09)/2 = 0.09, std ≈ 0.3
  LN(row0) = [(2.2-1.9)/0.3, (1.6-1.9)/0.3] = [1.0, -1.0]
- 行1: mean = (2.1+2.3)/2 = 2.2, deviations = [-0.1, 0.1], var = (0.01+0.01)/2 = 0.01, std ≈ 0.1
  LN(row1) = [ -1.0, 1.0 ]

LN(a) = [[ 1.0, -1.0],
         [-1.0,  1.0]]

Step 4 — FF の出力（既出の小さな値）
教育用に次を与える（各行は位置別の FF 出力と考える）：
ff_out = [[ 0.5, 0.5],
          [-0.2, 0.1]]

残差で足し戻す：
b = a + ff_out =
[[2.2+0.5, 1.6+0.5],
 [2.1-0.2, 2.3+0.1]] =
[[2.7, 2.1],
 [1.9, 2.4]]

これがこのブロックの出力（pre-norm の場合）です。表にすると次の通りです。

| ステップ | トークン0 | トークン1 |
|---|---:|---:|
| 入力 x | [2.0, 2.0] | [2.0, 2.0] |
| LN(x) | [0.0, 0.0] | [0.0, 0.0] |
| attn_out | [0.2, -0.4] | [0.1, 0.3] |
| x + attn_out = a | [2.2, 1.6] | [2.1, 2.3] |
| LN(a) | [1.0, -1.0] | [-1.0, 1.0] |
| ff_out | [0.5, 0.5] | [-0.2, 0.1] |
| a + ff_out = b (出力) | [2.7, 2.1] | [1.9, 2.4] |

上の数は教育用の縮尺値です。実際のモデルの中間表現とはスケールも分布も大きく異なります。

透明な短い Python（数式変数名と対応させる）
```python
import numpy as np

eps = 1e-5
x = np.array([[2.0, 2.0],
              [2.0, 2.0]])   # shape (T=2, d=2)

def layer_norm_rows(z, gamma=np.ones(2), beta=np.zeros(2)):
    mean = z.mean(axis=1, keepdims=True)
    var = z.var(axis=1, keepdims=True)
    return ((z - mean) / np.sqrt(var + eps)) * gamma + beta

attn_out = np.array([[ 0.2, -0.4],
                     [ 0.1,  0.3]])
ff_out   = np.array([[ 0.5,  0.5],
                     [-0.2,  0.1]])

# pre-norm のブロック
ln_x = layer_norm_rows(x)            # LN(x)
a = x + attn_out                     # x + MHA(LN(x))
ln_a = layer_norm_rows(a)            # LN(a)
b = a + ff_out                       # a + FF(LN(a))
output = b

print("ln_x:\n", ln_x)
print("a:\n", a)
print("ln_a:\n", ln_a)
print("output:\n", output)
```

全体の文脈とよくある誤解の訂正

- この一層はトランスフォーマの「ブロック」であり、実際のモデルはこれを縦に多層に積みます。各層は同じ形の入力・出力を保つため、残差で足し合わせられるように設計されています。
- 元の Transformer（Vaswani et al., 2017）はエンコーダ・デコーダの構造を持ち、原著は「後に正規化（post-norm）」のスタイルで記述されました。一方、GPT系のようなデコーダのみのモデルや多くの近年の実装では「先に正規化（pre-norm）」を使うことが多いですが、これは設計上の選択で、どちらが正しいという話ではありません。ここで示した教育用の情報経路は pre-norm を追跡したものです。
- 「トークン」は必ずしも単語ではありません。実装ではサブワードやバイトペア符号化（BPE）などが使われるため、「トークン = 単語」と安直に同値視してはいけません。
- Attention の重み（softmax の出力）を人間の注目の証拠と解釈するのは危険です。重みは特定の数値的最適化の結果であり、解釈には注意が必要です。
- LayerNorm はバッチ正規化とは異なります。位置ごとの平均・分散を使うため、バッチサイズの有無に左右されにくいという利点があります。

読者が説明できるようになること（要点）

- このブロックがどのように「正規化 → 注意（コンテキスト取り込み） → 残差で足し戻す → 正規化 → 位置別FF → 残差で足し戻す」という情報経路を持ち、各段階の目的が何かを説明できます。
- パラメータ（重み行列、バイアス、LN の γ/β）と活性化（入力 x、Q, K, V、attention の出力、FF の中間出力）を区別して説明できます。
- pre-norm と post-norm の違いを、式と情報の流れで示し、それぞれの特徴（学習安定性や実装上の注意）を述べられます。

確認問題（解答は本章の理解チェック用）
1) pre-norm の一層において、もし初期入力 x の全行が同じ値 [c, c, ..., c] であれば、LN(x) はどうなりますか？ その状態で attention の Q,K の内積や softmax の挙動にどんな一般的な影響がありますか。
2) post-norm の構成で深いネットワークを積み重ねたときに勾配が消失しやすい（あるいは学習が不安定になる）理由を、残差と正規化の位置の観点から説明してください。
