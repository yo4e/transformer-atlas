# Position: 順序を入れる

問題提起 — なぜ「位置情報」を渡す必要があるのか
自己注意（self-attention）は、入力列の各要素が並び替えられても同じ「計算のやり方」をする性質があります。すなわち、注意機構そのものは入力の順序を直接参照せず、各要素の中身（ベクトル表現）どうしの類似度に基づいて出力を作ります。これは長所でもありますが、語順や時系列の順序に依存する言語や信号処理では問題になります。たとえば同じ単語（あるいは同じ token）の列が順序だけ変わったとき、何が変わったかをモデルが識別できないと、正しい文理解や生成は難しくなります。

具体的な直観をまず示すと、自己注意は「誰が誰に似ているか」を計算しているにすぎません。2つの要素がまったく同一のベクトルを持っていれば、自己注意はそれらを区別できません。したがって、要素ごとに「ここは1番目」「ここは2番目」と区別するための信号（位置情報）をベクトル空間に注入する必要があります。ここで注意してほしいのは、位置情報を足す（または適用する）ことは「人間が文字で順番を見ている」ような単純な操作そのものではなく、内積や線形変換を通じて注意のスコアに影響を与えるための数学的な工夫だ、という点です。

有用な直感とその限界
位置情報の注入には主に二通りの直感が役立ちます。

- 直感A（加算型）: 各 token の埋め込みに「位置ベクトル」をそのまま足してやる。こうすると同じ語でも位置が違えば表現が変わるので注意は区別できる。
- 直感B（回転型）: token の表現自体を位置に応じて回転させる（あるいは位相をずらす）。これにより、内積（相互類似性）が位置差に敏感になる。

どちらも「位置を入れる」ための方法ですが、本質的には異なる働きをします。加算は入力空間に絶対位置を直接埋め込み、回転（RoPE）は注意内部の類似度計算（主に Query と Key の内積）に位相差として位置を組み込みます。どちらがよいかは応用や実装上の理由で選ばれます。ここで重要なのは、直観を字義どおりに受け取ってはいけない点です。たとえば「加算すれば必ず順序がわかる」とは限らず、重みや線形変換・正規化・残差結合など他の構成要素との相互作用で効果が変わります。

学習パラメータと計算で得られる活性化（activation）を区別する
実際の Transformer で扱うオブジェクトは三種類に分けて考えると分かりやすいです。

- 学習パラメータ（学習される定数）: トークン埋め込み行列 E、自己注意の重み行列 W_Q, W_K, W_V、FFN の重みなど。
- 固定だが設計による定数: 元々の論文で用いられた「sin/cos による位置エンコーディング」は学習されない固定関数です。
- 活性化（入力から順に計算される値）: 埋め込みに位置を足した結果のベクトル、attention の Q, K, V、ソフトマックス後の注意重み、各層の出力など。

以降の数式や例では、この区別を明示します。なお、本章で使う小さな数値例は教材目的の単純化された数であり、実際の大規模モデルの内部状態の大きさや分布を反映しているわけではないことを明言しておきます。

まずは簡単な数式で自己注意と位置注入を整理する
自己注意の最小構成（1ヘッド）を表す式を示します。入力列は長さ N、モデルの内部次元を d とします。入力トークン i の埋め込み（活性化）は x_i ∈ R^d です。学習パラメータの注意用行列は W_Q, W_K, W_V ∈ R^{d×d_k}（ここでは d_k = d に揃えて簡単化しても良い）とします。

- Query, Key, Value の計算:
  Q = X W_Q, つまり Q の i 行は q_i = x_i W_Q（x_i を行ベクトルと見た場合）
  K = X W_K, つまり k_j = x_j W_K
  V = X W_V

- スコアと重み:
  スコア行列 S の要素は s_{ij} = q_i · k_j / sqrt(d_k)
  注意重みは各行にソフトマックスをかけて a_{i:} = softmax(s_{i:})
  出力は o_i = Σ_j a_{ij} v_j

ここで X は入力列を縦に並べた行列、Q, K, V も同様に縦に並べた行列です。行列積 X W_Q は「各行 x_i に同じ線形変換 W_Q を適用して得る行列」と普通に読んでください。

重要な観察: もしすべての x_i が同じベクトルであれば、Q の各行は等しく、K も等しく、したがって S の各行も等しくなり、softmax の結果は各位置について同じ分布になります。これは「自己注意単体は順序を区別しない」ことの数学的要約です。だから位置情報をどこかで入れてやる必要があるのです。

具体例1 — 二つの token embedding [1,0] に位置 vector [0,1] と [1,0] を足す
まずはもっとも直感的な加算型の単純な手計算例を提示します。これは教材用の単純化された数値であり、実機の値ではありません。記号と役割を再掲します。

- トークン埋め込み（学習パラメータから取り出した活性化と考える）: e_1 = e_2 = [1, 0] ∈ R^2
- 位置ベクトル（ここでは説明のために固定の 2 次元ベクトルを使う）: p_1 = [0, 1], p_2 = [1, 0]
- 入力活性化: x_i = e_i + p_i
  よって x_1 = [1, 1], x_2 = [2, 0]

注意層で使う重みを簡単にするため、W_Q = W_K = I（2×2 の単位行列）と仮定します。これは学習パラメータが単位変換であるという単純化です（実際は学習されます）。

計算:
- q_1 = x_1 W_Q = [1, 1], q_2 = [2, 0]
- k_1 = x_1 W_K = [1, 1], k_2 = [2, 0]
- 内積 s_{ij} = q_i · k_j（ここでは sqrt(d_k) で割る係数は省略しても直感は同じですが、数値は影響します。簡便のため今回は割っていません。実装では通常 sqrt(d_k) でスケーリングします）

s_{11} = [1,1]·[1,1] = 2
s_{12} = [1,1]·[2,0] = 2
s_{21} = [2,0]·[1,1] = 2
s_{22} = [2,0]·[2,0] = 4

スコア行列 S = [[2, 2], [2, 4]]

各行に softmax を適用（行ごとに正規化）すると：

- 行1（クエリが位置1のとき）: softmax([2,2]) = [0.5, 0.5]
- 行2: softmax([2,4]) = softmax([-2,0]) = [e^{-2}/(1+e^{-2}), 1/(1+e^{-2})] ≈ [0.1192, 0.8808]

よって、位置1のクエリは両方のキーに同じ程度注目し、位置2のクエリは主に位置2の値に注目するようになります。これが位置ベクトルを足すことで「順序を区別できる」最も単純な例です。

対照実験（位置を足さない場合）:
もし p_1 = p_2 = [0,0] なら x_1 = x_2 = [1,0]。同じ単位行列仮定下で Q,K の各行は等しく、スコア行列はすべて同じ値（例: 1）となり、softmax の各行は [0.5,0.5] に固定されます。順序情報が失われているのが分かります。

具体例2 — 2次元ベクトル [1,0] を位置に応じて 90 度回す RoPE の最小例
RoPE（Rotary Positional Embedding）では位置を「加える」のではなく、Query と Key のベクトルを位置に応じた回転行列で回すことで、内積に位相差（＝位置差）を直接組み込みます。ここでは d = 2 の最小ペアで説明します。

回転行列 R(φ) = [[cos φ, -sin φ], [sin φ, cos φ]] を用い、位置 p に対して角度 φ = p · θ（θ は周波数に相当する定数、ここでは位置差 1 で 90° 回すため θ = π/2 とする）とします。

埋め込み v = [1,0] を位置 0 と位置 1 に置くと、
- pos = 0: R(0) v = [1, 0]
- pos = 1: R(π/2) v = [[0,-1],[1,0]]·[1,0] = [0,1]

RoPE は本来 Q と K に同じ回転を適用する（V は回転しないことが多い）ため、簡単化して W_Q = W_K = I、Q と K に対して上の回転を適用します。すると:

- q_0 = [1,0], q_1 = [0,1]
- k_0 = [1,0], k_1 = [0,1]

内積行列 S は
s_{00} = 1, s_{01} = 0
s_{10} = 0, s_{11} = 1

S = [[1,0],[0,1]]

softmax 行ごとに:
- 行0: softmax([1,0]) ≈ [0.7311, 0.2689]
- 行1: softmax([0,1]) ≈ [0.2689, 0.7311]

ここでは回転のために相互の内積が位置差に敏感になり、相対位置によって attention の分布が変化することが示されます。RoPE の利点は、回転は（ある条件下で）相対的な位置差を表現しやすく、学習パラメータを追加しなくても位置の作用を自然に組み込める点にあります。

数式の意味を普通の言葉に戻す（各記号の説明）
- N: 入力の長さ（トークン数）
- d: モデルの埋め込み次元（各トークンが持つベクトル長）
- x_i ∈ R^d: トークン i の入力ベクトル（埋め込みと位置情報が合わさった活性化）
- W_Q, W_K, W_V ∈ R^{d×d}: それぞれ Query, Key, Value を作る学習可能な行列
- q_i = x_i W_Q: トークン i に対する Query ベクトル（これは活性化）
- k_j = x_j W_K: トークン j に対する Key ベクトル
- s_{ij} = q_i · k_j / sqrt(d_k): Query i と Key j の類似度（内積をスケール）
- a_{ij} = softmax_j(s_{ij}): Query i が Key j に割り当てる重み（その行の正規化）
- o_i = Σ_j a_{ij} v_j: Query i に対する attention 出力（Value の加重和）

ここで「加算型位置エンコーディング」は x_i = e_i + p_i と定義することが多く、p_i は固定関数（sin/cos）で与えられたり学習可能な埋め込みとしてパラメータ化されたりします。一方「RoPE」は、x_i をそのまま使うか、あるいは Q,K を内部で回転させて q_i = R(p_i)(x_i W_Q) とするような操作で、位置を乗法的（線形変換として）に適用します。

透明な短い Python コード（NumPy）で動かしてみる
以下は上の二つの例を忠実に再現する最小コードです。変数名は式と対応しています。実際のモデルでは d はもっと大きく、W_Q などは学習されます。

```python
import numpy as np
from math import pi, cos, sin, exp

def softmax_rowwise(mat):
    # 行ごと softmax
    e = np.exp(mat - np.max(mat, axis=1, keepdims=True))
    return e / e.sum(axis=1, keepdims=True)

e1 = np.array([1., 0.])  # token embedding
e2 = np.array([1., 0.])
p1 = np.array([0., 1.])  # position vectors（教材用の任意のベクトル）
p2 = np.array([1., 0.])
x1 = e1 + p1  # [1,1]
x2 = e2 + p2  # [2,0]
X = np.vstack([x1, x2])  # 2x2 行列
Wq = np.eye(2)  # 単純化: 単位行列
Wk = np.eye(2)

Q = X.dot(Wq)  # 2x2
K = X.dot(Wk)  # 2x2
S = Q.dot(K.T)  # スコア行列
A = softmax_rowwise(S)
print("Additive position example")
print("X=\n", X)
print("S=\n", S)
print("softmax rows=\n", A)

# --- 例2: RoPE（回転） ---
v = np.array([1., 0.])
def R(phi):
    return np.array([[cos(phi), -sin(phi)], [sin(phi), cos(phi)]])
theta = pi/2  # 90度ずつ回す
q0 = R(0).dot(v)       # position 0
q1 = R(theta).dot(v)   # position 1
Q2 = np.vstack([q0, q1])
K2 = Q2.copy()
S2 = Q2.dot(K2.T)
A2 = softmax_rowwise(S2)
print("\nRoPE example")
print("Q2=\n", Q2)
print("S2=\n", S2)
print("softmax rows=\n", A2)
```

このコードを実行すると、本文で手計算した値と一致する softmax 結果が得られます（ただし実際の実装では sqrt(d_k) によるスケール、バイアス項、複数ヘッド、残差接続、LayerNorm などが入ります）。

Transformer 内での位置情報の入れ方（どこに入るか／どのように適用されるか）
- 元祖（Vaswani et al., 2017）の設計: トークンの埋め込み e_i に「絶対位置の sin/cos で作ったベクトル p_i」を足してから、以降の層に渡す。すなわち x_i = e_i + p_i を最初に作る。
- RoPE（回転）は、入力埋め込みに直接足すのではなく、自己注意の計算内部で Q と K に対して位置に応じた回転を適用する。したがって位置情報は（実装的には）Attention の内部で活性化に掛かる関数として表現され、外から見れば Q,K が位置で「位相差」を持つようになります。
- GPT 型のデコーダー系モデルでも、位置エンコーディングは通常トークン埋め込みに足す形で導入される場合が多い（学習型ポジションや固定波形、あるいは後述の RoPE など実装差はある）。重要なのは「位置情報は入力に早めにか、または注意内部でかけられる」のどちらかであり、どちらを採るかで挙動や設計上の制約が変わるということです。

実際の大規模モデルとの接続と採用事情について（一般論の注意）
近年のモデルでは、単純に固定の sin/cos を足す方法だけでなく、学習可能な位置埋め込み、relative positional encoding（相対位置を直接扱う設計）、RoPE のような回転的な手法、ALiBi のようなバイアス方式など多様な案が使われています。どれが「主流」かはモデル設計者の選択やタスクによります。本章で扱った RoPE は一部の大規模言語モデルで採用実績がある一方、すべてのモデルで広く使われているわけではありません。ここで紹介した小さな数値例はあくまで概念を示すための教材であり、実際のモデルの中間表現のスケールや性質は大きく異なります。

よくある誤解の訂正
- 「attention weight が高い＝モデルが人間的に『注目』している」ではありません。注意重みは出力を得るための線形混合係数の一つの側面であり、最終的な出力は Value のベクトル和、さらには後続の FFN、残差接続、LayerNorm によって変形されます。attention weight だけを見て「ここを参照している」と単純に解釈するのは危険です。
- 「位置ベクトルは one-hot のように直接順序を表現する」わけではありません。加算型でも回転型でも、位置は埋め込み空間の方向や位相として作用し、注意スコアと線形変換を通じて間接的に順序性を与えます。
- RoPE は「複素数で掛けるだけ」という単純化で説明されることもありますが、実装は実数演算でペアごとに回転する形です。理論的には複素数表現と同等ですが、実装上の細部（ペアの分割、周波数の選び方）は重要です。
- 「Additive＝絶対位置情報のみ、RoPE＝相対位置を表す」と単純化するのも誤りです。加算しても後続のアーキテクチャ次第で相対的位置情報が利用されることはあり、RoPE でも絶対位置の情報が失われるわけではありません。ただし数学的な性質として RoPE は相対距離を内積の位相差として扱いやすい、という言い方はできます。

章のまとめ: 本章で説明できること（チェックリスト）
- 自己注意が入力の順序に対して本質的に「鈍感」である理由を説明できる。
- 位置情報を「足す」方法（加算型）と「回す」方法（RoPE）の違いを具体的に述べられる。
- 学習パラメータ（埋め込みや重み行列）と活性化（Q, K, V, attention weights など）を区別して説明できる。
- 単純な 2 要素・2 次元の例で、位置を入れた場合と入れない場合の attention のスコア計算と softmax の結果を手で出せる。
- RoPE の最小例（2 次元で回転角が 90°）を使い、回転が内積にどう影響するかを示せる。
- 注意重みを過度に解釈することの危険と、位置エンコーディング手法の選択がモデル挙動に与える影響について説明できる。

確認問題（練習問題）
1) 加算型の簡単な例を与えます。e_1 = [0,1], e_2 = [0,1]、位置 p_1 = [1,0], p_2 = [0,1] とする。W_Q = W_K = I として、softmax 前のスコア行列 S と各行の softmax の結果を求めよ。位置を入れない場合（p_1=p_2=[0,0]）と比較して、どのように attention の分布が変わるか説明せよ。

2) RoPE を使った例。ベクトル v=[1,0] が位置 0 と位置 2 に置かれているとする。RoPE の角速度 θ = π/2（位置差 1 ごとに 90°）を用いるとき、位置 0 と位置 2 の Q ベクトルはどうなるか。これらの内積を計算し、softmax の結果がどのようになるか述べよ（W_Q = W_K = I とする）。
