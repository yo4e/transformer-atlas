# Causal masking

問題提起 — 次を見てしまうと学習が壊れる

自己注意機構（self-attention）を使って「次のトークン」を予測する学習を行うとき、ある時刻 i の出力を計算する段階で、その先のトークン（i+1, i+2, ...）の情報にアクセスできてしまうと、モデルは先読みしてしまいます。たとえば文脈「私はリンゴを」を与えて次に来る語「食べる」を当てる学習で、内部的に i が「私はリンゴを」を見ているにもかかわらず、計算の途中で既に正解である「食べる」を参照できれば、学習信号は誤った方向に導かれてしまいます。これは「未来の情報を使って現在を説明する」という意味で、次を当てること自体を破壊します。したがって学習時に「未来は見えない」ように明示的に仕組みを入れる必要があります。

仕組みの要旨（名前は後で）

各トークンどうしの「点数（score）」を行列で計算したあと、ある位置 i が参照できてよい入力位置 j は j ≤ i に限るように、行列のうち「未来に相当する上三角の要素」に非常に大きな負の値を足します。その後に softmax を取ると、負の大きな値を足した要素はゼロに近い確率に押し下げられ、実質的に「参照できない」扱いになります。重要な点は「トークンを消す」のではなく「その組み合わせの重みをゼロ化する」操作だということです。

直感と注意点

直感としては「i が j を"見ない"ようにエッジを切る」とイメージできます。実際の挙動は softmax を通じて確率分布に変換されるため、完全に刈り取られるのは理想化された場合（−∞ を入れる）であり、実装上は大きな負値（例えば −1e9）を使って近似します。もう一つの誤解しやすい点は、「マスクされたトークンは情報源として完全に消える」と考えることですが、トークンの埋め込みやキー・バリューは計算上存在し続けます。あるクエリ i から見てあるキー j の重みだけが実質ゼロになる、という話です。さらに、attention 重みが人間的「注目」の完全な証拠だと決めつけるのも誤りです。attention は計算的な重みであり、可視化はヒューリスティックな解釈に過ぎません。

数値オブジェクトの区別（何が固定パラメータで何が計算結果か）

ここで出てくる主要な種類を明確にしておきます。モデルに「学習される重み」があります（たとえばクエリ行列 W_Q、キー行列 W_K、値行列 W_V など）。これらはパラメータで、訓練によって更新されます。入力はトークンから作られるベクトル列（埋め込み）や位置情報で、学習のたびに与えられます。クエリ Q、キー K、バリュー V、それらの内積から得られる score（スコア）、softmax を通して得られる attention weight（注意重み）、そして attention の出力は「活性化（activation）」と呼ぶ中間データです。パラメータと入力は固定／外部で与えられるもので、活性化はそれらから計算されます。以降の数式・コードではこの区別を保ちます。

具体例（長さ3）を数字で計算する

まず長さ L = 3 のトークン列を考えます。あるレイヤーで計算されたスコア行列 S（形状 3×3、行がクエリ位置 i、列がキー位置 j を表す）を次のように与えます（これは説明用に選んだ数値で、実際の大規模モデルの内部値を意味するものではありません）：

S = [[3.0, 1.0, 0.0],
     [1.0, 2.0, 0.5],
     [0.0, 1.0, 3.0]]

ここで「未来を見せない」ために行 i から列 j に対して j > i の位置（上三角）に −∞ を加えます。実装上は −∞ の代わりに大きな負値 −M（例：M = 1e9）を使いますが、概念的には −∞ と表現します。するとマスク後の行列は

S_masked = [[3.0, -∞,  -∞],
            [1.0,  2.0, -∞],
            [0.0,  1.0,  3.0]]

各行ごとに softmax を取ると、最初の行は [3.0, −∞, −∞] の softmax ですから非マスキングの要素のみが残り、結果は [1, 0, 0] になります（exp(3)/exp(3) = 1）。二行目は [1.0, 2.0, −∞] の softmax を計算します。数値計算を示すと

exp(1.0) = 2.7182818...
exp(2.0) = 7.3890561...
合計 = 10.1073379...

したがって二行目の attention weight は約 [0.269, 0.731, 0.0] です。三行目はマスクされていないので通常の softmax：

exp(0.0) = 1
exp(1.0) = 2.7182818...
exp(3.0) = 20.0855369...
合計 = 23.8038187...

三行目の attention weight は約 [0.0420, 0.1142, 0.8438] になります。これで三行すべてを示しました：第一行は完全に左端（自分自身）だけ、第二行は左二つの混合、第三行は全てを使う、という挙動になります。

数式での表現と記号の意味（普通の言葉で）

ここで一般式を示します。トークン列の埋め込みを X（形状 L × d_model、L はトークン数、d_model は埋め込み次元）とします。学習パラメータとしてクエリ、キー、バリューへの線形変換の行列 W_Q, W_K, W_V（それぞれ d_model × d_k、d_model × d_k、d_model × d_v）を持ちます。これらは固定の「重み（パラメータ）」です。計算は次のようになります：

Q = X W_Q    （形状 L × d_k）   ← クエリ（各位置 i の問い合わせベクトル）
K = X W_K    （形状 L × d_k）   ← キー（各位置 j の照合ベクトル）
V = X W_V    （形状 L × d_v）   ← バリュー（各位置 j の供給ベクトル）

ここで、スコア行列 S はクエリとキーの内積（行ごとが i、列ごとが j）を正規化したものです。正規化係数は d_k の平方根 sqrt(d_k) で割るのが普通です（オリジナルTransformerの定式化）：

S = Q K^T / sqrt(d_k)   （形状 L × L）

S の i 行 j 列成分 S[i, j] は「位置 i のクエリが位置 j のキーとどれだけ合うか」を示す生の数値スコアです。これにマスク行列 M を足します。M は i 行 j 列で j > i のとき −∞、それ以外は 0 の値をとります。

S_masked = S + M

次に softmax を行う向きですが、ここでは各行 i に対して列方向に softmax を取る（すなわち j を総和する）ので、softmax は「行ごとの確率分布」を作ります：

A = softmax(S_masked, axis=1)   （A は L × L、行 i が i の attention weight）

最後に attention の出力は行列積 A V で与えられます：

O = A V   （形状 L × d_v）

この O がさらに線形変換などを受けて次の層へ渡ります。式中の各行・列の向きは「行がクエリ位置（出力位置）、列がキー位置（入力位置）」と覚えておくと実装と対応しやすいです。

小さな実装例（NumPy）

以下は先の具体例 S と同じ数値を使った簡潔な Python（NumPy）コードです。注意：実際の数値は説明用であり、実モデルの内部値とは異なります。数値的には −np.inf を直接入れると挙動が扱いにくい実装環境もあるため、実装では大きな負値 -1e9 を使うことが多いです。

```python
import numpy as np

S = np.array([[3.0, 1.0, 0.0],
              [1.0, 2.0, 0.5],
              [0.0, 1.0, 3.0]])

L = S.shape[0]
# マスク行列 M を作る（上三角を -inf、対角と下三角を 0）
M = np.zeros_like(S)            # 形状 L×L
for i in range(L):
    for j in range(L):
        if j > i:
            M[i, j] = -1e9      # 実装上は -inf の代わりに大きな負値

S_masked = S + M

# 行ごとに softmax を適用する
def softmax_rows(X):
    # 安定化のために行ごとの最大を引く
    X_max = np.max(X, axis=1, keepdims=True)
    e = np.exp(X - X_max)
    return e / np.sum(e, axis=1, keepdims=True)

A = softmax_rows(S_masked)

print("S_masked =\\n", S_masked)
print("attention weights A =\\n", A)
```

このコードを実行すると attention weights A は、上で手計算したように約

[[1.0, 0.0, 0.0],
 [0.269, 0.731, 0.0],
 [0.0420, 0.1142, 0.8438]]

のような値になります（有効桁は環境によって差があります）。

Transformer の中での前後関係と実運用上の接続

元来の Transformer（Vaswani et al., 2017）はエンコーダ・デコーダ構造を持ちます。この中でデコーダ側の「自己注意」は、未来を見ないようにマスクする必要があります。つまりマスクは主にデコーダ自己注意で使われます。一方、エンコーダの自己注意やデコーダのエンコーダ-デコーダ（cross-attention）では、入力系列全体に対して全ての位置を参照してよいので、同様の causal mask は使いません。

GPT 型のような decoder-only モデルでは、すべての自己注意層でこの causal マスクが適用されます。学習時はバッチ内で長いシーケンスを与え、全位置の出力を一度に計算して損失を求めますが、このときマスクで未来を隠しておくことで正しく次トークンを予測させます。推論（自動生成）時には、モデルは通常 1 トークンずつ生成し、過去のキー・バリューをキャッシュして新しいクエリだけを計算することで効率化します。この際に causal mask 自体は理論的に同じ役割を果たしますが、実装上は「既に生成済みの長さを考慮して attention を O(L^2) せずに済ませる」ための工夫（キャッシュ、分割注意、FlashAttention のような高速化手法）と組み合わされます。

よくある誤解の訂正

- 「マスクはトークンを削除する」：誤りです。マスクはスコアに大きな負値を足して softmax 後の重みを実質ゼロにするだけで、キーやバリューは計算上は残っています。別のクエリ（後方のクエリなど）はそのキー・バリューを参照できます。
- 「attention の値が高い＝モデルはその語に意味的に注目している」：注意の重みは内部の計算効率・線形結合の重みづけを示すだけです。解釈可能性の証拠としては限定的で、他の解析手法と組み合わせて慎重に扱うべきです。
- 「 causal mask は全ての Transformer に常に使われる」：いいえ。encoder-only 型（BERT のような）では別のマスク（マスクランゲージモデル目的など）があるし、encoder-decoder の encoder 部分では不用です。モデルの目的と構造によって適用箇所が異なります。

学習で使う数値についての注意

本文中に示した小さな浮動小数点の数値は教材上の例であり、実際の大規模モデルのステート（内部のスコアや埋め込み）の統計やスケールとは大きく異なります。ここでの目的は計算経路とマスクの効果を明示することであり、実運用の挙動をそのまま表すものではありません。

まとめ（この章を読んで説明できること）

- なぜ「未来を隠す」仕組みが必要なのか（次トークン予測が学習目標である場合）。
- マスクがスコアに大きな負値を足すことで softmax の出力を操作する仕組みであること。
- マスクはトークンを削除するのではなく、あるクエリから見た重みをゼロにするだけであること。
- 数式 Q = X W_Q、S = Q K^T / sqrt(d_k)、S_masked = S + M、A = softmax(S_masked)、O = A V が attention の流れであり、各記号が何を表すか。
- 実装上は −∞ を大きな負値で近似すること、推論時はキャッシュ等で高速化すること。
