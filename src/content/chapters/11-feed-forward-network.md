# Feed-forward network

**問題提起：注意機構で位置間が混ざったあとに何が必要か**

文章や音声、系列データを扱うとき、まず各要素（単語やサブワードなど）をベクトルに変換し、注意機構によって「どの位置からどれだけ情報を受け取るか」を学習します。注意は位置同士を混ぜ合わせる強力な道具ですが、注意だけで済ませると次のような問題が残ります。

- 各位置の「特徴ベクトル」を、非線形に変換してより表現力の高い特徴にする必要がある。注意は複数の位置から情報を集めるが、その後で各位置の特徴自体を変換する処理がないと、モデルの表現力は限られる。
- 位置間の混合（＝どの位置から情報を集めるか）と、各位置で行う特徴変換（＝集めた情報をどう使うか）は別々に設計した方が扱いやすい。混合と変換を分けることで、位置のやり取り（文脈）と、局所的な非線形表現の拡張という二つの役割を明確に分担できる。

ここで問題となるのは「注意で混ざった後の各位置に、同じ非線形変換を独立して適用する仕組み」がどう働き、なぜ必要なのかを理解することです。以降ではその直感、数学的定式化、数値例、実装例、全体構成での位置づけ、よくある誤解の訂正、そして学習上のポイントを順に説明します。

**直感（有用なイメージ）と字義通りではない点の注意**

直感的にはこう考えられます。注意で集めた情報は「その位置に関する原材料」です。原材料を加工するために、各位置ごとに同じ加工機（同じ重み）を通すことで、位置ごとに同種の処理を施せます。例えば「強調すべき特徴を打ち出す」「不要な成分を抑える」「別の空間に写像する」などです。重要なのは、同じ加工機がすべての位置で共有されるため、少ないパラメータで多くの位置を処理できる点です。

しかし、この直感を文字どおりに受け取らないでください。具体的には：

- 「同じ機械を通す＝すべての位置の出力が同じ」ではありません。入力ベクトルが異なれば、同じ関数の出力も異なります（関数は共有でも入力が違う）。
- 「位置間の混合はここでは起こらない」は大筋で正しい（この層自体は位置を混ぜない）が、注意の後に来るため、注意で混ざった結果が入力として与えられ、その文脈情報に応じて出力が変わります。つまり、間接的に位置間の依存を反映します。
- 非線形性（例：ReLUやGeLU）は非常に重要です。線形変換だけを積み重ねても、全体で見れば単一の線形変換に畳み込まれてしまい表現力は制限されます。

次に、数学的にきちんと定義しますが、その前に「学習パラメータ」「入力」「活性化（activation）」などの語を区別しておきます。

- 学習されるパラメータ（parameters）：モデルが学習によって獲得する固定の数値。ここでは重み行列やバイアス（例：W1, b1, W2, b2）。
- 入力（input）：その層に入ってくる値で、別の層や埋め込み、注意出力の結果。実行時に与えられるアクティベーションです（例：x_i）。
- 活性化（activation）：線形変換の出力やその後の非線形関数適用後の値。前段の出力であり、次段の入力になります。混同しないよう、たとえば「前段の出力 = 入力ベクトル x」、「線形の結果 = h（pre-activation）」、「非線形後 = a（post-activation）」、「最終出力 = y」と表記します。

以下でこれらを使って正式に説明します。

**数学的定式化（記号と「普通の言葉」による説明）**

対象とする処理は、系列の各位置に対して同一の2層の非線形写像を独立に適用するものです。記号を導入して普通語に戻して説明します。

- 系列長（取り扱う位置の数）を n とする。ただしこの層は位置ごとに独立なので、n の値は個々の計算に直接関係しません（同じ関数を n 個回並べて適用するイメージ）。
- 各位置の入力ベクトルを x_i と書く（i = 1, 2, …, n）。これは前の処理（例えば注意ブロック）の出力で、次の層の入力になります。ベクトルの次元を D と呼びます（しばしば d_model と呼ばれる）。
- 学習パラメータは次の四つ：
  - W1: 形は (D_ff × D)。これは第1の線形変換の重みで、入力 D 次元を中間の D_ff 次元に写像する行列。
  - b1: 形は (D_ff)。第1線形のバイアス（ベクトル）。
  - W2: 形は (D × D_ff)。中間 D_ff 次元を元の D 次元に戻すための行列。
  - b2: 形は (D)。第2線形のバイアス。

処理の流れは位置 i について次の通りです（行列積や加算を言葉で説明します）：

1. 線形変換（重みで線形変換してバイアスを足す）で前段の出力を中間空間に写す：
   h_i = W1 × x_i + b1
   ここで "W1 × x_i" は W1 の各行と x_i の内積を取り、それぞれが h_i の成分になります。b1 は各成分に足す定数ベクトルです。h_i を「ReLU などの非線形関数に入る前の値（pre-activation）」と呼びます。

2. 非線形関数 φ（ここでは ReLU）を成分ごとに適用：
   a_i = φ(h_i)
   ReLU は負の成分を 0 にし、正の成分はそのままにする単純な関数です。これが非線形性を導入します。

3. 第2の線形変換で元の次元に戻す：
   y_i = W2 × a_i + b2
   これがこの小ブロックの出力（位置 i に対する新しい活性化）です。

注意点をもう一度：W1, b1, W2, b2 は同一の値がすべての位置に対して共有されます。したがって上の三つの式は i に依存するのは x_i のみであり、パラメータは共有されるという意味で「位置ごとに同じ関数を適用する」ことになります。

次に、与えられた具体例で数値を追い、ReLU の前後と出力を厳密に計算します。

**具体例（要求どおりの数値をそのまま使って計算）**

与えられたもの：
- 入力ベクトル x = [1, −1]^T。これは D = 2 の列ベクトル。
- W1 = [[1, 2], [0, 1]]。行列として書くと
  W1 = [ [1, 2],
         [0, 1] ]
  ここで W1 は 2×2 行列になっています（D_ff = 2 を仮定）。
- 非線形関数は ReLU（負の成分を 0 にする）。
- W2 は「小さな数値例」を使う、という指定なので便宜上以下を採用します（実モデルとは無関係なサンプル値です）：
  W2 = [ [0.5, −0.5],
         [0.1, 0.2] ]
  これは D×D_ff の形（ここでは 2×2）です。
- バイアスは簡素化のために b1 = [0, 0]^T, b2 = [0, 0]^T と仮定します（必要なら異なる値も示せますが、指定がないためゼロとします）。

では計算を順に示します。まず h = W1 × x + b1。

1) W1 × x の計算：
- 第1成分: (1)*1 + (2)*(−1) = 1 − 2 = −1
- 第2成分: (0)*1 + (1)*(−1) = 0 − 1 = −1
したがって h = [−1, −1]^T。（b1 = 0 なので加算で変化なし）

2) ReLU を成分ごとに適用して a = φ(h) を得る：
- ReLU(−1) = 0
- ReLU(−1) = 0
従って a = [0, 0]^T。

3) 最終出力 y = W2 × a + b2 を計算：
- W2 × a は a がゼロベクトルなので当然 [0, 0]^T
- b2 = [0, 0]^T と仮定したので y = [0, 0]^T

結論：この具体例では、W1 の選び方と x の組合せにより中間表現 h がすべて負になり、ReLU によって a がゼロベクトルになり、最終出力 y もゼロベクトルになります。

この数値例から学べること：
- 中間の線形変換で全成分が負になると、単純な ReLU によって情報が「消える」可能性がある。学習時にはバイアスや重みの調整でこの挙動を避ける／活用することがある。
- 小さな例では出力が 0 になるが、これは学習するパラメータとバイアスが適切であれば防げる（あるいは意図的にすることもある）。
- この手続きは各位置で独立に行われるため、位置ごとの入力 x_i によって結果が大きく異なる。共有パラメータでも出力が一様になるわけではない。

（補足）今回使った数値は教材用の簡単な例です。実際の大規模モデルでは D や D_ff は数百から数千、パラメータの初期値や学習済みの値はこのような単純な小数ではなく、統計的に管理された初期化や学習手順によって得られます。したがって上の具体例の数値は「本物のモデル内部を直接表すものではない」ことに注意してください。

**行列積と軸の説明を普通の言葉に戻して再掲**

- W1 は「（出力の）行ごとに見れば、入力 x の各成分にかける重みの束」であり、W1 の 1 行目は h の 1 成分を作るための重み、2 行目は h の 2 成分を作るための重み、と読みます。
- 行列積 W1 × x は、各行と入力ベクトルの内積で成分を計算する操作。バイアス b1 はその結果に足し込む定数。
- ReLU は各成分に独立にかかる関数（要は「成分ごとのスイッチ」）で、非線形性をもたらします。
- W2 は逆に中間成分を再び線形結合して元の次元に戻すための重み集合です。

これを異なる言い方で理解すると、W1 は「特徴の展開（次元を増やして複雑なパターンを表現しやすくする）」、ReLU は「特徴の選別と非線形性」、W2 は「選別された特徴を元の空間に集約する」役割を果たします。

**短い Python 実装例（数式の変数名と対応させる）**

次のコードは上で示した数値例をそのまま計算します。変数名は数学的表記と対応しています（x, W1, b1, h, a, W2, b2, y）。外部ライブラリは NumPy を使用し、可読性を優先した簡潔な実装です。

```python
import numpy as np

x = np.array([1.0, -1.0])  # x (D=2)

# パラメータ（与えられた例）
W1 = np.array([[1.0, 2.0],
               [0.0, 1.0]])  # W1 (D_ff x D)
b1 = np.array([0.0, 0.0])    # b1 (D_ff)

# 中間の線形出力（pre-activation）
h = W1.dot(x) + b1           # h = W1 * x + b1
print("h (pre-activation):", h)  # 期待値 [-1. -1.]

# ReLU の適用（post-activation）
a = np.maximum(0.0, h)       # ReLU
print("a (post-activation):", a)  # 期待値 [0. 0.]

# W2 は小さな数値例
W2 = np.array([[0.5, -0.5],
               [0.1, 0.2]])  # W2 (D x D_ff)
b2 = np.array([0.0, 0.0])    # b2 (D)

# 最終出力
y = W2.dot(a) + b2
print("y (output):", y)      # 期待値 [0. 0.]
```

このコードを実際に動かすと、先の手計算と一致します。コメントで示したとおり、h は [-1, -1]、a は [0, 0]、y は [0, 0] になります。

**Transformer 全体の中での前後の処理、モデル規模での接続**

元の論文（Vaswani et al., 2017）が提案した Transformer（エンコーダ・デコーダ構成）では、この「位置ごとの非線形変換」ブロックは注意サブブロックの直後に置かれます。典型的な一つの層の流れは：

1. （自己注意やエンコーダ–デコーダ注意など）注意ブロックを実行して位置間の文脈を集める。
2. 残差接続（入力を足す）と正規化（LayerNorm）を行う。
3. その結果をこの位置ごとの2層非線形ネットワーク（今章で扱うもの）に入力する。
4. さらに残差接続と正規化を行う。

重要な点は、この2層ブロック自体は位置間の混合を行わないことです。したがって「位置間のやり取り」は主に注意が担い、特徴の局所的な非線形変換はこのブロックが担います。エンコーダ・デコーダ両方の Transformer と、GPT 系列のようなデコーダのみのアーキテクチャ（causal self-attention を持つ）でも、この種の位置ごとのフィードフォワードはほぼ同じ形で使われます。ただし、エンコーダ／デコーダの全体構造や注意の因果性（causal）といった違いは混同しないでください。元のエンコーダ・デコーダ Transformer と、後に登場した GPT 型（decoder-only）はアーキテクチャの目的と注意の使い方が異なりますが、位置ごとの2層 MLP ブロックはどちらにも共通に存在するコンポーネントです。

現実の大規模モデルでは次のような実装上の点が一般的です（ただしすべてのモデルで共通ではない）：

- D（d_model）は数百〜数千、D_ff は通常 D の 2〜4 倍（例：D=1024, D_ff=4096）。
- 非線形関数は ReLU の代わりに GeLU を使うことが多い（GeLU は確率的な滑らかさを持つ関数）。
- 正規化（LayerNorm）や残差接続、Dropout などが組み合わさる。
- 計算効率のために行列は大きく、学習や推論で高速化ライブラリ（例：FlashAttention）は注意機構だけでなく、全体のメモリ管理を改善するために使われる。
- 変種としてモジュール選択（Mixture of Experts）や，位置ごとの条件付きスケーリングといった拡張があるが、それらは「一般的な採用」を意味するものではない。

ここで一つ重要な学習上のこと：この2層ブロックはパラメータを共有するため、同じ変換がすべての位置に適用されます。これにより、モデルは「どの位置に現れるかに依存しない特徴変換」を学べます。逆に、位置固有の処理が必要であれば注意や位置エンコーディングなど別の仕組みで表現せねばなりません。

**よくある誤解とその訂正**

1. 「このブロックが位置間の依存を作る」：誤解。位置間の依存は主に注意が担当します。このブロック自体は位置間の混合をしない（位置ごとに独立に処理する）ことに注意してください。ただし、入力 x_i に注意の結果が含まれているため、間接的に文脈情報を反映する点は混乱しやすいです。

2. 「Attention weight は人間が『どこを注目しているか』をそのまま示す証拠だ」：誤解。注意重みはあくまでモデルの計算過程での係数です。可視化は直感を与える場合があるものの、必ずしも人間的な説明に直結するわけではありません。注意に基づく説明は慎重に扱うべきです。

3. 「token は単語と同じ」：誤り。実際には token は単語、あるいはサブワード、バイトペア、その他の単位であり、単語とは必ずしも一致しません。モデルの入力はトークン列であると理解してください。

4. 「ReLU を使ったら負の情報がすべて失われるので ReLU は危険」：部分的に正しい。ReLU が負の成分を 0 にするのは事実ですが、バイアスや重みでそれを制御できます。また、負の値を残したいなら GeLU や他の活性化、あるいはバイアス設定で対処します。ReLU は計算効率と学習の安定性の良さから広く使われます。

**学習面の概略（微積分や確率の詳細なし）**

モデルはデータに対してパラメータ（W1, b1, W2, b2 を含む）を適応させます。学習時には損失関数（タスク固有）を定義し、損失を減らす方向にパラメータを少しずつ変更する手順を繰り返します。重要な点は、位置ごとのブロックはパラメータを共有するため、すべての位置のデータが同じパラメータ更新に影響を与えるということです。結果として、このブロックは言語や系列データに共通する局所的な変換を学ぶことになります。

（詳細な数学的最適化・勾配計算は本章の範囲外ですが、パラメータがどう「学習されるか」は学習データと目的関数次第である点は押さえておいてください。）

**章の最後に：あなたが説明できること（学習目標）**

この章を通じて、読者は次のことを具体的に説明できるはずです。

- 注意で混ぜたあとに「位置ごとに同じ非線形変換を独立に適用する」処理が何をするか、その目的と利点を説明できる。
- この処理が線形変換と非線形関数（例：ReLU）から成ることを説明し、式 h = W1 x + b1, a = φ(h), y = W2 a + b2 を書ける。
- 学習パラメータ（W1, b1, W2, b2）と実行時のアクティベーション（x, h, a, y）を区別して説明できる。
- 与えられた具体例（x=[1, −1], W1=[[1,2],[0,1]], ReLU, W2 の例）で中間値 h, a, y を手計算・プログラムで求め、その意味を解釈できる。
- このブロックが位置間の混合を行わないこと、attention と役割を分けること、attention weight の解釈に関する注意点を説明できる。
