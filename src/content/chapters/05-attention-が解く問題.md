# Attention が解く問題

まず問題を提示する。多くのデータ列（たとえば文章中の単語列や時系列の観測）を扱うとき、各位置（ある単語やある時刻）が、他のどの位置から情報を取り入れるかは入力ごとに変わる必要がある。ある文では先頭の語が後ろの語を参照したいかもしれないし、別の文では隣接する語だけが重要かもしれない。もし「常に一定の幅でしか隣を見られない」仕組みや「列全体を一律に平均する」しかできないと、入力ごとに変わる複雑な関係を表現できない。ここで求められるのは、位置ごとに、どの位置からどれだけ情報を受け取るかを入力に応じて決められる仕組みである。

直感としては「ある位置がほかの位置に『より多く注目する』」ようにして、注目度に応じて複数の候補を混ぜ合わせるイメージが役に立つ。だがこの直感は文字どおりの「人間的な注目」ではない。重みが高いからといってそのモデルが人間と同じ理由でその箇所を選んでいるわけではなく、単に計算上その入力からの情報が出力の改善に寄与することを示す数値である。したがって重み（スコア）を人間の「理由づけ」の直接証拠と見るのは誤りだと覚えておいてほしい。

次に、実際にどのように情報を集めるかを段階的に示す。ここでは三種類のオブジェクトを区別して扱うことが重要だ。

- 入力に基づく数値（activation、計算の途中で得られる値）。たとえばある位置から得られる候補のベクトルや、それらを比較して得られるスコアがこれに当たる。
- 学習されるパラメータ（learnable parameters）。線形変換の係数行列などで、訓練データから学習される固定の数値。これらはモデルの「調整ねじ」であり、訓練中に変化する。
- 保持される値（values）。通常は入力から変換されて得られる「情報の入れ物」となるベクトル群で、最終的に重み付き和で混ぜられる対象。

ここで典型的な操作を数式で表す前に、簡単な具体例で直感を固める。三つの value ベクトルがあるとする。

- v1 = [2, 0]
- v2 = [0, 3]
- v3 = [1, 1]

これらに対して位置固有に得られた重み（確率的に合計が1になるよう正規化された非負数）が

- α = [0.6, 0.3, 0.1]

と与えられたなら、出力は各 value に重みをかけた「重み付き和」で計算される。要素ごとに計算すると、

- 出力の第1成分 = 0.6×2 + 0.3×0 + 0.1×1 = 1.2 + 0 + 0.1 = 1.3
- 出力の第2成分 = 0.6×0 + 0.3×3 + 0.1×1 = 0 + 0.9 + 0.1 = 1.0

よって出力ベクトルは [1.3, 1.0] になる。一方で、この三つを単純に一律平均すると、(v1 + v2 + v3) / 3 = ([3, 4]) / 3 = [1.0, 1.333...]. 比較すると、一律平均は第1成分を 1.0 に、第2成分を約 1.333 に固定してしまうのに対し、重み付き和は第1成分を相対的に高く（1.3）し、第2成分を低く（1.0）することで「第1成分に寄った」出力を作れている。これが「入力ごとにどこから情報を集めるかを変えられる」利点の本質である。

ここから一般式を示す。長さ N の列があり、各位置 i に対して d 次元の value ベクトル v_j（j は候補の位置）を用意する。位置 i の出力 o_i は候補 v_j の重み付き和で書ける：

o_i = sum_{j=1..N} α_{ij} v_j

ここで α_{ij} は位置 i が位置 j に与える重みで、自然に非負であり j に沿って合計が 1 になるように正規化されている（α_{ij} ≥ 0, sum_j α_{ij} = 1）。行列形式で書けば、V を (N × d) の行列、A を (N × N) の重み行列とすると、出力行列 O は

O = A V

となる。行列積の意味を普通の言葉に戻すと、A の i 行は「位置 i が各位置からどれだけ引き出すか」を示す重みの列で、その重みで V の行（各位置の情報）を足し合わせて o_i を作る、という操作だ。

では α_{ij} はどう得られるか。多くの実装で使われる方法は「位置 i 用の問い合わせベクトル（query）q_i」と「位置 j 用の候補表現（key）k_j」を用意し、その内積をスコア s_{ij} として比較することだ。典型的な式は

s_{ij} = (q_i · k_j) / sqrt(d_k)

α_{ij} = softmax_j(s_{ij})

ここで sqrt(d_k) は数値を安定化させるための定数で、softmax_j は j に沿って指数関数を取り正規化する操作（exp(s_{ij}) を j で割る）で、結果は非負で合計1になる。q_i と k_j は通常、入力から別々の学習パラメータ（線形変換の重み行列）を通して得られる「活性化」であり、値 v_j もまた別の線形変換で作られることが多い。まとめると、学習される重み行列（パラメータ）は queries/keys/values を取り出すための変換を定義し、実際にデータに依存して計算される q_i, k_j, v_j はその都度変化する activation である。

ここで、すべての記号の意味をもう一度平易に示す。

- N: 列の長さ（位置の数）。
- d_k: key/query ベクトルの次元（スコアを計算する空間の次元）。
- d_v: value ベクトルの次元（最終的な出力の次元）。
- V: 候補ベクトルをまとめた行列。形は (N × d_v)。行 j が v_j。
- Q: 問い合わせベクトルをまとめた行列。形は (N × d_k)。行 i が q_i。
- K: 候補キーをまとめた行列。形は (N × d_k)。行 j が k_j。
- S: スコア行列。形は (N × N)。要素 s_{ij}。
- A: 重み行列（softmax 後）。形は (N × N)。要素 α_{ij}。
- O: 出力行列。形は (N × d_v)。行 i が o_i。

S = Q K^T / sqrt(d_k)
A = softmax_rows(S)   （各行を正規化する）
O = A V

これらは単に行列の掛け算と列ごとの正規化を組み合わせたものに過ぎないが、Q と K が入力に依存して計算されるため、A は入力ごとに変化する。

実用的な短い Python の実装例を示す（教育目的の簡潔なコード）。ここでは NumPy を使い、softmax を自前で書く。数式の変数名と対応するようにしている。

```python
import numpy as np

V = np.array([[2.0, 0.0],
              [0.0, 3.0],
              [1.0, 1.0]])  # shape (3, 2)

# 例として既知の重みを与える場合（学習で得られるのはこれではなくソフトマックス結果）
alpha = np.array([0.6, 0.3, 0.1])  # shape (3,)

# 重み付き和（先に示した具体例の計算）
output = alpha @ V  # shape (2,)
print("weighted output:", output)  # => [1.3, 1.0]

# 一律平均と比較
uniform_output = V.mean(axis=0)
print("uniform average:", uniform_output)  # => [1.0, 1.33333333]

# 以下は重みを Q, K から計算する例（簡単なダミー）
Q = np.array([[1.0, 0.0],  # q_1
              [0.0, 1.0],  # q_2
              [1.0, 1.0]]) # q_3
K = Q.copy()  # 対称な例
d_k = Q.shape[1]
S = (Q @ K.T) / np.sqrt(d_k)        # shape (3,3)
# softmax を行毎に適用
def softmax_rows(x):
    x = x - x.max(axis=1, keepdims=True)
    e = np.exp(x)
    return e / e.sum(axis=1, keepdims=True)
A = softmax_rows(S)                # shape (3,3)
O = A @ V                          # shape (3,2)
```

上のコードでは alpha を直接指定した先の例と、Q・K からスコアを計算して softmax で A を作る例の両方を示した。実際のモデルでは Q, K, V は入力トークン列に対して別々の学習行列（パラメータ）を通した結果であり、α はその都度計算される activation である点を繰り返す。

注意しておくべき点を列挙する。

- 上で用いた小さな小数（0.6, 0.3, 0.1 等）は教育用の例であり、実際の大規模モデルの内部状態や値を表すものではない。実モデルの数値は次元も値域も大きく、これらの例は概念理解を助けるための単純化である。
- 「token」は必ずしも英単語や日本語の単語と同義ではない。モデルはしばしば subword や BPE トークンを扱い、token は「記号列の最小単位」を指す。
- attention の重みを「人間的な注目の証拠」として安易に解釈しないこと。高い重みはモデルの計算上重要であることを示すが、その「理由」を人間が読み取れるとは限らない。可視化は示唆を与えるが決定的証拠ではない。

この仕組みは、オリジナルの Transformer（Vaswani et al., 2017）論文で提案された「位置ごとに入力から重み付き和を作る仕組み」を核にしている。重要な点は、オリジナルの Transformer はエンコーダ・デコーダの構造を持ち、自己注意（self-attention）とエンコーダ→デコーダのクロス注意の両方を使った点だ。これに対して GPT 型のモデルはデコーダのみを積み重ね、出力の生成時には未来の位置を見ないように三角マスク（causal mask）を置いた「マスクされた自己注意」を用いる。両者を混同しないように注意すること。実装や応用の場面で、役割（エンコーダかデコーダか）によって attention の使われ方が異なる。

また実用上の課題としては計算量とメモリの増大がある。全ての位置対にスコアを計算するため、長い列では O(N^2) の計算とメモリが必要となる。これを改善するためにアルゴリズム（FlashAttention のような高速化）や、特定の位置だけを見る疎な注意（sparse attention）、専門化した経路を取る MoE（Mixture of Experts）などが研究・実装されている。ただしこれらの変種は目的やトレードオフが異なり、どれが「正解」と一般化できるわけではない。

よくある誤解の一つを訂正しておく。しばしば「重みが高い位置が出力のすべての情報源である」と解釈されるが、実際には出力は値ベクトル v_j の線形結合であり、各 v_j の内部に複数の情報が混在している。重みが高いからといってその位置から単一の「意味」がそのまま移されるわけではなく、重みと値の両方を見る必要がある。したがって attention heatmap（重みの可視化）だけで因果関係や内部推論を断定するのは誤りである。

最後に、この章を読んだ後にあなたが説明できるべきことを短くまとめ、理解を確かめるための確認問題を2問用意する。

- 説明できること（箇条書き）
  - なぜ各位置が他位置から入力ごとに異なる割合で情報を集める必要があるのか。
  - 重み付き和が一律平均とどう異なり、どのようにして入力ごとに変化する重みを作るか（query/key と softmax を使うこと）。
  - 学習パラメータ（queries/keys/values を作る線形変換）と、入力から計算される activation（q_i, k_j, v_j）、および最終出力（o_i）の役割の違い。
  - attention weight を人間の注目と同一視することの危険性と、値ベクトルとの関係を同時に見る必要性。

- 確認問題
  1. v1=[2,0], v2=[0,3], v3=[1,1] に対して α=[0.6,0.3,0.1] のときの重み付き和を計算し、列の一律平均との違いを説明せよ（手計算を示すこと）。
  2. 位置 i の query q_i とすべての position j の key k_j に対して内積を取って softmax を適用すると重み α_{ij} が得られる。なぜスコアをそのまま使わず sqrt(d_k) で割り、さらに softmax を取るのか、それぞれ直感的に説明せよ。
