# Temperature, top-k, top-p

問題提起と動機
モデルが語彙（token）から次に出すものを決めるとき、単に「最も確からしいものを常に選ぶ」だけでは柔軟さが足りません。常に最大確率の語を返すと単調で繰り返しが生じやすく、逆にそのまま確率分布どおりにサンプリングすると稀な語が頻繁に出て質が落ちることがあります。そこで、同じ「候補ごとの生の数値（logits）」から、生成時にどのように確率を変形してサンプリングするかを決めるいくつかの規則が用いられます。本章ではその仕組みを、できるだけ具体的な数値経路で説明します。なお、ここで扱う小さな数値例は教材用の簡易な値であり、実際の巨大モデル内部の値とは異なります。

直感と注意点
直感的には次の三つが役に立ちます。第一に「温度（temperature）」は確率の尖り具合を調節するつまみで、高いほど均一に、低いほど尖る。第二に「top-k」は上位k個だけ残す刈り込み、第三に「top-p（nucleus）」は累積確率がpになるまで上位を残す可変的な刈り込みです。しかし重要な注意点が二つあります。温度は確率そのものに直接掛けるのではなく、softmax の前の logit に作用します（これは数学的に結果を大きく変えます）。また top-k と top-p は「選択肢を切り捨てる」ため、長文生成での多様性と一貫性に与える影響が異なります。どの方法も万能ではなく、モデル・タスク・要求される出力品質に応じて使い分ける必要があります。

用語の区別（重要）
- 学習パラメータ：重みやバイアスなど、訓練で固定される数値。ここでは W や b。
- 入力から計算される activation（ここでは logits）：ある入力と学習パラメータの組合せから算出される生のスコア。通常は語彙ごとに一つの実数 l_i。
- 確率：softmax によって logits から得られる非負数の配列 p_i（合計が1）。

数式とその言葉での説明
まず基本の softmax を書きます。語彙の各候補 i に対して、モデルは生のスコア l_i（logit）を算出します。これを確率に変えるのが softmax：
p_i = exp(l_i) / sum_j exp(l_j)

ここで temperature T を入れると、softmax に供するスコアを縮尺する形になります。一般的には logits を T で割る（または逆数 β = 1/T を掛ける）：
p_i(T) = exp(l_i / T) / sum_j exp(l_j / T)

言葉で戻すと「logit を小さく割ると、指数関数による差が縮まり確率が平坦化し、逆に小さい T は差を拡大して尖らせる」ということです。top-k の操作は次のように書けます。まず上位 k のインデックス集合を S_k とし、i ∉ S_k の p_i を 0 にして残りを renormalize（合計が1になるように割る）します。top-p（nucleus）は降順に並べた確率の累積が閾値 p になるまで候補を取り、残った集合を S_p として同様にゼロ化→再正規化します。

具体的な数値例（要件に従った順序適用）
初めに与えられた確率（教材用）を p = [0.55, 0.25, 0.12, 0.08] とします。ここでは温度 T = 1.5 を採用し、順に「temperature → top-k（k=2）→ top-p（p=0.8）」を適用します。注意：温度は通常 logits に適用するため、便宜上確率から逆に log を取って logits を復元し、温度を適用してから softmax を再計算します（元の logits が与えられない教材的な手順）。

1) 確率から logit を復元（教材的近似）
l_i ≈ ln(p_i)
計算：
ln(0.55) = -0.5978
ln(0.25) = -1.3863
ln(0.12) = -2.1203
ln(0.08) = -2.5257

2) 温度 T = 1.5 を適用（logit を割る）
l'_i = l_i / T
値：
l' = [-0.3985, -0.9242, -1.4135, -1.6838]

3) softmax で再正規化して新しい確率 p'
exp(l') = [0.6716, 0.3961, 0.2432, 0.1856]
和 = 1.4966
p' = exp(l') / 1.4966 = [0.4489, 0.2648, 0.1626, 0.1240]

この結果は元の [0.55,0.25,0.12,0.08] に比べて尖りが和らいでいます（最大が0.55→0.4489に下がる）。

4) top-k = 2 の適用
p' を降順で見て上位2つを残し他を0にし、再正規化します。上位2つは 0.4489 と 0.2648、和 = 0.7137。
renorm すると
p_topk = [0.4489/0.7137, 0.2648/0.7137, 0, 0] = [0.6291, 0.3709, 0, 0]

5) top-p = 0.8 の適用（ここでは top-k 後に適用）
p_topk を降順に累積すると最初が0.6291 (<0.8)、最初と2番目で 1.0 (>=0.8)。したがって最小集合は {1,2} になり、切り捨ては起きません。よって最終は p_topk のまま：
p_final = [0.6291, 0.3709, 0, 0]

補足的比較：もし temperature の後に直接 top-p=0.8 を適用していれば
p' = [0.4489, 0.2648, 0.1626, 0.1240]
降順累積は 0.4489, 0.7137, 0.8763 → 最小集合は上位3つ、和 = 0.8763
renorm すると
p_topp = [0.4489/0.8763, 0.2648/0.8763, 0.1626/0.8763, 0] = [0.5125, 0.3023, 0.1852, 0]

この比較は top-k と top-p が互いに異なる結果を生む可能性を示しています。

短くて透明な Python 実装
下面のコードは上の数式と数値経路をそのまま再現します。変数名は数式の記号に対応しています。

```python
import numpy as np

p = np.array([0.55, 0.25, 0.12, 0.08])         # 与えられた確率（教材用）
l = np.log(p)                                  # 確率から近似的に logit を復元
T = 1.5
l_scaled = l / T                                # 温度適用
exp_l = np.exp(l_scaled)
p_prime = exp_l / exp_l.sum()                    # 温度後の確率

k = 2
idx_topk = np.argsort(-p_prime)[:k]             # 上位 k のインデックス
mask_topk = np.zeros_like(p_prime, dtype=bool)
mask_topk[idx_topk] = True
p_topk = p_prime * mask_topk
p_topk = p_topk / p_topk.sum()                  # 再正規化

# top-p (p=0.8) を top-k 後に適用する例
p_threshold = 0.8
sorted_idx = np.argsort(-p_topk)
cum = 0.0
keep = np.zeros_like(p_topk, dtype=bool)
for i in sorted_idx:
    if p_topk[i] == 0.0:
        continue
    cum += p_topk[i]
    keep[i] = True
    if cum >= p_threshold:
        break
p_final = p_topk * keep
p_final = p_final / p_final.sum()
```

Transformer 内での位置と学習時との違い
これらの処理は典型的には Transformer の最後の線形層（隠れ状態 h を語彙次元に写す W_vocab と b_vocab による線形変換）から得られる logits の直後に行われます。具体的には decoder-only（GPT型）では、まず最新の隠れ状態 h_t があり、それにより logits l = W_vocab h_t + b_vocab が計算されます。訓練時にはこの logits を softmax にかけ、交差エントロピー損失と比較して重みを更新します。生成（推論）時は上で説明した temperature / top-k / top-p のようなサンプリング規則を logits に適用して次の token を選び、それを入力に戻して次のステップを進めます。重要な点は、訓練中は通常 top-k や top-p を適用せず、教師ありの正解 token に基づく損失計算を行うことです。生成時の規則は「評価／推論の戦術」であり、学習アルゴリズムとは別物です。

よくある誤解の訂正
- 「温度は確率に直接掛ける」：誤りです。温度は logits に対するスケールであり、確率に直接作用すると softmax の性質を失い、別物の操作になります。教材で確率から逆に log を取る手順を使ったのは、元の logits が与えられていない場合の便宜的処理です。
- 「top-k はより良い確率を保証する」：top-k は低確率候補を完全に切り捨てます。これにより稀なワードが除かれ多様性が減ることもあり、常に品質を改善するわけではありません。
- 「attention weight は人間的な注目の完全な証拠である」：attention の重みはモデルの計算上の値であり、人間の解釈とは異なる場合があります。単純に「ここを注目しているから意味がある」と短絡するのは避けるべきです。

実運用上の結び付きと注意
現実の大規模モデルでは logits のスケールや語彙サイズが非常に大きく、温度や top-k/top-p の最適値はタスクによって変わります。加えて、生成時には温度や切り捨てを逐次的に変えること（たとえば最初は高い温度で多様に、末尾は低い温度で安定に）も行われますが、これは経験的な調整です。ここで説明した数式は元の Transformer（Vaswani et al., 2017）および GPT 型デコーダーでの標準的な位置関係に基づきます。近年の変種や最適化手法（例えば混合アーキテクチャ、正規化の違い、学習率スケジューリング等）は本章の基本的概念を変えませんが、各実装での挙動には注意が必要です（採用状況はモデルごとに異なります）。

この章を読み終えた後、あなたは次のことを説明できるはずです
- logits と softmax の関係、および temperature がどの段階でどのように作用するか。
- top-k と top-p の違いとそれぞれが生成に与える典型的な効果。
- 訓練時の softmax（損失計算）と生成時のサンプリング規則が別物である理由。
- 実際に与えられた確率配列に温度・top-k・top-p を順に適用して数値を得る手順。

確認問題（セルフチェック）
1) 与えられた logits l = [2.0, 1.0, 0.1] に対して温度 T = 0.5 を適用したときの softmax 確率を計算しなさい。T を 2.0 にした場合と比べてどう変わるかを答えなさい（言葉での説明を含む）。
2) ある確率配列 p = [0.4, 0.3, 0.2, 0.1] に top-p = 0.6 を直接適用した場合に残る候補と最終確率を計算しなさい。これを top-k=2 と比べて違いを説明しなさい。
