# Transformer は何をしているのか

**問題の提示 — なぜ「文字」を数に変える必要があるのか**

私たちがコンピュータに文章を「理解」させたいとき、コンピュータは文字や単語ではなく数を扱います。入力の「猫 は 寝る」という並びを、そのまま計算に使うことはできません。まず、離散的な記号（トークン）を連続値のベクトルに変え、それらのベクトル同士を比較・合成し、最終的に次に来るトークンの確率分布（0〜1の数の並び）を作る必要があります。さらに「文中のどの語が今重要か」を動的に決める仕組みも要ります。これらを、モデル内部のレイヤ（ブロック）と学習される重み（パラメータ）で実現します。

最初に問題を言葉だけで示しました。以降はこの流れに沿って、具体的な数（トークンID→埋め込み→ブロックを通る活性化→最終logits→確率）を追い、どこが「設計（アーキテクチャ）」でどこが「学習されたパラメータ」かをはっきり区別します。最初に示す小さな例を通して、各矢印の前後でどんな情報が移動しているかを追跡します。

注意：以下で使う数値は教育用の小さな例です。実運用される大規模モデルの内部の数値とは性質も大きさも異なります。また「トークン」は一般に単語そのものではなく、サブワードや記号が混じることを忘れないでください。

---

**直感的な説明（有用なイメージとその限界）**

直感1 — トークンIDはラベル、埋め込みはそのラベルに対応する座標。
直感2 — attention は「どの位置を見るかの重み」を決める行為。
これらは有用ですが完全ではありません。たとえば attention の重みが高いからといって、人間が直感する「注目」と同じ意味で解釈できるとは限りません。重みは学習された数値に過ぎず、複数の計算経路の一部でしかありません。

---

**用語を区別する：アーキテクチャ vs パラメータ vs 活性化**

- アーキテクチャ（設計）: 層の並び方（埋め込み→位置情報の付与→複数のブロック→最終線形層→softmax）や計算のルール（Attention の式、残差接続など）。実体は「どの演算を繋ぐか」の設計図。
- パラメータ（学習される重み）: 埋め込み行列 E、各線形層の重み W_Q,W_K,W_V,W_O、MLP の重みなど。これは訓練で数値が決まる。
- 活性化（計算で生じる値）: 入力トークン列に対して実際に計算される内部のベクトル列。訓練後も入力が変われば変化する。

これらを混同すると誤解の元になります。たとえば「埋め込みが大きいから重要だ」というのは、埋め込み（パラメータ）とそのときの活性化（入力依存）を取り違えています。

---

**具体例 — 語彙と入力**

語彙（簡略化）: {猫:2, は:5, 寝る:9, EOS:0}
入力トークン列（ID）: x = [2, 5, 9]

この例を、以下の4つの段階で追います（最後の位置だけを抜粋して示す）:
1. 埋め込みだけ（Eによるルックアップ）
2. 位置情報を足した後（埋め込み + pos）
3. ブロックを一つ通した後の活性化
4. 最終線形層で出たlogits

追跡表（最後のトークンに対するベクトル表示の簡潔な表記）:
| ステップ | 値（最後の位置） |
|---:|:---|
| 埋め込みのみ | [3] |
| 埋め込み + 位置 | [3, 4] |
| ブロック後 | [3, 4] |
| 最終 logit（選択した出力2つ） | [3, 10] |

この [3]→[3,4]→[3,4]→[3,10] が、本文で実際に数を計算して得られる結果です。以下で全体を計算して示します。

注：この例では埋め込み次元を小さく（2次元）にし、説明を簡潔にするために出力語彙の一部のみを表示しています。実モデルでは次元も語彙も桁違いに大きく、数値の意味合いも異なります。

---

**数式での定義（記号と軸の説明を普通の言葉で）**

記号:
- V: 語彙のサイズ（本例では語彙に含めたIDは0,2,5,9のみ扱う）
- d_model: モデルの隠れ次元（本例では 2）
- x = [x_0, x_1, x_2]: トークンIDの列（本例 x = [2,5,9]）
- E ∈ R^{V × d_model}: 埋め込み行列。行 i はトークン i のベクトル。
- P_pos ∈ R^{L × d_model}: 位置埋め込み。pos は文中の位置（0始まり）。
- H^{(0)} ∈ R^{L × d_model}: 埋め込みに位置を足したもの。各行はある位置のベクトル。
  H^{(0)}[t] = E[x_t] + P_pos[t]
- Attention ブロックや MLP の重みは W_*（これらがパラメータ）。
- 最終出力 logits = W_out · h + b_out、ここで h は最後の位置の活性化（列ベクトル）。出力は語彙方向のスコア（各語彙に対する「生の得点」）。

行列積・軸の意味:
- E[x_t] は E の x_t 行を取り出す（1×d_model のベクトル）。
- H は長さ L の行列（L 行、d_model 列）。行が「位置」、列が「特徴次元」。
- W_out は (|V| × d_model)。h を左から掛けると、各語彙に対するスコアが得られる。

---

**具体的な数値例の完全な計算**

設定（教育目的の小さな数値）:
- d_model = 2
- トークンIDと埋め込み E の選択（行は token ID の行；他の行は省略）:
  - E[2] = [1, 0]   (「猫」)
  - E[5] = [1, 3]   (「は」)
  - E[9] = [3, 0]   (「寝る」)
- 位置埋め込み P_pos:
  - P_pos[0] = [0, 0]
  - P_pos[1] = [0, 4]
  - P_pos[2] = [0, 4]
（これにより最後の位置のベクトルは E[9] + P_pos[2] = [3,4] になります）
- ブロックのパラメータ（簡素化）:
  - Attention の値（V）への投影 W_V をゼロ行列にする（これにより attention 出力は 0 ベクトルになる）
  - MLP の出力も 0（重みゼロ）にする
  - ただし残差接続があるので、ブロックの出力は入力 H^{(0)} と等しくなる
- 最終線形層 W_out（語彙を簡略化して2つだけ示すために2行に制限）:
  - 対象出力 0: w0 = [1, 0]
  - 対象出力 1: w1 = [1, 1.75]
  W_out = [w0; w1]（行ベクトルを縦に並べる）
  これにより W_out · [3,4]^T = [1*3+0*4, 1*3+1.75*4] = [3, 10]

順を追った計算:
1. 埋め込みだけ（最後のトークン = ID 9）:
   E[9] = [3, 0] → 本例の「[3]」は第一成分だけを簡潔に示したもの
2. 埋め込み + 位置:
   H^{(0)}[2] = E[9] + P_pos[2] = [3, 0] + [0, 4] = [3, 4]
3. ブロック後（本例のブロックは残差で入力を戻す設計にしてある）:
   H^{(1)}[2] = H^{(0)}[2] = [3, 4]
4. 最終線形層（logits、ここでは2つのみ示す）:
   logits = W_out · H^{(1)}[2]^T = [3, 10]

確率への変換（softmax）:
- softmax([3, 10]) = [ exp(3)/Z, exp(10)/Z ] で Z = exp(3) + exp(10)
- 数値的に exp(3) ≈ 20.0855、exp(10) ≈ 22026.4658
- よって確率 ≈ [0.00091, 0.99909]

これで表の [3]→[3,4]→[3,4]→[3,10] が得られます（最後は logits）。上の数値は教育目的の簡約例であり、実モデルの内部値ではありません。

---

**行列乗算や軸の意味を「普通の言葉」で復元する例**

- 埋め込み E の行を取る = 「トークンというラベルを長さ d_model の座標に置き換える」こと。ここで各座標は特徴（抽象された意味成分）を表す。
- 位置埋め込みを足す = 「語の順序情報を同じ座標空間に加える」こと。位置情報は埋め込みと同じ次元で、同じ軸で意味を共有する。
- W_out · h = 各語彙に対して、その語彙が今の h とどれくらいマッチするかを点数にする操作。各行は「語彙に対応するフィルタ」で、h の各成分を重み付き合計してスコアを出す。

---

**短い透明な Python 実装（numpy、変数名は上の記号に対応）**

```python
import numpy as np

d_model = 2
# 埋め込み行列の一部（行は token ID）
E = np.zeros((11, d_model))
E[2] = np.array([1.0, 0.0])
E[5] = np.array([1.0, 3.0])
E[9] = np.array([3.0, 0.0])

P_pos = np.zeros((3, d_model))
P_pos[0] = np.array([0.0, 0.0])
P_pos[1] = np.array([0.0, 4.0])
P_pos[2] = np.array([0.0, 4.0])

# 入力
x = [2, 5, 9]  # token IDs

# 埋め込み + 位置
H0 = np.stack([E[t] + P_pos[i] for i, t in enumerate(x)])  # shape (L, d_model)
# ブロック: 本例では attention の V と MLP をゼロにして残差でそのまま戻す
H1 = H0.copy()

# 最終線形（出力を 2 個に限定した簡単な例）
W_out = np.array([[1.0, 0.0],
                  [1.0, 1.75]])  # shape (2, d_model)

last_h = H1[-1]  # 最後の位置 [3,4]
logits = W_out.dot(last_h)  # [3,10]
probs = np.exp(logits) / np.exp(logits).sum()

print("最後の位置 H0:", H0[-1])      # [3,4]
print("logits:", logits)              # [3,10]
print("probabilities:", probs)        # softmax 結果
```

このコードは上で示した手順と数値をそのまま再現します。

---

**モデル内部での前後の処理と現実の大規模モデルとの接続**

前後の処理（Decoder-only の流れ、簡略）:
1. トークン列を ID に変換（トークナイザ）。
2. ID を埋め込みベクトルに変換（E）。
3. 位置埋め込みを足す。これが入力の H^{(0)}。
4. 何層ものブロック（自己注意 + MLP + 残差 + 正規化）を順に通す。各ブロックは入力を少しずつ書き換える。
5. 最終的に得られた各位置のベクトルに線形層を掛け、softmax で次トークンの分布を出す。
6. 生成では、その分布からサンプリングするか最大値を取ってトークンを確定し、次のステップへ繰り返す。

実際の大規模モデルとの違い:
- 次元や語彙サイズ、ブロック数が桁違いに大きい（d_model は数百〜数千、語彙数は数万以上）。
- Attention の最適化（FlashAttention 等）や様々な正規化、位置表現の改良などの差分がある。
- 本章の数値は教育用の縮小モデルであり、実際の数値分布や学習過程とは異なる。

**よくある誤解の訂正（少なくとも一つ）**

誤解:「Attention の重みが高ければ、その単語が『意味的に重要』であることの証拠だ」。
訂正: Attention 重みは学習された数値で、特定の出力に対する計算経路の中で使われる重みです。高い重みが必ずしも人間の直感する「重要さ」を示すわけではなく、別の中間表現を持ち込むための最適な計算経路であることが多い。注意行列の可視化はヒントを与えることはある一方で、モデルの判断全体を説明するには不十分です。

もう一つの注意: 「トークン = 単語」ではありません。多くの実装はサブワード分割を使うため、1単語が複数のトークンになることが頻繁にあります。
