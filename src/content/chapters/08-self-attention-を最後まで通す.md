# Self-attention を最後まで通す

問題提示 — なぜこれが要るのか（名前はあとで）

複数の単語や部分語（トークン）からなる文章を機械が扱うとき、ある位置にある情報が別の位置の情報をどの程度使って良いかを決めたい場面が頻繁に出ます。たとえば「彼はリンゴを食べた。とても甘かった。」という文で、「とても甘かった」が「リンゴ」を説明していることを機械に伝えたい場合、文中のある位置がほかの位置を参照して重み付けされた組み合わせを作る仕組みが必要です。単純な足し算・平均ではなく、「ある位置が他のどの位置をどれだけ参照するか」を位置ごとに決め、その重みで情報を合成する手続きが便利です。

ここで問題になるのは次のような点です。各位置（トークン）について、「どの位置をどれだけ参照するか」をどう決めるか、計算はどの方向（行か列か）で行うのか、そして重みを使って何を合成するかを明確にしないと、意味ある出力になりません。また、内積や指数関数を使うと結果のスケールが大きく変わりやすく、穏やかな重みになるように調整が必要です。以降では、この「位置ごとの参照と重み付き合成」を、入力から中間の隠れ層を挟まず最後まで数値を追って実際に計算していきます（仕組みの名は章中盤で丁寧に出します）。

直感とその限界（役割のイメージと注意点）

直感的には、各位置について「質問（query）」を作り、文の各位置に「鍵（key）」と「値（value）」を割り当てて、質問と各鍵の“似ている度合い”に応じて値を混ぜる、というイメージが役立ちます。質問がある語の文脈上の必要性を表し、鍵が他の語の「提供可能な情報の方向」を表し、値がその情報の中身、という具合です。

ただし注意点が二つあります。
1) 「注目(weight)＝人間の注目を示す証拠」ではありません。重みは数学的に得られる数値で、解釈は便利ですが完全な説明ではありません。高い重みが必ずしも「人間的に重要」と一致するわけではありません。
2) 「query/key/value のそれぞれが直接単語そのもの」ではありません。通常は入力のベクトル表現に学習済みの行列を掛けて得られる中間表現（活性化）です。ここで扱う Q,K,V は既にその活性化だと考えてください。

数値オブジェクト、学習パラメータ、活性化の区別

以下で出てくるものを明確に区別します。
- 学習パラメータ（parameter）：モデルが学習で調整する固定行列など。例：入力ベクトルを Q に変換するための重み W_Q。ここでは計算に直接使いませんが、Q,K,V がどこから来るかは通常こうしたパラメータ経由です。
- 活性化（activation）：入力とパラメータの掛け算などから計算される中間ベクトル。今回の Q,K,V は活性化です（数式中の具体的な行列）。
- 数値オブジェクト：単なる行列やスカラー。たとえば softmax の結果やスコア行列は活性化にあたりますが、固定定数 sqrt(d_k) は数値オブジェクトです。

ここでは Q,K,V を活性化として扱い、学習パラメータ（W_Q 等）は注記するだけにします。小さな例で示す数値は教育目的の便宜的な値であり、実運用する大規模モデルの内部状態とは異なることを強調します。

全体の数式（まず全体像を示す）

まず式だけ示すと、典型的な一回の処理は次の順になります（各記号は後で普通の言葉に戻します）。

1) scores = Q K^T
2) scaled_scores = scores / sqrt(d_k)
3) weights = softmax_rowwise(scaled_scores)
4) output = weights V

ここで d_k は鍵（key）の次元数（列数）です。softmax_rowwise は各行ごとに要素を指数化して合計で割る操作を意味します（行の合計が 1 になります）。以降で各式の意味、行列積がどの成分の比較を表すか、そして具体的な数値例を順を追って計算します。

記号と行列積の軸（普通の言葉で）

- 行列 Q の「行」は「クエリを作る対象の位置（トークンの位置）」を表します。たとえば文に2つのトークンがあれば Q の行数は 2 になります。Q の「列」はその位置を表す特徴（ベクトル次元）です。
- 同様に K の「行」は鍵を持つ位置、K の「列」は特徴次元（通常 Q と同じ次元 d_k）。
- V の「行」も位置に対応し、「列」は値としての特徴次元（多くの場合 d_v）。

ここで要点は、Q の i 行（位置 i のクエリ）と K の j 行（位置 j の鍵）の内積が scores_{i,j} に出る、という点です。行列積 Q K^T は「すべての i,j の組み合わせでクエリ i と鍵 j の内積を並べた」行列を作る操作です。内積のサイズが大きいほど「似ている（参照しやすい）」というシグナルになります。

スケール（sqrt(d_k)）の役割：なぜ割るのか

内積は次元数 d_k に依存してばらつきが大きくなります。特徴が独立で平均がゼロに近いと仮定すると、内積の分散は d_k に比例します。分散が大きくなると softmax の指数関数が非常に大きい/小さい値を生み、結果としてソフトマックスが極端に尖った（ほぼ1つの要素に集中する）か、数値的に不安定になることがあります。したがって内積を sqrt(d_k) で割るとスケールが安定し、ソフトマックス後に適度に分散した重みが得られやすくなります。これは元の論文で導入された単純かつ有効な安定化手段です（学習可能なスケールを用いる拡張もありますが、ここでは元の定式化に沿います）。

実例を通す（すべての数値を順に計算）

指定された具体例を使って、数を順に追います。Q, K, V はそれぞれ 2 行 2 列の行列です（行＝位置数 2、列＝特徴次元 2）。

与えられた行列：
Q = [[1, 0],
     [0, 1]]

K = [[1, 1],
     [1, -1]]

V = [[2, 0],
     [0, 3]]

まずは Q K^T を計算します。行列積の要素については次のとおりです。scores_{i,j} = (i 行の Q) ⋅ (j 行の K)（内積）。

K の転置 K^T（行と列を入れ替え）はここでは
K^T = [[1, 1],
       [1, -1]]
で、元の K と同じ形になっています（この K は転置しても同じ形）。

1) scores = Q K^T
- 第一行（i=1、Q の行 [1,0]）と K の行 j=1,2 の内積：
  - scores_{1,1} = [1,0] ⋅ [1,1] = 1*1 + 0*1 = 1
  - scores_{1,2} = [1,0] ⋅ [1,-1] = 1*1 + 0*(-1) = 1
  → 第1行は [1, 1]
- 第二行（i=2、Q の行 [0,1]）と K の行：
  - scores_{2,1} = [0,1] ⋅ [1,1] = 0*1 + 1*1 = 1
  - scores_{2,2} = [0,1] ⋅ [1,-1] = 0*1 + 1*(-1) = -1
  → 第2行は [1, -1]

したがって
scores = [[1, 1],
          [1, -1]]

2) scaled_scores = scores / sqrt(d_k)
ここで d_k = 2（鍵の列数）。sqrt(2) ≈ 1.41421356。要素ごとに割ります。

scaled_scores ≈ [[1/1.41421356, 1/1.41421356],
                 [1/1.41421356, -1/1.41421356]]
≈ [[0.70710678, 0.70710678],
   [0.70710678, -0.70710678]]

3) weights = softmax_rowwise(scaled_scores)
各行ごとにソフトマックスを取ります。ソフトマックスは要素を指数関数に通して行の総和で割る操作です（数値安定化のために各行の最大値を引くことが普通ですが、ここでは直接数値で示します）。

- 第一行: [0.7071, 0.7071]
  exp(0.7071) ≈ 2.02811498。同じ値が2つなので重みは等しく、
  weights_row1 = [0.5, 0.5]

- 第二行: [0.7071, -0.7071]
  exp(0.7071) ≈ 2.02811498
  exp(-0.7071) ≈ 0.49306869
  合計 ≈ 2.52118367
  weights_row2 ≈ [2.02811498/2.52118367, 0.49306869/2.52118367]
               ≈ [0.8040, 0.1960]  （小数4桁で表示）

まとめて
weights ≈ [[0.5,   0.5  ],
           [0.8040,0.1960]]

ここで各行の和はそれぞれ 1 になっています（確率分布になっている）。

4) output = weights V
最後に、各行（各クエリ位置）で得られた重みを V の行（位置ごとの値）に対して左から掛け、位置ごとの混合値を得ます。行列積で表すと output_{i,:} = sum_j weights_{i,j} * V_{j,:}。

V は対角行列に近く、V の各行は
V_row1 = [2, 0]
V_row2 = [0, 3]

- 第一行の出力:
  output_row1 = 0.5 * [2,0] + 0.5 * [0,3] = [1, 0] + [0, 1.5] = [1, 1.5]

- 第二行の出力:
  output_row2 = 0.8040 * [2,0] + 0.1960 * [0,3]
              = [1.6080, 0] + [0, 0.5880] = [1.6080, 0.5880]

したがって最終出力（重み付き和の行列）はおよそ
output ≈ [[1.0000, 1.5000],
          [1.6080, 0.5880]]

これが一連の処理を「入力の活性化」から「出力の活性化」へとそのまま通した数値的な結果です。

透明な短い Python 実装（対応する変数名を保つ）

以下は上の計算を再現する Python（NumPy）コードです。変数名は数式と対応させています。学習用の小さな例のため、数値安定化（行ごとの最大値引き）はコメント化していますが、実装では常に入れることが推奨されます。

```python
import numpy as np

Q = np.array([[1., 0.],
              [0., 1.]])
K = np.array([[1., 1.],
              [1., -1.]])
V = np.array([[2., 0.],
              [0., 3.]])

scores = Q.dot(K.T)
# 2) scaled_scores = scores / sqrt(d_k)
d_k = K.shape[1]
scaled_scores = scores / np.sqrt(d_k)

# 3) weights = softmax rowwise
# (数値安定化: 各行の最大値を引いてからexpするのが良い)
def softmax_rowwise(x):
    x_max = np.max(x, axis=1, keepdims=True)
    e = np.exp(x - x_max)
    return e / np.sum(e, axis=1, keepdims=True)

weights = softmax_rowwise(scaled_scores)

# 4) output = weights V
output = weights.dot(V)

print("scores:\n", scores)
print("scaled_scores:\n", scaled_scores)
print("weights:\n", weights)
print("output:\n", output)
```

このコードを実行すると、上で手計算した値に一致する結果が得られます（小数表示の違いは丸めによる差です）。

全体の流れと Transformer 内での位置付け（前後の処理との接続）

実際の Transformer では、上の処理はより大きなブロックの一部です。典型的な流れは次の通りです（ここでは encoder-decoder の区別や decoder-only の特殊処理を補足しますが、混同はしません）：

- 入力（トークン列）はまず埋め込み（embedding）により連続値ベクトル列に変換されます。さらに位置情報を入れるために位置エンコーディングが加わる場合があります。
- 各位置の埋め込みベクトルに対して学習パラメータ W_Q, W_K, W_V（行列）を掛けて Q,K,V の活性化を得ます。つまり Q = X W_Q, K = X W_K, V = X W_V（ここで X が入力の埋め込み行列）。
- 上で説明した Q K^T → softmax → weights → weights V を行い、出力活性化を得ます。
- 出力はさらに線形変換（学習パラメータ）や残差接続、正規化、位置ごとの小さな全結合層（フィードフォワード）に渡されます。
- マルチヘッド注意：上の処理を複数並列に（ヘッドごとに異なる W_Q,K,V）実行し、それらの出力を連結して最後にもう一度線形変換するのが標準的です。

decoder-only（GPT型）の場合は、softmax の計算に先立って「因果マスク」を適用します。これは、各クエリが将来（右側）の鍵を見ないように、一部の scores_{i,j} を -∞ に置き、softmax でゼロ重みになるようにする操作です。encoder-decoder ではエンコーダの出力を鍵・値として用いる「クロスアテンション」があり、これは別の入力列を参照する形になります。

よくある誤解の訂正（最低一つ）

誤解: 「attention の重みが高い箇所を見ればモデルの理由付けが分かる。」
訂正: 重みは確かにモデルの出力を作る上でどの位置の情報がどれだけ合成されたかを示しますが、その理由（なぜその重みが学習されているか）や内部表現の意味を直接的に示すとは限りません。重みは活性化に基づく数値であり、特徴空間の向きやスケール、他の層の影響、学習時の正規化など多くの要因が絡んでいます。したがって注目可視化は一つのヒントにすぎず、決定論的な説明と混同してはいけません。

もう一つの誤解: 「token ＝ 単語」
訂正: 実際のモデルは BPE や WordPiece といった分割を使うため、token は部分語やサブワードであることが多いです。したがって「トークン位置」を人間の語に直結させるのは危険です。

実モデルとのスケール感に関する注記

本節で用いた小さな行列・小さな数値は教育用の簡単化です。実際の大規模 Transformer では次元数 d_k, d_v は数百から数千程度であり、softmax に入るスコアの分布や learning dynamics はここで示した振る舞いより複雑になります。したがって具体的な小数値（例: 0.7071 や 0.8040）は示唆的ですが、実際のモデル内部で常にこのような値になるわけではありません。

章のまとめ（読者が説明できるようになること）

この章を読み終えると、以下の点を自分の言葉で説明できるはずです。

- 行列 Q, K, V の各行と列がそれぞれ何を表すか（行＝位置、列＝特徴）と、なぜ Q K^T が「すべての位置ペアの類似度」を提供するのか。
- なぜ内積を sqrt(d_k) で割る必要があるのか（スケールの安定化と softmax の尖り防止）。
- softmax をどの軸に適用するか（行ごと、すなわち各クエリごとに鍵への重みが正規化されること）。
- attention の重みと値（V）の重み付き和が出力ベクトルを与える仕組みと、これがどのように文脈依存の情報合成を実現するか。
