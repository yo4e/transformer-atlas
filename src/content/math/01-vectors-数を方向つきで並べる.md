# Vectors: 数を方向つきで並べる

**はじめに — なぜTransformerで「ベクトル」が必要か**

Transformer（Vaswani et al., 2017）では、単語やトークンはまず「埋め込み（embedding）」という数の列に変換されます。さらに、Attentionの計算で使うQuery（Q）、Key（K）、Value（V）も、埋め込みに線形変換を施して得られる数の列です。これらの「数の列」の最小単位が「ベクトル」です。ベクトルはAttentionの内積（類似度）計算、重み付き和（コンテキスト合成）、正規化や投影といった操作の対象になり、Transformerの計算のほとんどはベクトルと行列の組み合わせで表現できます。後年の改良版や派生モデルはあっても、原著における埋め込み→Q/K/V→内積→softmax→重み付き和、という流れは基本理論であり、ここで扱う「ベクトル」の理解は不可欠です。

**最小の定義：ベクトルとは何か（簡潔）**

ベクトルとは「順序を持った数の列」です。具体的には、同じ長さ（次元数）を持つ数が位置順に並んだもので、例えば [2, -1, 3] のように書きます。ベクトル同士の加算や内積、定数倍といった演算が定義されるため、計算対象として便利です。重要な点は、各座標に対して人間が勝手に意味ラベル（例えば「この次元は形容詞性」など）を過剰に与えないことです。埋め込みの各次元は学習で決まる実数であり、多くの場合単一の明解な人間語義を持ちません。つまり、座標は「意味的なラベル」ではなく、モデルが内部で情報を表現するための数値の並びだと理解してください。

**記号とshapeの解読**

- 小文字ボールド x（または x）をベクトルとし、x ∈ R^d と書くと「xは実数d次元ベクトル」を意味します。shape 表記では x.shape = (d,) や（行列と合わせるとき）(d, 1) と表されます。
- 埋め込みの次元数は d_model、Attentionで使うQ,Kの次元を d_k、Vの次元を d_v と呼ぶことが多いです（原著の表記に準拠）。
- 行列 W は線形変換を表し、Q = X W_Q のようにして得られます。ここで W_Q のshapeは (d_model, d_k) や（実装によって）(d_k, d_model) のどちらかで表されます。バッチや系列長が絡むと、テンソルshapeは (batch, seq_len, d_model) → Q: (batch, seq_len, d_k) という形になります。

**上の数値を省略せず計算する：具体例**

ここから必ず指定された数値をそのまま使って計算します。ベクトルを
a = [2, -1, 3]
b = [1, 4, -2]
とします。

1) 要素ごとの加算（両ベクトルは「要素数が同じ」でなければ加算できません）
両方とも要素数（次元数）は3です。従って加算は次のように定義されます。
a + b = [2+1, (-1)+4, 3+(-2)] = [3, 3, 1]

2) 定数倍（スカラー倍）の例（スカラーを2とする）
2 * a = [2*2, 2*(-1), 2*3] = [4, -2, 6]
-1 * b = [-1*1, -1*4, -1*(-2)] = [-1, -4, 2]

3) 長さ（ここは二つの意味があるので注意）
- 次元数（要素の個数）は両方とも3で「同じ」であり、要素ごとの演算が可能です。
- 一方で「ユークリッドノルム（大きさ、長さ）」は次の通り計算されます。
||a|| = sqrt(2^2 + (-1)^2 + 3^2) = sqrt(4 + 1 + 9) = sqrt(14) ≈ 3.7417
||b|| = sqrt(1^2 + 4^2 + (-2)^2) = sqrt(1 + 16 + 4) = sqrt(21) ≈ 4.5826
ユークリッド長は一般に等しくないことが普通であり、重要なのは「次元数が一致していること」です。内積や類似度の計算でノルムが影響します。

4) 内積（dot product）— Attentionでの類似度の基礎
a · b = 2*1 + (-1)*4 + 3*(-2) = 2 - 4 - 6 = -8
内積が大きいほど（正の大きな値）方向が似ていると解釈され、Transformerのスコア計算で使われます（原著ではスケーリングも行う）。

これらの計算は手計算でゆっくりやってよく、速さは要求されません。ポイントは「順序を持った数の列としての性質」と「次元数の一致が演算の前提」であり、座標ごとに人間的なラベルを貼る必要はない、という点です。

**透明な短いPythonコード（そのまま実行可能）**

```python
import numpy as np

a = np.array([2, -1, 3])
b = np.array([1, 4, -2])

print("a + b =", a + b)
print("2 * a =", 2 * a)
print("||a|| =", np.linalg.norm(a))
print("||b|| =", np.linalg.norm(b))
print("a · b =", np.dot(a, b))
```

このコードはベクトル演算、スカラー倍、ノルム、内積をそのまま示します。実装では埋め込みやQ/K/Vはこのような一行ベクトルの集合（行列やテンソル）として扱われます。

**よくある誤解（とその訂正）**

- 誤解：埋め込みの「各次元」は明確な意味を持つ。
  訂正：一部の次元が「性別」「時制」などに対応することが観察される場合はありますが、一般に埋め込みの次元は学習で決まる抽象特徴であり、明確な人間語義を持つとは限りません。次元ごとの意味づけは過剰解釈の危険があります。

- 誤解：ベクトルの大きさだけが情報の重要度を表す。
  訂正：内積は方向と大きさの両方に依存します。Attentionではスケーリングやsoftmaxが加わるため、単純にノルムが大きい＝重要とは言えません。

- 誤解：QとKは別物で、比較できない。
  訂正：QとKは異なる線形変換で得られますが、内積することが目的なので同じ次元に揃えられます（d_k）。Vは値の伝達役として別次元であることが許容されます（d_v）。

**読者が説明できること（チェックリスト）**

- ベクトルを「順序を持つ数の列」として定義できる。
- なぜQ,K,Vや埋め込みがベクトルで表されるのかを説明できる。
- [2,-1,3] と [1,4,-2] に対して要素ごとの加算、定数倍、内積、ノルムを手順を追って示せる。
- 埋め込みの各座標に過剰な意味付けをしない理由を述べられる。
- Vaswani et al. (2017) におけるAttentionの主要な計算がベクトル／行列演算であることを説明できる。
