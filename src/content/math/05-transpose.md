# Transpose

このノートは「transpose（転置）」というごく単純な線形代数の操作――行と列の役割を入れ替えること――が、なぜTransformerの注意機構（attention）で「全てのqueryと全てのkeyを一度に比較する」ために必要かを、大学数学の前提なしに直感的かつ具体的に説明することを目的とします。説明はVaswani et al. 2017（Transformer原著）で使われている行列表記を基本とし、後年の変種（相対位置バイアスや別の正規化法など）は明示的に区別します。まず最小限の定義と慣習を示し、その後に与えられた数値例を省略せずに手計算・コード実行し、最後に誤解しやすい点と学習のチェック項目を示します。

最小の定義：転置（transpose）。与えられた行列Aの転置をA^Tと書くと、Aの行と列を入れ替えた新しい行列になるだけです。たとえば A の (i,j) 成分が a_{ij} なら、A^T の (j,i) 成分は同じ値 a_{ij} です。行列の並び方に関する慣習として、Transformerの説明では「各行が一つのトークン（単語やサブワード）に対応し、その行の各列が埋め込み・特徴（次元）を表す」ことが多い点に注意してください。つまり、行は「トークン方向」、列は「特徴方向（空間）」です。

なぜQ K^Tを計算するのか（直感）。Transformerではまず各トークンに対してqueryベクトル q、keyベクトル k、valueベクトル v を作ります（これらは同じ埋め込みから異なる線形変換で得られる）。注意重みを計算する基本操作は「あるqueryが各keyにどれだけ似ているか」をすべてまとめて計算することです。ここで「すべてまとめて」とは、全てのquery（文中のすべての位置）と全てのkey（同じく全ての位置）の間の内積（または類似度）を一つの表にしてしまうことを指します。行列の掛け算を使うと、Q（全queryを行に並べた行列）とK（全keyを行に並べた行列）の掛け算で、その全てのペアの内積を一度に得ることができます。ただし通常の行列掛け算のルールに合わせるには、Kの行を列に変えて（転置して）掛ける必要があります。これがQ K^Tを計算する理由です。数学的に言えば、Q∈R^{n_q×d}, K∈R^{n_k×d} のとき Q K^T ∈ R^{n_q×n_k} の (i,j) 成分は q_i · k_j （特徴次元 d に沿った内積）となります。

数値例の計算（省略せずに手計算）。与えられた行列をそのまま使って具体的に計算します。
K = [[1, 1], [1, −1], [0, 2]] （これは3行2列、形状 3×2）
Q = [[1, 0], [0, 1]] （これは2行2列、形状 2×2、単純化のためここでは単位行列）
まずKを転置すると K^T は 2行3列になります。転置の結果を各成分で書くと、Kの1行目がK^Tの1列目、Kの2行目がK^Tの2列目、……ではなく、成分を入れ替える操作に基づいて次のようになります：

K =
[ [1,  1],   ← k_1 = (1, 1)
  [1, −1],   ← k_2 = (1, −1)
  [0,  2] ]  ← k_3 = (0, 2)

K^T =
[ [1, 1, 0],
  [1, −1, 2] ]

次に Q（2×2）と K^T（2×3）を掛けます。行列の積 Q K^T は 2×3 の行列になり、その (i,j) 成分は Q の i 行と K^T の j 列の内積です。手で逐一計算すると：

Q の1行目 = [1, 0] と K^T の各列との内積：
- 列1 = [1, 1] → 1*1 + 0*1 = 1
- 列2 = [1, −1] → 1*1 + 0*(−1) = 1
- 列3 = [0, 2] → 1*0 + 0*2 = 0

Q の2行目 = [0, 1] と K^T の各列との内積：
- 列1 = [1, 1] → 0*1 + 1*1 = 1
- 列2 = [1, −1] → 0*1 + 1*(−1) = −1
- 列3 = [0, 2] → 0*0 + 1*2 = 2

したがって Q K^T = [[1, 1, 0], [1, −1, 2]]。これはちょうど K^T の行がそのままQの行に対応して選ばれた形になっています（今回はQが単位行列だったため第一行はK^Tの第一行、第二行はK^Tの第二行と一致しています）。別の見方をすると、各要素は q_i と k_j の内積であり、行列全体は「各queryが各keyに対してどれだけ似ているか」の一覧表です。

記号とshapeの解読。Transformerの標準表記に沿って、よく見かけるシンボルとその形状をまとめると次のようになります（Vaswani et al., 2017 に準拠）：
- Q ∈ R^{n_q × d_k}：n_q はクエリの数（通常はトークン数）、d_k は各query/keyの次元（特徴の数）。
- K ∈ R^{n_k × d_k}：n_k は key の数（通常は同じくトークン数）。
- V ∈ R^{n_k × d_v}：value の行数は key と合わせる。d_v は value の次元。
- Q K^T ∈ R^{n_q × n_k}：この行列の (i,j) が q_i·k_j。これに 1/√d_k を掛け、各行ごと（あるqueryに対する全key方向）にsoftmaxを取って重みを得るのが標準的な流れです（これはVaswani et al., 2017で導入されたスケーリング）。

透明な短いPythonコード（実際に実行可能なコード、numpyを使用）：
```python
import numpy as np

K = np.array([[1, 1],
              [1, -1],
              [0, 2]])   # shape (3,2)
Q = np.array([[1, 0],
              [0, 1]])    # shape (2,2)

KT = K.T                      # shape (2,3)
result = Q.dot(KT)            # shape (2,3)

print("K^T =\n", KT)
print("Q K^T =\n", result)
print("shapes:", Q.shape, "x", KT.shape, "=", result.shape)
```
このコードを実行すると K^T と QK^T の中身、形状が表示され、手計算と同じ結果が得られるはずです。

よくある誤解と注意点：
- 「転置は単に行列の向きを変えるだけだが意味は変わらない」と捉えがちですが、どの軸（トークン軸か特徴軸か）に沿って情報を集めたいかで意味が大きく変わります。Transformerでは「全query × 全key の表」を作るために転置が必要です。
- 行と列の慣習（各行がトークンか、各列がトークンか）を混同すると、次元不一致や間違った内積を計算してしまう原因になります。実装では batch 次元や head 次元がさらに加わるため、形状管理は特に重要です。
- QK^T の後に 1/√d_k を忘れると、内積のスケールが大きくなりsoftmaxが極端な分布になりやすい（Vaswani et al., 2017 で導入された重要な修正）。
- 「転置しても数が変わらないので意味も変わらない」と考えるのは誤り。内部の数は同じでも、それをどう読み取るか（行が観測、列が特徴か）は計算の意図を左右します。
