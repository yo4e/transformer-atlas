# Matrix multiplication

**なぜTransformerのどの箇所で必要になるか**

Transformer（原著: Vaswani et al., 2017）では、入力の各トークン表現を線形変換してQuery（Q）、Key（K）、Value（V）を作ります。この線形変換が行列積です。具体的にはバッチ内の各トークンの特徴ベクトルを並べた行列 X（形状: シーケンス長 L × モデル次元 d_model）に、学習される重み行列 W_Q, W_K, W_V（形状: d_model × d_k や d_model × d_v）を掛けることで Q = X W_Q, K = X W_K, V = X W_V を得ます。行列積は「全トークンに同じ線形写像を並列に適用する」操作であり、Transformerの注意機構・ヘッドの並列化を支える基本演算です。以降の説明は原著の構成に基づき、後年の変種（位置埋め込みや正規化のタイミングなどの違い）は明示的に区別します。

**最小の定義：行列積とは何か（直感）**

行列積 A B は「A の各行ベクトル」と「B の各列ベクトル」の内積（dot product）を、すべての組合せについて並べた結果です。つまり結果行列 C の成分は
C[i, j] = sum_k A[i, k] * B[k, j]
で与えられます。ここで i は結果の行インデックス、j は列インデックス、k は和を取る方向（A の列かつ B の行）を表します。行列積は、複数のベクトルに同じ重み（重み行列の列）を一度に適用する効率的な表現です。

**数値例：X = [[1,0],[0,1]] と W = [[1,2],[3,4]] の全四要素計算**

ここで X と W を具体的に与え、C = X W を手で全て計算します。両方とも 2×2 行列なので、結果も 2×2 になります。成分をインデックスで書くと X[i,k], W[k,j] です。

- C[0,0] = X[0,0]*W[0,0] + X[0,1]*W[1,0]
  = 1*1 + 0*3 = 1

- C[0,1] = X[0,0]*W[0,1] + X[0,1]*W[1,1]
  = 1*2 + 0*4 = 2

- C[1,0] = X[1,0]*W[0,0] + X[1,1]*W[1,0]
  = 0*1 + 1*3 = 3

- C[1,1] = X[1,0]*W[0,1] + X[1,1]*W[1,1]
  = 0*2 + 1*4 = 4

よって C = [[1,2],[3,4]] になります。ここでの直観：X は単位行列（各行が「どの特徴がそのトークンにあるか」を表す）なので、線形変換 W をそのまま通した結果になっています。各出力成分は「X の i 行（トークン i の特徴）の k 成分」と「W の k 行（k 成分から出力 j を作る重み）の j 列成分」の対応の積を足し合わせたものです。

**記号と shape の解読（軸の追跡）**

今回の例で軸を明確に追います。X の shape は (2, 2) で、ここでは「行 = トークン index i（0..1）」「列 = 入力特徴 index k（0..1）」とします。W の shape は (2, 2) で、「行 = 入力特徴 index k」「列 = 出力特徴 index j（0..1）」です。行列積 X W を計算すると結果の shape は (2, 2) で、「行 = トークン index i」「列 = 出力特徴 index j」です。和を取るインデックス k が、X の列軸と W の行軸をつなぎます。大事なのは「どの軸が内積されるか」を常に確認することです。Transformer での X は通常 (L, d_model)、W は (d_model, d_k) と書くため、結果 Q は (L, d_k) になります。

**透明な短いPythonコード（実際に動く NumPy）**

以下は実行可能な Python + NumPy のコードです（仮コードではなく実行可能なサンプルです）。

```python
import numpy as np

X = np.array([[1, 0],
              [0, 1]])  # shape (2, 2)
W = np.array([[1, 2],
              [3, 4]])  # shape (2, 2)

C = X.dot(W)  # または np.matmul(X, W)
print("X shape:", X.shape)
print("W shape:", W.shape)
print("C = X W:")
print(C)
```

このコードを実行すると C は [[1 2] [3 4]] となり、shape は (2,2) です。Transformer の実装でも同じ操作をバッチやヘッドごとに拡張して行っています（例えばバッチサイズ B、シーケンス長 L、ヘッド数 H を取り入れるとテンソルの形状はより多次元になりますが、内積の本質は同じです）。

**よくある誤解（と正しい理解）**

- 誤解: 行列積は単に要素ごとの掛け算（Hadamard 積）だ。
  正: 行列積は行と列の内積。要素ごとの積とは異なり、和を取る軸が存在する。

- 誤解: 行列を掛ける順序は気にしなくて良い。
  正: 行列積は非可換。一般に A B ≠ B A。順序により「どの特徴をどの空間へ写すか」が変わる。

- 誤解: 軸を間違えても自動でブロードキャストされるから大丈夫。
  正: ニューラルネットワーク実装では軸の意味（トークン、特徴、ヘッド、バッチなど）を揃えないと形状エラーや意味の間違いが生じる。必ず (L, d_model) × (d_model, d_k) のように内積される軸を合わせる。

- 誤解: 行列積は「数値の計算」だけで、何を表すかは重要ではない。
  正: 各成分が「どの入力特徴がどの出力特徴へどの程度寄与するか」を表す意味を持つ。Transformer ではこれが学習され、注意スコア計算やトークン表現の変換に直結する。

**読者が説明できること（学習の到達目標）**

- 行列積 C = A B の各成分 C[i,j] がどのように計算されるかを手で示せる。
- Transformer における Q = X W_Q の形状の意味（入力軸 X の行がトークン、列が特徴）と、内積で使われる軸（特徴次元）が何かを説明できる。
- X = [[1,0],[0,1]] と W = [[1,2],[3,4]] の例を使い、各出力成分の由来（どの掛け算と和から生じたか）を説明できる。
- 行列積と要素ごとの積（Hadamard）や行列の転置の違いを説明できる。
- 実装上の形状エラーが出たときに、どの軸の不一致を疑うべきかを判断できる。
