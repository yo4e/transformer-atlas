# Chain rule

連結した関数への影響を途中の変化率の積として戻す、という考え方は、機械学習でパラメータを調整する際の最も基本的な道具です。特にTransformer（Vaswani et al., 2017）においては、自己注意や線形変換、位置ごとのフィードフォワードなど多数のパラメータが積み重なっており、損失が出たときに「どのパラメータをどれだけ動かせば損失が下がるか」を効率よく求めるために、この考え方とその効率的な実装であるバックプロパゲーション（逆伝播）が不可欠です。本稿は大学数学の前提を必要とせず、直感と最小限の定義で「連鎖律（chain rule）」とバックプロパゲーションの役割を理解できるように書いてあります。

まず直感：関数が連続してつながっているとき、最終的な出力の変化は途中の各変化の「積」として表せます。例えばあるパラメータθがまず中間変数zを変化させ、そのzが損失Lを変化させるなら、θがLに与える影響は「Lのzに対する変化率」と「zのθに対する変化率」を掛け合わせたものです。これは、道のりを分担している各区間の「伸び縮み」を掛け合わせるイメージです。

最小の定義（必要十分）
- スカラーの場合の連鎖律：もし z = g(θ) と L = f(z) なら、θが小さく変化したときのLの変化は dL/dθ = (dL/dz) * (dz/dθ) で与えられます。ここのdは「変化率」を表します。これだけで基本は理解できます。
- ベクトル／行列が関わる場合は、出力がスカラーであれば（損失は通常スカラー）、パラメータごとの微分は同様の局所的な因子を組み合わせることで得られます。実装上は、各ノードで局所的な微分（局所勾配）を計算して前段へ伝える「逆順」で計算することで効率化します（逆伝播）。

必ず通す数値例（途中の変化率の計算）
**数値例の計算**
与式： z = 2θ, L = (z − 4)^2 を考えます。
1. まず L を z で微分します。L = (z − 4)^2 より、基本的な微分公式から
   dL/dz = 2 * (z − 4).
2. 次に z を θ で微分します。z = 2θ より
   dz/dθ = 2.
3. 連鎖律により
   dL/dθ = (dL/dz) * (dz/dθ) = 2 * (z − 4) * 2 = 4 * (z − 4).
   さらに z = 2θ を代入すると
   dL/dθ = 4 * (2θ − 4) = 8θ − 16.
具体的な数値例として θ = 3 を代入すると z = 6、L = (6 − 4)^2 = 4、dL/dz = 2*(6 − 4) = 4、dz/dθ = 2、したがって dL/dθ = 4 * 2 = 8。手で計算しても自動微分で計算しても一致する値です。

記号と shape の解読（直感優先）
- スカラー（単一の数）：θ, z, L のようなもの。微分は単一の数になります（dL/dθ はスカラー）。
- ベクトル：x ∈ R^n のように複数成分を持つ入力。損失がスカラーのとき、dL/dx は元の x と同じ次元のベクトルになります（各成分ごとの偏微分）。
- 行列：W ∈ R^{m×n} のような重み行列。損失がスカラーのとき、dL/dW は W と同じ形状 m×n の行列で、各要素の偏微分を並べたものです。
- 実務的に重要な事実：線形変換 y = W x の場合、損失の y に関する勾配が g = dL/dy（長さ m のベクトル）であれば、W に対する勾配は g と x の外積（g を列、x を行として掛ける）で得られます。つまり dL/dW = g ⊗ x^T。これは「どの入力成分がどの出力成分に効いているか」を示す直感的な形です。

透明な短いPythonコード（実際に動く）
以下は上のスカラー例をそのまま計算するシンプルな実行可能コードです（numpyのみ使用）。
```python
import numpy as np

theta = 3.0

# 順伝播
z = 2.0 * theta
L = (z - 4.0) ** 2.0

# 局所勾配（手計算どおり）
dL_dz = 2.0 * (z - 4.0)
dz_dtheta = 2.0

# 連鎖律で合成
dL_dtheta = dL_dz * dz_dtheta

print("theta =", theta)
print("z =", z)
print("L =", L)
print("dL/dz =", dL_dz)
print("dz/dtheta =", dz_dtheta)
print("dL/dtheta =", dL_dtheta)  # 期待値: 8.0
```
同様に、ミニマルな線形層の例（x はベクトル、W は行列）の場合も numpy で勾配を明示的に計算できます。これはバックプロパゲーションの「局所勾配を掛け合わせて前へ伝える」手続きそのものです。

バックプロパゲーションが多数パラメータ版の効率的計算である理由
- トップレベルの損失がスカラーである場合、逆伝播（reverse-mode autodiff）は「損失→中間→パラメータ」の順で勾配を1回の逆パスで効率良く求めます。パラメータ数が大きい（Transformerでは何百万〜何十億）とき、各パラメータに対して個別に前方差分を行うのは非現実的ですが、逆伝播は各中間の局所導関数を1つずつ計算して掛け合わせるだけで、全てのパラメータの勾配を同時に得られます。
- 実装面では、順伝播で得た中間値（活性化、線形出力など）を保持しておき、それらを使って局所勾配を計算し、前段へ伝えることで、不要な再計算を避けます。
- ベクトル化と行列演算（BLAS）を用いれば、同じ計算を一括で高速に行えるため、GPU/TPU上で巨大なモデルでも現実的な時間で勾配を得られます。

Transformer のどの箇所で必要になるか（原著: Vaswani et al., 2017）
- 注意機構（self-attention）：Q = X W_Q, K = X W_K, V = X W_V のような線形変換が多数重なります。損失が最終出力のスカラーとすると、W_Q, W_K, W_V に対する勾配はそれぞれの線形変換の局所勾配と、後段から伝わる勾配の積として計算されます。
- 出力射影 W_O、層ごとのフィードフォワード（2層の線形変換と活性化）、および埋め込みテーブル（embedding）など、すべてが連鎖律に基づいて勾配が伝播されます。
- これらの事実は原著のTransformer（Vaswani et al., 2017）に記された構成に基づきます。後年の変種（例えばパラメータ共有、代替的な正規化やスケーリング、効率化のための低ランク近似など）はアーキテクチャ的に差がありますが、勾配を求める根本の仕組みは同じです（連鎖律＋逆伝播）。

よくある誤解（短く）
- 「微分は常に局所だけ見れば良い」：局所微分は必要ですが、最終的にどのパラメータが損失にどう影響するかは連鎖的に掛け合わせる必要があります。局所だけで判断すると誤った最適化につながります。
- 「逆伝播は数式を丸暗記するもの」：本質は「局所的に計算して前へ伝える」手続きです。各レイヤーで何を保存しどの局所勾配を計算するかを理解すれば暗記は不要です。
- 「行列の微分は難しい」：形（shape）と単純な線形代数の直感（外積、行列積のルール）を使えば十分実用的に扱えます。深い理論は必要ありません。
